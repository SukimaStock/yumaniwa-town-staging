# Prototype 0 — 街の見方を観察する

仮称・配置: `works/town-glance/`。独立した静的ページ。町への登録、公開、production変更は含まない。

## 試す

リポジトリ直下で `python -m http.server 8765`、ブラウザで `http://localhost:8765/works/town-glance/`。
iPhoneからは同じネットワークの配信PCのIPアドレスを使う。ローカルホストをiPhoneに入力するとiPhone自身を指す。

行き先を選ぶ → A/B/Cで見る → 店をタップする、または「場所を見る」。ドラッグ、ピンチ、＋／−、街全体。Cの「真上から」は同じ街を俯瞰にする。YOU ↻は現在地を動かさず向きだけを90度変える。回転センサーは使用しない。

A/B/Cは同じ目的地・YOUの向き・パン／ズームを保持する。場所を選び直すと説明だけ閉じる。リロードすると初期状態へ戻る。全体へ戻す操作は位置と倍率だけを戻す。

## 共通の街

座標正本は `town.mjs`。YOU (190,430)、駅 (120,370)、公園 (275,280)、大通り y=205、塔 (435,100)。喫茶 (295,150)、パン屋 (475,270)、本屋 (110,465)。Aには補助道路・区画・他の店を表示、B/Cは選んだ店だけを表示。川は境界の補助として共通表示。

Cは固定の平行投影。地面に一つの変換を適用し、建物の高さだけ画面上方へ伸ばす。実在の地理、経路や方角の正しさを表すものではない。全体表示時に全目印を見られる。パン／ズームで外へ出ても「街全体」で戻れる。

## 観察すること

画面内にテストや採点は設けない。以下は観察者向け手順。発話を促す程度に留め、正答を教える作業や訓練にしない。

1. 最初に表示するA/B/Cを参加者ごとに変える（ABC / BCA / CAB）。初回だけの「どの辺か分かった」までの時間と発話を観察者が記録する。説明を開いたかも記録。
2. 「この店、知っている場所でいうとどの辺？」を自然な会話として聞く。速さと、駅・公園・大通りなど何を基準にしたかを記録する。東西南北は求めない。
3. 店を変えず他の表示を見てもらう。YOU ↻で向きを変えた後、位置の捉え方が変わるか観察する。Cでは斜め／俯瞰の両方を試す。
4. 数分の別の会話を挟み、画面を見ずに「さっきの店はどの辺だった？」と聞く。記憶に残った目印・関係を記録する。必要なら口頭や紙で説明してもらう。
5. 「どれが分かりやすい／記憶に残る／また眺めたい？」を別々に聞く。「ほかの店を見たい」は先に促さず、自発的な操作や発言を観察する。その後で希望を聞く。

記録例: 表示順／店／初回理解までの秒数／説明を開いたか／基準にした場所／向き変更後の発話／数分後の発話／分かりやすさ／記憶／再び見たい／自発的な別店舗選択。

## 解釈の限界

同じ街を繰り返すため順序・学習効果がある。3店舗も同じ街のため独立な課題ではない。Aも固定表示で、GPS回転地図との比較ではない。この試作で比較できるのは情報量と投影の見方、YOUの回転に対する反応。実際の歩行・店から出た直後・方向感覚改善・長期的な習慣化は検証できない。

実在地図、GPS、API、経路、検索、アカウント、保存、外部通信、計測、ゲーム報酬、複数ステージ、Engine依存を意図的に設けない。認知仮説の成否は操作試験の成功とは別に判断する。
