## 初回の失敗と共通ルール修正

| 観測 | 原因 | 修正と再確認 |
| --- | --- | --- |
| 丘・谷・斜面でも縮小すると横一列の街に見えた。高い前景の壁が画面を均一にした | 輪郭の振幅が小さく、高さが一軒ごとの乱数に偏っていた | 輪郭の振幅を拡大。街区単位の高さのまとまりを導入し、前景を低く幅広にした。修正後36枚では輪郭の差を確認できた |
| `postcard-03`で塔が屋根に埋もれ、特徴として読みにくかった | 前のレイヤーの遮蔽だけを検査し、奥の隣家が作る輪郭との差を見ていなかった | 塔の周囲の全レイヤーを含め、上部が輪郭を越えるよう制約。[修正前](review/before/postcard-03.svg)／[同seed修正後](review/postcard-03-after.svg) |
| 小さな帆船の帆が岸辺へ重なる可能性があった | 描画は高さの1.62倍まで帆を伸ばす一方、検査は船の高さだけを使っていた | 実際の帆上端・船影下端を検査し、水域へ配置。[別の同seed：修正前](review/before/postcard-20.svg)／[修正後](review/postcard-20-after.svg) |

特定seedの例外分岐は追加していない。上記を一回の共通ルール修正として実施し、36枚と3,600条件の構造検査をやり直した。その後、塔の検査範囲を生成側と一致させ、水面の線の右端も画面内に制約した。

## 修正後36枚の観察

| 観点 | 観察・具体例 |
| --- | --- |
| A 街としての認識 | 壁、屋根、窓、岸辺、船という少数の図形が、縮小しても街に見える。`001`は高さが連なり、`015`は二つの高い街区と塔がまとまっている |
| B 構図 | `004`と`013`の双丘、`021`の丘、`030`の谷、`007`と`035`の逆向きの斜面を区別できる。岸の高さ、3段・4段、塔の位置も変わる |
| C 配色 | 青い空と朱・黄、桃色の空と群青の水、緑系の空と黄・赤茶の3系列を比較できる。同じ壁色の隣接は避けられている。緑系は他の2系列より明度差が穏やかで、好みは作者に確認したい |
| D 情報量 | 壁面と窓の反復で情報量を作り、細かな線は少ない。一方、`010`・`013`では段差の単色面が広く、密集した港町より急な段丘の町に見える。残る表現上の課題として提示する |
| E 統一感 | 窓の間隔、屋根、壁面、一定幅の岸辺、少数の船が共通する。輪郭が違っても同じシリーズとして読める |
| F 偶然の面白さ | `015`の二つの高い街区の間に立つ塔、`024`の左の塔と右の高層群、`033`の二つの頂部と二隻の船は、個別配置なしで異なる関係になった |

上表の数字は`harbour-`以下のseed番号。魅力の最終判断は作者に委ねる。

## 自動検査と独立コードレビュー

- モデルテスト7件成功。同seed・設定のscene/SVG一致、配色だけ変えた際の配置一致、異seedの構造差、不正数値・支え・連続配置・塔の可視性・船の範囲、SVG基本形式・seedのエスケープを検査。
- 300seed × 4輪郭 × 3密度 = 3,600条件で構造エラーなし。
- 最終36seedは全て構造エラー・警告なし。SVGのタグ数553〜831。全36枚をSVGとして記録し、別のSVGラスタライザー（sharp）で320×400 PNGへ変換できた。これはブラウザーのPNG保存操作とは別の検査である。
- 300seedの生成＋SVG文字列化はNode v24.22.1のコンテナーCPUで中央値1.92ms、95パーセンタイル5.76ms。iPhoneの性能値ではなくDOM描画時間も含まない。最終コードでの再測定は[測定記録](review/performance.json)を優先する。
- UIコードレビューで、PNG作成中に新しい街へ切り替えると旧画像へ新seedのファイル名が付く競合を発見。書き出し開始時にSVGとファイル名を固定する修正を親担当へ依頼し、修正を確認した。
- 一覧は36枚に制限し、作り直し・離脱時のObject URL解放がある。入力seedの画面表示はtextContent、SVG内はエスケープを使い、外部画像・ネットワーク・継続アニメーションは追加していない。

## 未確認・残る課題

実機iPhone Safariのタップ・ダウンロード・発熱、作者による配色と構図の採否は本レビューでは未確認。ブラウザーの操作・SVG/PNG書き出し、360・375・390pxの結果は別途の検証記録を参照する。

水際は水平で、船の種類は2つ、塔は1種類に限定している。同じ輪郭設定では似た街になる場合もある。今後は街区間の空き面の量や岸の輪郭を、既存の図形を使ったまま比較できる。

## 一覧の再生成

検査用環境に既存のsharp・Pillowがある場合、次で36枚と一覧を再生成できる。リポジトリへ依存関係は追加していない。

```sh
node works/postcard-generator/review/generate.mjs
python3 works/postcard-generator/review/make-contact.py
```

`generate.mjs`は`CODEX_PRIMARY_RUNTIME_NODE_MODULES`内のsharpを使用する。通常のLabとSVG生成にはこれらの検査用依存は不要。個別PNGは一覧作成時の中間ファイルで、配布一覧はSVGを使う。
