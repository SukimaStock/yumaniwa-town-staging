# AmberTimeの作業時に守る確定事項

rootのAGENTS.mdとChange OSに従う。このファイルは2026-10-28までに作者が決めた販売室の条件を、次の実装・Lab採用にも引き継ぐためのもの。後の明示的な作者指示で変える場合は、新指示と変更する条件をPRに記録する。新たな作者承認を毎回要求するものではない。

## 販売室の受入条件

- **未解放の店は行ごと表示しない。** 自家販売は常時、普通の店は実際の`shop.relations`が成立してから表示する。「取扱前」の文字だけ消す対応にしない。申し出段階を契約済みと扱わず、申し出の確認は既存の取扱店導線を使う。
- **瓶の本数は実際の残数。** 売れた4本を残数の位置に「−4本」と表示しない。売れた数は商品ごとの「4本売れた」という一時通知として分ける。通知終了後も残数が正しいことを確認する。
- **左側は納品先として押せる見た目。** 枠・有効状態・「置く →」の表示を持たせる。右の瓶を選ぶと引き取り、左の店を押すと置くという既存操作を保つ。
- 手元の実物の瓶を直接選ぶ。銘柄選択dropdown、通常画面の`#10`・`第10回`等の通し番号へ戻さない。瓶の識別は発売日・瓶・本数を使う。
- 本数選択は「1本・5本・全部」。デパートを通常の棚やフッターへ常時表示しない。
- 通常の販売操作はスマートフォン1画面に収める。解放済み1/2/3販路、複数発売回、売れた通知中でも文字・瓶・タップ先が切れないこと。少なくとも360×568、375×620、390×680、430×740で通常フォントを確認する。
- 店へ渡す・引き取るだけでは現金や販売実績を変えず、保存成功後だけ移動・成功演出を確定する。販売計算や保存方式の変更をUI修正へ紛れ込ませない。

## 販売UI変更・Lab採用時の確認

Labの画面全体を移植する前に、この条件と本編の差分を照合する。新機能が動くことだけで既存条件を確認済みにしない。

関連UI変更では次を実行する。

```sh
node --test works/ambertime/tests/market-ui-main.test.mjs works/ambertime/tests/formal-copy.test.mjs works/ambertime/tests/market-rules-ui.test.mjs
```

ブラウザー実行環境がある場合は、次も実行する。依存を製品へ追加せず、実際に利用可能なPlaywright/Chromiumのパスを環境変数へ渡す。

```sh
AMBER_BROWSER_MODULE=/absolute/playwright-core/index.mjs AMBER_BROWSER_EXECUTABLE=/absolute/chromium node --test works/ambertime/tests/market-compact-browser.test.mjs works/ambertime/tests/market-rules-browser.test.mjs
```

実行できない項目は未確認として報告する。作者の実機確認をAIのブラウザー成功で代用しない。テストの期待値を変える場合は、作者の今回の指示で変わった条件を示す。通すためだけに上記受入条件を削らない。

販売ルール・移行・在庫に関わる場合は、既存のstore-market/native model/save回帰も対象にする。既存保存・過去の操作の再解釈を避ける。Stagingへの反映はProduction公開と別判断。
