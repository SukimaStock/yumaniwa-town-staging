## ルール

初期資金£4,000。ゲーム内の通貨・圧縮された時間であり、実際のウイスキー経済の再現ではない。目標額・勝利条件は置かない。

1. 抽出範囲0〜100%を選び、一月に一仕込み。蒸留£260、24〜40 L。
2. Bourbon £160 / Refill £100を選ぶ。原酒は分割して同じ仕込みを別樽で比較できる。貯蔵庫は4樽。毎回樽を購入する。
3. 1か月進める。荒さ・香り・木の影響・残量を更新し、在庫販売と維持費を一括処理。
4. 好きな本数を瓶詰め。0.7 L / £3。瓶詰めした香味は以後変わらない。残った樽は熟成を続ける。
5. 価格£2〜160を設定。来月から売上が入り、次の仕込みに使える。ニューメイクも同じ販売棚で扱う。

棚は在庫のある8商品まで。少数の商品の価格と回転を観察するための上限。全商品が月24人の客を分け合う。客数や樽容量を増やす設備は作らない。

維持費は基本£22/月、熟成中1樽あたり£5/月、手元に原酒があると£3/月。売上を計上し維持費を引くと資金が負になることはあるが、借入や救済収入はない。所持金以上の蒸留・樽購入・瓶詰めは拒否する。棚の売上で回復できない場合は帳面を保存するか新しく始められる。

樽詰め後に瓶1本未満の原酒が残ったとき、最終瓶詰めの端数、蒸発で瓶1本未満になった樽は整理する。微量残量で永久に貯蔵枠・仕込みが停止しない。樽終了記録を保存する。

## 数値モデル

正本は `parameters.mjs`。ロジックは `model.mjs`。UIは `app.mjs` / HTML / CSS。Engine・外部ライブラリ・外部通信は使わない。

| 量 | 変化 |
| --- | --- |
| 収量 | 24 + 16 × 抽出幅 |
| 初期荒さ | 0.22 + 0.68 × 幅、小幅のシード差 |
| 初期個性 | 0.30 + 0.60 × 幅、小幅のシード差 |
| 荒さ | 樽別の指数減衰。Bourbon 0.057、Refill 0.036/月、抽出幅・樽差を反映 |

| 蒸発 | 現在残量へ掛ける。Bourbon 0.26%、Refill 0.19%/月、樽差を反映 |
| 内部需要価値 | 口当たり・個性・木の調和と熟成を反映。強い若い荒さ、木の過多には不利益 |
| 月次需要 | 現在価格/内部需要価値が高いほど指数的に減少。若い原酒と個性的な香りにも需要 |

樽差は軟化・木・蒸発の係数±14%程度。各月の結果を乱数で決めない。抽出と樽選びが主因、乱数は仕込み・樽詰め時のみ。シードと操作列が同じなら、保存を挟んでも再現する。

内部需要価値はテスト用であり、UIに評価点・最適瓶詰め月・将来価格として表示しない。熟成が強ければ高価格、という一本の式にしない。とくに若い強い荒さの需要低下と、熟成後に残る個性の価値を分けた。

## 情報と待つ体験

樽ID、仕込みID/年月、抽出幅、樽詰め年月、熟成年月、残量が分かる。香味は現在状態から作る試飲メモで読み、3か月ごとの履歴を比較できる。荒さ・香り・木の正確なスコアや未来のピークは出さない。同じ種類の樽でも進み方が違う。

全室から月送りできる。維持費と資金が少ない場合の「売上なしで何か月分」を示す。価格編集は確定ボタンで反映し、次月の実績から判断する。月次まとめ・手放した樽・仕込みを帳面に残す。月を進めるだけでは収益は増えない。

最初は蒸留室へのボタンと3段階の操作案内。PC/スマートフォン向けHTML、44px以上の主要操作領域、狭い幅で縦に並ぶCSS。人物・物語・ランキング・ニュースで月送りを埋めない。

## 保存と将来のUI

`sukimastock.ambertime.v1` という専用localStorage key。保存状態は `version:1`, `modelVersion:1`。月次時計・乱数・現金・原酒・樽・棚・履歴を一元化。操作ごと自動保存、手動保存、確認付き初期化、任意シード。

破損・未来版・不整合な年月/残量/出自/本数は読み込まず、元データを上書きしない。保存領域にアクセスできない場合は明示してメモリ内で遊べる。対応する旧版を置き換える前に将来migrationを実装する必要がある。

ドット絵版ではロジックを維持し、操作と観察の表示を交換する。樽を覚える出自/履歴、一本の月時計、シード、不可逆な瓶詰め、数値パラメータの正本を引き継ぐ。Feel Studioへの調整用Bridgeや未使用の拡張クラスは作っていない。
