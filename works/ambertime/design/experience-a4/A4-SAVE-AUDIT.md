# A4 保存機能の監査

基準は staging main `79ee2f90`。構造整理 #768〜#776、体験改善 #778以降、A3 #787・#788の保存境界を引き継ぐ。

| 項目 | 既存動作 |
| --- | --- |
| 正式保存 | `sukimastock.ambertime.main.v1`。ブラウザの localStorage。版2の包みは game、userPaused、elapsed を含む |
| 保存タイミング | 新規起動、必要な復元補正、正式操作、時計・月次処理、画面離脱時の既存経路。設定を開くこと自体に書き込みはない |
| 成功と復元 | 保存書き込み後の読戻し、または起動時の厳密な復元。メニューを表示しても新しい保存を意味しない |
| 失敗・別タブ | 保存停止、元記録保護、再確認／再読込の既存案内。候補操作は比較後に書き込み、失敗時に確定しない。破損時は元の文字列を書き出せる |
| 試遊 | 正式保存を書き換えない。試遊内の初期化は試遊の進行だけを戻す |
| 通常書き出し | `ambertime-save.json`。現在のゲームと時計状態からJSONを作る。正式保存や進行を変更しない。ファイル読込UIはない |
| 旧方式書き出し | `ambertime-before-market-rules.json`、`ambertime-before-store-market.json`、`ambertime-before-stage4.json`。既存の状態条件と投影を使用。接続前は現在の標準設定では非表示 |
| 旧保存引き継ぎ | 正式キーが空の起動時のみ旧2キーを候補にする。明示選択、旧形式と候補の検証、旧データの競合確認、正式キーへのコピー。配分の選択と旧キーの元データを保持 |
| 旧版・研究資料 | 旧版URLはその版で遊ぶ入口。研究所・比較実験は資料へのリンク |
| 新しく始める | 確認後、現在の正式キーに新しい蒸留所を書き込む。旧版キーは残る。取消は変更なし。失敗時は既存の停止・再確認経路 |
| 維持費 | HUD側の要素はCSSで非表示。利用者が確認できる既存の金額として、保存画面の下部に残す |

旧メニューは書き出し、方式変更、初期化を近い位置に置いていた。確認文の「以前の版の記録は残ります」は、現在の正式保存も残るように読める。A4は画面と確認文を整理し、保存・再生・競合・時計の実装を保持する。
