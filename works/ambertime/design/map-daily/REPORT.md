## 読み取りと状態保持

`map-daily-view.mjs`は既存`map-sales-view.mjs`と`mapProgress`から表示だけを導出する。町の酒店・スーパー・デパート以外の仮店舗は追加しない。デパートや旧卸納品は「納」、現行店頭購入は「売」と区別する。未解放・申出だけの店、未来の記録、仮置きを取扱実績へ含めない。

本編に町別・地方別の店頭販売台帳はない。地方・日本・地球では各店の札を並べず、「町の取扱店」の合計と既存の口コミ到達先を区別して表示する。全国への口コミ到達を全国の販売実績に置き換えない。自家販売は蒸留所表示の累計として別扱い。

閲覧範囲と選択だけを別のUI用sessionStorageへ保持する。正式セーブのキー・形式・モデルは変更しない。UIストレージが使えなくても同じページ内の往復は保持し、再読込後は町から開始できる。表示外になった選択は解除する。

地図/子の店情報で販売室を隠す際だけ、既存の引取確認を維持する。地図を閉じる経路で仮配分をリセットせず、販売室への導線で`selectRoom`の保存・取消処理を呼ばない。瓶・数量・未確定の操作を自動確定しない。地図操作から経済APIを呼ばない。

## 表示と操作の確認

クラウドChromiumの360×568、375×620、390×680相当iframeで、専用入口・店選択・範囲往復を操作した。選択前後のCanvas外枠はすべて186×186pxで位置も一致。360pxではダイアログ466px高で画面内に収まり、通常の店の反応も内部スクロールなしで表示できた。長文が来た場合は情報欄だけをスクロールする。

販売室で引取確認を開く → 地図 → 店情報 → 地図 → 戻る、の後も同じ引取確認が残った。実際に回収した後、手元の同じ瓶と「5本」を選択 → 地図 → 地方 → 閉じる → 再度地図 → 販売室、でも瓶・数量を維持し、往復前後の正式保存文字列は同一だった。UI範囲は再読込後も復元した。

3店舗と「売999+ 残999+」「納999+」の表示専用fixtureを同じマークアップ/CSSで描画し、札の相互重なりと文字の切れがないことを確認。ゲームの正式保存へ架空の納品を足していない。未解放・取扱前・完売・回収・混合台帳・表示対象外の選択・初回案内・後続解放は自動テストで確認した。

常時アニメーションは追加しない。reduced-motionに対応。店選択前後で背景Canvasを保持し、実測描画回数は1→1。範囲や既存到達状態が変わる場合だけ描き直す。100シード実行時の6範囲投影合計の最悪値は約39.7ms（Node、端末描画負荷とは別）。実機Safariの発熱・タップ感は未確認。

表現監査：未選択欄を説明で埋めず、常時通知点・装飾的な副題・架空の評判を追加しない。操作名「地図」、期間凡例、選択枠、既存「店情報」への導線は保持した。
