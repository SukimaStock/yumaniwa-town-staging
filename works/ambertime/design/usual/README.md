# AmberTime 0.13 — いつもの仕込み

対象は Staging の `works/ambertime/`。0.12 の手動蒸留・熟成判断・卸売・特別注文・銘柄と評判の計算を維持する。Production、設備、経済パラメータ、レシピ帳、自動販売は変更しない。

## 予約から一樽まで

手動で抽出を止めて樽詰めに成功すると、実際の抽出位置（30〜99）と樽種を一件だけ記録する。旧保存からは成功した手動の stop/fill 履歴を読み、保護された origin にある製法も取り出す。新しい手動仕込みで更新し、自動仕込みでは更新しない。

「次の一樽を任せる」はその製法のコピーを予約する。予約時は無課金。4樽満杯・資金不足・今月の仕込み上限では待つ。実行前だけ無料で取消でき、手動蒸留に戻るときもまず予約を取り消す。

画面の時計が動いていて、試飲・判断・申し出・ダイアログ・保存停止・非表示のいずれでもない場合に開始する。開始時に既存の蒸留費£120を引き、100msごとに既存の抽出処理を一段進める。設定位置に到達したら既存の停止・樽詰め処理を一つの完了操作として実行し、樽代£100/£160を引く。予約は消え、卸売も銘柄も指定していない通常の樽が一つ残る。画面移動を要求しない。

月次は従来どおり6秒ごと。抽出が月をまたいでも他の樽の熟成・販売・出荷が進み、全出荷と資金判定が終わった後の時計で次の仕込みを始める。最後の樽が出荷されても実行可能な予約が時計を起動する。資金不足で仕事がない場合には空の月を無限に進めない。予約中は3か月スキップを止め、抽出時間を短縮しない。予約操作は進行中のスキップも解除する。

## 資金と履歴

開始前に蒸留費・選んだ樽代・既存全樽と最大抽出量の瓶詰め資金を確認する。蒸留中も選んだ樽代を確保し、バーボン樽と最安樽の£60差額を維持費に使わせない。月次の資金回復判断は既存の停止方式を使う。残高や経済係数を補う処理はない。

新しい v10 / `usual-batch` 実行境界を明示的に追加する。`enable-usual`、`reserve-usual`、`cancel-usual`、`start-usual`、`complete-usual` が操作履歴に残る。途中の抽出は既存と同じ進行値を保存し、履歴再生は低層の抽出処理で復元するため、自動完了を二度実行しない。到達済み位置を「途中」として保存した不正状態は拒否する。

新アプリは `sukimastock.ambertime.wholesale.v10` だけに保存する。session v2 はゲーム、時間停止の意思、月内の経過ms（0〜5900、100ms単位）を持つ。v9以前を厳密に復元してから有効化し、元のキーは上書きしない。旧アプリが持たなかった月内経過は移行時のみ0とする。`v012.html` と0.12のアプリはそのまま残る。壊れたv10から旧キーへ黙って戻らない。開始・完了で即保存し、失敗したら時計を止めて同じ状態の保存を再試行する。

## 再現方法と証拠

- `node --test works/ambertime/tests/*.test.mjs`
- `node works/ambertime/design/usual/simulate.mjs`
- `node works/ambertime/design/usual/browser-run.mjs`（Playwright、`AMBERTIME_CHROME` または `/tmp/audit-chromium`）

モデルテストは原酒・乱数・費用の手動一致、抽出30/99、取消、4樽待機、卸売空き、同月複数出荷、選択樽代と瓶詰め資金、停止条件、並行販売、v9と多重origin移行、途中と完了の別プロセス復元を扱う。同月4出荷と厳密な資金閾値は人工境界を明示し、有効な保存の証拠とは分けている。合法的な満杯予約と資金不足も別途公開操作だけで検証する。

UIテストは停止中・試飲・モーダル・非表示、手動競合、出荷後に仕事がなくなる境界、59/60段目と月内5900msの復元、開始/完了の保存失敗を扱う。ブラウザはPC1280pxとiPhone相当390×844pxで実際の手動抽出・樽詰め・予約・取消・途中再読込・自動完了・満杯からの卸売出荷を操作する。検証専用ページは公開操作で作った状態をページ内メモリに置き、プレイヤー保存に触れない。制御時計でもアプリ本来の100msタイマーをすべて実行する。

長期比較は8シード×120か月×手動/自動の二方式。同じ生産要求で抽出65/リフィルと99/バーボンを比較し、毎月の状態、費用・生産量・売上・在庫・時間、途中/60月/120月の履歴再生を照合する。出力は `simulation-results.json`、ブラウザ結果は `browser-results.json`、画面は同ディレクトリのPNG。

実機iPhone Safari、指での触感、作者による採用判断は未確認。Chromiumの画面サイズ確認を実機確認と扱わない。既存のJavaScript実行環境間の浮動小数点差は今回変更しない。Change Verificationのfinal/automatic VERIFIEDは保留のため主張しない。LABは既存の試作作業台の接続を維持する。

## 実行結果（2026-10-17）

8シード全件で120か月の各月状態が一致した。各方式の完成は1シードあたり34樽、自動完成は合計264樽。費用・生産量・抽出tick・売上・最終在庫・資金の方式差はすべて0で、合計1,920か月の比較となった。65/リフィルの平均費用£12,055・平均売上£23,268・最終平均在庫30.75本、99/バーボンは£15,087.25・£28,444・38本。原酒の個性による違いは残り、自動化による生産・時間の優遇はない。

追加の公開操作経路では、月111の特別24か月樽と月117の通常18か月樽が月135に同時出荷し、完全に空いた蒸留所で予約を開始、65tickと通常の月次を経て一樽だけ完成した。予約中・同月出荷直後・完了後の別プロセス再現、売上と費用の各帳簿も一致した。

独立レビューで予約前の進行中スキップ、選んだ樽代を含む不足額表示、到達済み抽出位置の不正な途中保存を確認・対処した。全件テストと最終のモデル/UI重点テストを実行し、PC/iPhone幅のブラウザは各項目合格。Scope Guard、Risk Gate、Impact Check、Lifecycle/LABも照合する。
