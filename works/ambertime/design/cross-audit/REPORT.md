# AmberTime 0.15.2 — 複数樽・在庫・判断導線の横断監査

## 監査基準

基準はStaging `9907ffac1a19672b1acfc0da7881c809abd45e69`（AmberTime 0.15.1）。`shop-app.mjs`、`shop-model.mjs`、`partner-orders.mjs`、`economy.mjs`、`brand-reputation.mjs`、蒸留・熟成・保存と既存テストを確認した。実装と別担当の在庫監査・モーダル監査を分担し、再現できた問題だけ表示層で修正した。Productionは対象外。

## 確認された問題と修正

| 問題 | 再現・影響 | 修正 |
|---|---|---|
| 樽名が現存樽の並び順だった | seed42で樽ID2・4を作り、ID2を瓶詰めするとID4が「樽2」から「樽1」へ変化。出荷済みIDの名前は「樽0」になる | 既存の固定IDを `樽 #2` のような識別番号として表示。貯蔵庫・判断・取引履歴・瓶詰め後の試飲記録で一致 |
| 同じ銘柄の発売回が分かりにくい | 商品モーダルと販売棚に発売番号がなく、同名・同年数の別商品を区別しにくい | 銘柄の永続する発売履歴から「発売2」を算出し、棚・商品・記録・酒店納品履歴に表示 |
| 再読込で商品設定への自動導線が消える | 瓶詰め後に他の樽の判断が続く間、再読込すると実行中だけの `pricingQueue` が消える。商品は未陳列で保存され、在庫消失ではない | 既存の未陳列・在庫あり商品から設定待ちを復元。陳列済み／完売の古いキュー項目は飛ばす |
| 後回し中の販売継続が明示されない | 実際に32本から6本、完売へ進む。納品分を確保する仕様ではない | 申し出に「後回しの間も、自分の棚での販売は続きます。」を追加。在庫ゼロ時は次の発売から届けられることも表示 |

樽番号の欠番は意図的。内部では原酒・樽・商品が識別番号を共有するため、番号が連番になるとは限らない。番号を棚位置と混同しない `#` 表記を採用し、過去記録の整理や旧保存の移行で変わる表示用の別番号は作らない。最大4樽は従来どおりで、番号が大きくても保有可能数を意味しない。

発売番号も現存する商品だけから数えない。完売した発売回が残る履歴を使うため、販売棚から別の発売回が消えても番号は変わらない。

## 問題ではなかった仕様

- 後回し中も自家販売は月次で続き、自然に完売する。在庫の自動確保・予約は行わない。
- 未確認／確認済みの申し出は在庫ゼロでも残る。取扱いだけ始められ、承諾だけでは現金・在庫は変わらない。
- 完売や商品の整理後も銘柄と取扱関係・納品履歴は残る。同じ銘柄を再発売すれば、再契約せず納品できる。
- 納品で減るのは選択した商品だけ。銘柄ごとの月10本枠は複数発売回で共有する。
- 納品分は別台帳で記録され、自家販売の評判・販売実績へ二重加算しない。
- 判断処理は先頭の樽ID＋イベントID、商品操作はモーダルの商品IDを照合していた。誤った樽・銘柄への操作は確認されず、モデルのガードを変更する必要はなかった。

## 判断の順序と時計

順序は **樽の熟成判断 → 瓶詰め後の商品設定 → 通常卸売／特別注文の申し出 → 酒店の申し出** を維持する。判断の数を減らしたり、一括処理へ置き換えたりしない。

樽の判断見出しに固定の樽番号を含め、種類・熟成年数・判断内容を同時に確認できる。別の自動表示対象が待つ場合だけ「このあと判断 N件」を小さく添える。後回し済みの酒店申し出はこの自動待機件数へ含めない。大きな管理一覧は作らない。

モーダル中は既存の時計停止を使い、閉じた後は元の `userPaused` に従う。連続した判断が残っている間は停止を続け、すべて終われば手動の再開操作を追加せず進む。明示的な手動停止は維持する。抽出・樽詰め待ち・試飲の最中には酒店の自動通知を割り込ませない。

未陳列の商品は設定待ちなので、再読込すると再提示する。通常の時計進行だけで、閉じた商品設定を毎月繰り返し開く処理は追加しない。

## 保存・計算の保護

変更は表示専用 `work-context.mjs` と既存UIのみ。固定ID、操作履歴、ゲームv12、セッションenvelope2、保存キーを変えない。新しい保存値や操作は追加しない。未陳列商品の設定待ちは保存済み在庫から算出し、ゲーム状態を修復・書換えしない。

案Aの抽出・熟成・蒸発、4樽、需要、通常卸売・特別注文、酒店の買取率80%・銘柄月10本、評判、自動仕込みは変更しない。既存の厳密な再実行検査も緩めない。

## 数値・在庫の検証

`node works/ambertime/tests/cross-simulate.mjs` で8シード×120か月、計960か月を100ms刻み57,600ステップで進行した。資金・年齢・在庫を注入せず、実際の販売で資金を作り、全シードが4樽の並行保有に到達した。

| 観測項目 | 結果 |
|---|---:|
| 生産 | 233樽 |
| 一樽限定の自動仕込み | 225回 |
| 試飲での停止 | 114回 |
| 通常／特別卸売の出荷 | 21樽 |
| 酒店への任意納品 | 302操作 |
| 特別注文の自然発生・達成 | 2シード |
| 同月の複数出荷 | 2回 |

| 最低現金 | £985 |
| 最終現金の範囲 | £6,414.42〜£6,584.12 |

全シードの60・120か月で厳密な保存再実行、現金・本数・販売先別売上の一致を確認した。保護対象モデル9ファイルは実行前後とも基準SHA256と一致した。[全結果](simulation-results.json)に方針・生産・会計・年次在庫・再実行指紋を保存した。これは一つの運営方針の監査であり、利益の最適化や面白さの判定ではない。

別の合法な操作履歴フィクスチャで、同月通常卸売2樽、特別注文42本×£26.10、未達注文の明示的な通常卸売への切替も確認した。これらを全8シードで発生したものとは扱わない。

在庫ケースはseed42の公開操作で、申し出時32本→後回し2か月後6本→完売を確認した。未確認・確認済みの申し出と、納品せず完売した承諾済み関係はいずれも保持。ゼロ在庫での承諾、再発売45本から5本納品して40本、別発売回の在庫不変、残り4本だけの提示も成功した。

## 実ブラウザ確認
