# AmberTime 0.9 — 継続的な卸売販売

基準: staging `4fb5dcb32ef402aeb9887de7fa711cd330ddcd3d`。作品内のみ。旧モデル・経済パラメータ・4樽上限は未変更。

## 取引と樽を分ける

一社の `relationship` と、内部樽IDを持つ `contracts[]` は別の状態。最初の申し出を承諾すると関係が始まり、選んだ一樽だけを指定する。新しい樽は勝手に指定しない。出荷は指定だけを完了し、取引先は残る。

- 既存の貯蔵庫で樽を選び「卸売へ指定」。初回の二条件は既存12/18/24/30か月の隣接条件と同じ価格係数で提示。樽ごとに年齢・単価・費用を固定する。
- 瓶詰め前は一樽だけ無料解除できる。他の指定・熟成判断には影響しない。
- 販売室で取引先・提示条件・納品累計を確認。休止は新規指定だけを停止し、確定済み出荷は履行する。終了は全指定解除を確認し、熟成は継続する。
- 自由な試飲、通常の熟成イベント、見守る／方針変更は0.8.1のまま。販売の委任は熟成の自動化ではない。

## 次の申し出

初回は過去の出荷本数・若い商品の実績・継続性から確率を決める。0.9では卸売記録も実績として使い、通常販売を繰り返さなくても次につながる。

継続先の納品が1件以上ある場合、12〜18か月の間隔の後、納品実績に応じた月6〜10%の確率で新条件を提案する。承諾・辞退どちらも可能。未提示年齢を優先し、全4年齢が揃えば一条件の単価変更を提案する。メニューは年齢ごとに一条件、最大4件。価格は既存の条件表と係数を使用し、大きな経済調整はしない。

承諾で変わるのは今後指定できる条件だけ。指定済み樽は条件の写しを持つため、後から変更・値下げしない。保証は単価であり、蒸発後の本数と総額は見込みとして区別する。

## 月次処理

全樽熟成と小売販売 → 出荷前の樽数で維持費を一度計上・按分 → 内部ID順に満期樽をまとめて瓶詰め・出荷 → 資金予約保護 → 残った樽の判断・申し出。

各出荷は通常瓶詰め処理を再利用し、棚待ちだけを省く。売上・瓶詰め費・本数・残量・試飲／判断記録・完成記録を一取引で更新する。`lastShipments[]` に同月全件を残し、UIでは本数・純入金をまとめて通知する。表示中の部屋は計算に使わない。

全樽の瓶詰め費を予約する従来の資金保護を維持。支払える非指定樽から回収を促し、最も近い卸売出荷までの期間を示す。全樽指定時も予約を無条件で取り崩さない。この保守的停止は現金破産とは別であり、0.8.1から続く設計上の留保。

## 保存

`trade.mjs` は version5 / `continuous-wholesale`、キー `.wholesale.v5`。旧 `wholesale.mjs` と `v08-app.mjs` は完全に残し、旧入口 `v081.html` を追加する。

新キーがない場合だけv4、次にv3を検査。旧エンジンで厳密復元したv4状態（入れ子のv3を含む）を `origin` に保管し、新操作だけを0.9で再現する。既存の単発契約は同じ条件の取引先と一樽の指定へ移す。申し出中・試飲中・蒸留途中・判断待ち・手動停止も保持する。元キーは書き換えず、新キーが壊れていれば黙って巻き戻さず停止する。容量エラー時も停止する。

## 検証と留保

全200自動テスト成功（旧180件は未変更、新モデル11件・新UI9件）。通常の継続納品・個別解除・休止／再開／終了・条件提案・出荷後の再仕込み・保存は合法な操作履歴で再現。4樽同月出荷＋通常販売＋資金ゼロの境界は、注記した状態注入でトランザクションを検査した。

実時計と同じ蒸留60フレーム／月で作った `fixtures.mjs` の3状態を保存し、ブラウザ用 `browser-check.html` で実際のindex/appをメモリ保存に隔離して操作できる。最初の申し出・2樽同月出荷前・納品後の条件提案を比較する。実際のブラウザ結果・公開SHAはPRへ追記する。ローカルサーバーはブラウザ環境から到達できなかったため、公開後の検証と区別する。

独立レビューで申し出種別が帳面の `kind` を上書きする問題を発見し、`offerKind` を別に保持して修正。回帰で確認。QA状態生成の初回は蒸留中に起きた既存熟成判断を解決せず停止したため、実際のプレイヤー同様に判断を解決して続けるスクリプトへ直した。ゲームの判断を消す変更はしていない。

長期経済結果は `BALANCE.md` とCSV/JSON。人間の面白さ・実機Safariの触感を自動検証済みとは扱わない。
