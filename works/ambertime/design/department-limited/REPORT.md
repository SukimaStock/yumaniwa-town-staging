# AmberTime 0.16.2 — デパートの限定取扱い

デパートを「特選ウイスキー」の限定取扱いへ変更した。一つの相談から5本を納品すると完了する。24か月以上・刺激0.30以下・標準価格の140%は維持。個人商店・スーパー、蒸留・熟成・試飲・評判・4樽・通常卸売・特別注文の計算は変更していない。

原典は現行0.16（PR #456）と、[0.16.1比較監査](https://github.com/SukimaStock/yumaniwa-town-staging/blob/3eee35090a4c894c8337723fe3946b714ca1e68f/works/ambertime/design/department-audit/REPORT.md)。比較スクリプトの製造・在庫配分方針を、実際のv13/v14モデルによる検証へ引き継いだ。風味別企画や認知・需要・評判ボーナスは追加していない。

## 操作

販売室に「町のデパートからの相談」が届く。既存モーダルで銘柄、対象の発売回、熟成期間、5本、買取単価、納品後の在庫を確認する。条件を満たす在庫があれば「5本届ける」でその場で納品できる。

「相談を残す」は、次の発売で改めて応えるための関心の記録。「あとで考える」は既存の申し出を保留する。「今回は断る」は辞退する。在庫は予約せず、生産・納品の義務や期限、辞退による評判低下はない。

残した相談への納品は、次に発売した瓶の既存モーダルから行う。その発売回の24か月・刺激・在庫5本を改めて検査する。過去の条件適合を理由に、条件の違う商品を渡すことはできない。相談は瓶のモーダルと銘柄記録の「相談を終える」から取り消せる。商品が完売・削除されても、銘柄記録から終了できる。

納品後は「今回の企画は完了」、採用実績は既存の銘柄記録に年月・企画名・発売回・5本・買取金額で残る。再発売後も閲覧できる。新しい管理画面、評価点・星・派手な演出は追加していない。

## 管理と識別子

| 項目 | 内容 |
| --- | --- |
| 保存モデル | v14 / `department-limited-selection` |
| 企画種別ID | `department-select-whisky`。表示名「特選ウイスキー」の一種類 |
| 個別の選考ID | `department-selection-<offerSerial>`。相談と納品を結ぶ不変のID |
| 選考元発売回 | `sourceReleaseId`。申し出の根拠になった過去または現在の発売回 |
| 実際の納品発売回 | `releaseId`。5本を実際に渡した発売回。選考元と異なってよい |
| 採用記録 | 銘柄ID、両発売回ID、企画・選考ID、採用月、5本、単価・金額、納品履歴ID |

取扱関係と、今回の5本の選考を区別する。納品後も店との関係は残るが、関係だけを理由に翌月さらに納品することはできない。完了するとその相談を除き、採用記録と通常の納品履歴を同時に確定する。在庫・所持金・売上は一度だけ更新し、自家販売実績と評判には加算しない。

同じ発売回は再採用しない。旧版でデパートへ納品済みの発売回も、新しい選考や新しい採用の対象にしない。申し出済みの根拠発売回は再び使わず、新しい発売回を次の機会とする。新しい申し出は従来どおり安全な月次時点、販売実績40本・売れた発売回2回・銘柄作成後2か月・評判、共通の6か月間隔などを満たした時に発生する。辞退・相談終了後の12か月待機も既存方式を使う。

在庫なしでも、条件を満たした発売履歴から申し出可能。引受済み相談は同じ銘柄・同じ企画に1件だけ。未処理の申し出も既存の店舗別待機列を使うため、同じ店の通知が無制限に積み上がらない。選考元の記録は発売回上限512件内、相談数は銘柄数内、採用数は納品履歴上限内に収まる。相談は月次進行や販売を止めない。

旧Aの月間5本上限は、デパートについて個別の選考5本へ置き換えた。別銘柄の別選考を同じ月に納品することはできる。個人商店・スーパーの店舗別月間上限と条件は従来のまま。

## 保存と旧版

既存状態を厳密に復元してから `enable-department` 操作を追加し、v14へ移行する。現行キーは `sukimastock.ambertime.wholesale.v14`。移行時に旧v13以下の原文は書き換えない。既存の取扱関係・納品履歴・他店舗の保留申し出を維持する。デパートの保留申し出は、再採用可能な発売回がある場合に限定相談へ引き継ぐ。過去の納品から新しい採用実績を作らない。

v13のコンストラクターと操作は引き続き従来の継続納品を再現する。途中の蒸留進行と「いつもの仕込み」も履歴から復元する。新しい納品操作には選考IDを記録し、別の相談へ古いボタンが使われることを防ぐ。操作帳や納品帳の上限を超えるときは原子的に拒否する。厳密なJSON比較を緩めていない。

`v016.html` と元のUI・CSSのコピーを残し、保存・以前の版から開ける。UI/CSSのSHA256は実装前と一致する。実ブラウザで旧画面を開き、v13の取扱関係・履歴とv14の保存が共存することを確認した。旧画面を利用すれば従来どおり自身のv13進行は更新される。v14から旧版へ逆変換はしない。

## 長期比較

8シード×240か月×旧v13／実装v14の16走行、計3,840か月。初期資金£1,600、最大4樽。抽出40・65・90、バーボン／リフィル、3銘柄を同じ順で製造した。36か月までは2樽・6か月品、その後4樽で12・24・36・24か月を割り振る。棚は標準価格、瓶詰めから月を一度進め、48か月からデパート→スーパー→個人商店の順で納品する。24か月以上の在庫は最初のデパート関係成立まで他店舗へ回さず、自家販売を続ける。通常卸売の申し出は断る比較方針。

全8組で記録した発売年月・本数・抽出時期・樽種・刺激・個性の値が一致した。4樽、在庫保存則、会計、自家販売と納品の分離、納品による評判不変を検査。16走行すべて別Nodeプロセスでも保存の厳密再生・再保存が一致した。蒸留・熟成・需要・原価・評判に関する7ファイルのハッシュは基準版と実行前後で一致する。

| 8走行合計 | 旧v13 | 限定v14 |
| --- | ---: | ---: |
| デパートの申し出 | 23 | 80 |
| デパート納品操作／完了選考 | 125操作 | 77選考 |
| デパート納品 | 625本 | 385本 |
| 個人商店納品 | 1,494本 | 1,689本 |
| スーパー納品 | 4,119本 | 4,148本 |
| 自家販売 | 8,756本 | 8,772本 |
| 期末現金 | £96,995.39 | £93,990.44 |
| 実現収支（売上−製造費−維持費） | £84,195.39 | £81,190.44 |
| 期末瓶在庫 | 344本 | 344本 |

v14の77選考はすべて5本で、同じ発売回の重複採用ゼロ。80申し出中77件に納品し、期末の相談は3件。相談数の最大は各走行3件、各銘柄1件だった。最初のデパート納品は両モデルとも7シードで64か月目、1シードで79か月目。

56件の採用では、選考元と実納品の発売回が違っていた。過去実績からの相談に次の発売で応えられたことを示す。完成した相談の待ち時間は中央値28か月、最大76か月。期末に残った3件も13〜29か月経過していた。相談を長く残す可能性自体はなくしていない。期限・義務を設けず、重複を抑え、必要なら終了できる形にした。

採用は早め／中盤／後半抽出で31／31／15件、24／36か月で39／38件。現行条件は穏やかな酒を選ぶ一種類の企画であり、これを品質全体の順位や、別風味の評価まで実現したとは扱わない。

0.16.1の比較用Bの440本とは一致しない。今回の実装は同じ選考元の再利用と、旧デパート納品済み発売回の採用を防ぐ。比較用Bの周期的な再申し出をそのまま本編へ写していない。金銭面の結果を良くするための価格・需要調整もしていない。上の結果は固定の在庫配分方針であり、最適戦略や人間の面白さを示さない。期末の樽・瓶在庫は清算していない。

## 検証

- 全Nodeテスト458件成功、失敗0。限定取扱い21件には24か月／0.30／5本境界、翌月・同一発売回の再採用拒否、次回発売、相談取消、旧関係・履歴、旧保存・途中蒸留、別プロセス再生、会計・容量・古いIDの原子的拒否、他店舗・待機列・判断優先を含む。
- 実ChromiumでPC1280×900、iPhoneサイズ390×844の計14ケース成功。日本語表示、44px操作対象、横はみ出し・ページエラーなし。即時納品／完了、在庫なし相談と取消、次回発売、複数申し出と辞退、時間再開・手動停止維持、旧版入口、4樽識別・連続判断・再読込を確認した。
- 独立レビューで内部のキャッシュ参照更新漏れを修正。新しい `shop-model.mjs` は内部import／re-exportも0.16.2指定に統一した。再検査後の阻害事項なし。
- 長期検証の初回で子プロセスへの日本語入力が分割Buffer変換で破損する検証側の問題を発見。UTF-8ストリーム指定で修正し、16走行を再実行して厳密一致を確認した。本編の文字列・数値・保存判定は変更していない。
- 表現監査は既存画面の状態・金額・履歴の短い案内に限定。LABの既存入口・名称・探索状態は維持。新しい作品登録は不要。

実機iPhone Safari、実指の触感と「選ばれて嬉しい」という体験の評価は未確認。作者による採用・Production公開をCI成功で代替しない。
