## 表示方式

PR #644の `uniformMetrics()`、Canvas描画/計測/折り返し、CSSのスコープ・優先順位はそのまま。現在の本編HTMLにある既存マーカーを確認した場合だけ、単一サイズを標準にする。マーカーのない過去版・独立Labは有効化しない。`font-uniform=0` の明示時だけ旧サイズへ戻る。

美咲・BODY_SIZE=20・8物理px単位の丸め・DOMとの同期・整数ドットを維持。360/375/390px、高さ844px、DPR3ではCanvas64物理px、DOM約21.3333 CSS px、1ドット8物理px。カウントダウン・見出し・補助文字・入力も同じサイズ。フォント/CSS/行間/余白/色/絵/枠/座標の変更、サイズ例外はない。比較URLも同じ `main.v1` を読み書きし、保存項目は増やさない。

### 完売の識別

表示専用 `soldOutLabel()` が、完売した実productIdに一致するreleaseを参照し、実brandIdの名前を使う。発売年月用の `releaseLabel()` は帳面・詳細で従来どおり使う。棚や在庫の順番から商品を推測しない。

- 同brandに複数発売: **記録にある発売ID**を補助表示。欠けた旧記録から「第何回」を作り直さない。
- 旧保存の同名別brand: `麦（ブランド #1）・発売 #8` と `麦（ブランド #2）` のように実brandIdを補う。
- 同時処理で空の商品が棚から除去された場合も、before/afterの記録を実IDで照合。
- brand不明: `ウイスキー（発売 #77）`。releaseもなければ `ウイスキー（商品 #31）`。古いrecord.nameは味の名前の可能性があるため、ブランドとは断定しない。
- プレイヤー名はそのまま。通知は既存のtextContent経路を使い、名前をHTMLとして処理しない。

完売の検出式、通知ID・件数・順番・集約・重複抑制・3500msの表示時間は変えていない。表示ラベルを作るcallbackだけ差し替えた。通常販売/発送を静かに扱う正式版の条件も維持。

## 意図して維持した文章

店の他の台詞・客の感想47グループ、味/試飲/熟成の記録、口コミ/問い合わせ/訪問/地図の一言、世代の出来事・歴史本文は原則維持。挨拶の句点と構造化事実から作る世代の固定テンプレだけ変更した。

`次の代へ引き継ぐ` と `○代へ引き継ぎました。` は動詞として維持。保存の「引きつぐ記録」や安全文も維持。過去の文・入力された名前へ一括置換は適用していない。

既存の `翌月5本納品` は「翌月」の予定を示す文、`納品した分は戻せません` は確定後の不可逆性の警告として維持。資金保護停止の説明、未確認範囲を示す「確認できた納品」「確認できた入金」、理由と対処を含む重要なエラーは短縮しない。

[安全エラー補足](error-inventory.json) は静的到達依存72モジュールの日本語例外386箇所・動的転送8箇所を、発生元/包含関数/assert条件/表示経路/維持理由付きで記録。通常操作で防がれる防御検証、復旧時に固定案内へまとめられる検証、開発用引数、worker内部診断を分けた。全例外を実機で発火した証明ではなく、内部ログを通常UIの変更対象に含めるものでもない。

## 確認結果

- 関連unit **59件成功**（font4、message5、event8、描画4、配分/保存/free-aging38）。実IDで複数brand・同brand複数発売・同月発売・同名brand・疎な旧記録・brand欠損・商品除去・名前の記号を確認。
- 表示ラベルを除くbefore/after通知イベントが一致し、状態が不変であること、再通知抑制と3500msを確認。
- 360/375/390px・DPR3の**33表示**と基本操作15項目を確認。[結果](browser-results.json) / [再現用ハーネス](browser.cjs)。文字のcomputed sizeとCanvas fillText、枠内、ボタンの横はみ出しを計測。測定範囲で横はみ出し・画面外小窓0。
- 通常→明示1→旧サイズ0→通常で保存byte列が一致。仮置き/ひとつ戻すでは未保存、確定後に一度保存、同じ配分では保存も成功演出も追加しない。
- 実際の手動/時期指定自動ビン詰め、月次で在庫が0になる完売、町の酒店への実納品の表示を確認。保存setItem失敗を注入し、成功文を出さず在庫・保存byte列が維持されることを確認。
- 独立レビューで重大な指摘なし。Scope→Risk→Impact、必須CI、公開版のexact SHA・配信一致はこのPRの証拠コメントに記録する。

検証ハーネスでは、停止した仮想時計による部屋切替の描画待ち不足と、注入したStorage例外の復元漏れを修正して再実行した。製品コードの変更で検査を通していない。包括的ゲームE2E・長期計算監査は行っていない。

実機Safari/VoiceOverは未確認。計算、需要、保存形式/キー、操作履歴、取扱関係、月次、地図解放、時間処理、通知条件/順番/時間、Productionは未変更。正式なChange Verification stateは契約上UNVERIFIEDを維持し、CI成功を実機確認とは扱わない。
