# 帳面 第4段階 — 世代交代の振り返り

基準 main d1add6177ba9fd0e4680d1efca1d29e75aad6cb4（PR #570）。実装前Plan Lock ffa4f0cd8f76a1a2f2d1f9bc76c25d33823608c05b02d9b4857c2595765dfc82。

## 集計と帰属

generation-summary.mjs は既存の public operation replay から切り離された before / after を読むだけの投影。保存項目・操作列・当主交代条件・最後の仕込み処理・経済計算を変更しない。distillery-history.mjs の既存replayにcollectorを接続し、年表と世代集計を1回のreplayで生成する。UIスレッドで再生せず既存 history-worker を使用する。PR #568/#569のcask workerと帳面4分類は維持。

- 実行者: 操作直前の before.generations.active.id。製作者や年月範囲で振り分けない。同月に引継いだ後の瓶詰め・売上は次代。
- 仕込たる: 操作によって増えた一意のcore.casks ID。手動fill・自動complete-usual。開始だけでは増やさない。
- ビン詰め: 操作によって生成された一意の商品IDのoriginalStock。部分瓶詰め、自動瓶詰め、旧卸売の月次瓶詰めも含む。record/releaseミラーを重ねない。
- 販売: core.totals.bottlesSoldの操作前後差分。小売・店舗納品・デパート・旧卸売を一度だけ数える。lastMonthを累計の正本にしない。
- 完了した代: generation-handoverを観測した時点の集計・樽数・資金で確定。後継者の進行で変わらない。世代記録しか残らず引継ぎ操作を観測できない場合、財産・実績はnull。
- 欠損: originや世代導入前の作業を初代へ補わない。不完全な世代は「記録の残る範囲」とし、確認できた正の小計は「以上」、ゼロしか確認できない項目は「不明」。完全に観測できたゼロと区別する。次の世代は観測した交代操作から完全に集計可能。

## 表示

既存の世代交代モーダル: 世代名（タイトル）・期間 → 仕込み/ビン詰め/販売の3数字 → 実際の出来事最大2件 → 最後の仕込み（完成/未完成/見送り）→ 引継たる/資金。資金は正確なセント表示。出来事は新しい通常店舗の初回取扱開始・実納品に紐づくデパート採用・36か月以上の初回瓶詰めから操作順に先着2件。相談・承認待ちを実採用にしない。

「蒸留所の歩み」の完了世代ボタンから同じ表示・集計を再利用する。新しい世代管理画面・保存台帳なし。交代確認から歩みを開いて戻る導線も維持。読込中も引継ぎ・歩み・戻るを操作でき、失敗時は再試行。古い応答が別stateへ描画しない。親画面・フォーカス・展開とスクロールは既存復元を再利用。
