# 自家販売演出のイベント監査

対象は保存が成功した月次販売の表示だけ。`savedMarketSales(before, after)` の既存導線を使用し、正式な販売・在庫・価格・評判計算へ処理を追加していない。基準mainは `cee22eaf`、実装前のPlan Lockは `.change-plans/ambertime-home-sale-flight/r0.lock.json`。

## 正式なイベントへの接続

`shop-app.mjs` の月次タイマーは `save()` の成功を確認した `if(saved)` 内で `marketUI.consume(beforeStep, game)` を呼ぶ。市場操作のトランザクションも候補保存を確認してから `game=next` と `consume(before, game)` へ進む。書込み失敗ではこの経路へ到達しない。プレビューは既存方針どおり正式保存を作らずに試遊する。

投影は次の条件を満たす販売だけを受け取る。

- 現在月が前の状態より進み、`lastMonth.month` が現在月と一致する。
- 正の整数の実販売本数がある。
- 自家販売（既存のchannelなし、または明示的retail）か、通常店へのstockist販売。
- 同じ商品ID・同じ店IDだけを合算する。

旧処理では非stockistをすべて自家販売と見なしていた。一方、正式モデルには `channel:'wholesale'` の販売も存在するため、自家販売の瓶移動が誤発火し得た。今回UI投影にchannelの許可条件を追加し、卸売・デパートの特別取引を通常店の演出から除外する。販売モデルのchannelや計算結果は変更しない。

`consume` は同じ販売リストを重複消費せず、再描画時に演出を再作成しない。再読込ではbefore/afterの月差がなく、販売イベントを新規生成しない。配置・取消・引取りも同じ月の操作であり、売上演出にはならない。

## 本物の月次販売を使った数量検証

既存の `tests/fixtures/placement-established-six.json` を正式な `restoreDistillery` で読み込み、`enableStoreMarket` と `enableMarketRules` を公開APIで順に実行する。商品ID5・月12で、`setMarketRetail` を使って自家販売へ割り当て、既存の `advance` で月13へ進める。架空の販売結果を本編状態へ注入していない。

| 自家販売へ割り当て | 正式な月13の販売 | 売上 |
| ---: | ---: | ---: |
| 0 | 0 | 0 |
| 1 | 0 | 0 |
| 2 | 1 | 16 |
| 3 | 2 | 32 |
| 4 | 3 | 48 |
| 5 | 4 | 64 |
| 6 | 5 | 80 |

したがって、1本・2本・3本・4本以上の演出確認にはすべて実際の採用済みルールによる販売を使用できる。割当本数と売れた本数を取り違えない。

同じ商品・異なる店、異なる発売回については、引き続き正式に読み込める旧市場ルールの同fixtureも使う。この状態に限り、通常店へ2本、自家販売へ2本を配置し、残存する樽から別の発売回を2本瓶詰めして自家販売へ置く。正式月次処理は商品5の自家販売2本／町の酒店2本と商品6の自家販売2本を別々に出力する。現行ルールで同条件の店は `waiting-for-customers` となるため、この結果を現行ルールの需要と混同しない。

重複行の合算・未知channel・デパート除外・負値・小数・古いlastMonthは、別途**表示投影専用の合成入力**で検査する。これは実際のゲーム進行として扱わない。

## 日付の意味

商品札の日付は発売回の `bottledMonth`、つまり瓶詰め年月である。蒸留年月や熟成年数ではない。正式リリース情報を優先し、既存の製品データへフォールバックする。fixtureの商品5は瓶詰め月11（2026年12月）で、短縮表示は `26/12`。同じ短縮表示になる異なる世紀の製品がある場合は、既存の年の省略回避を維持する。

## 回帰と不変性

`tests/retail-sale-events.test.mjs` の5テストで、実販売数量0–5、商品・店舗の分離、配置／返品／未確定取消、再読込、表示専用の合算と除外、日付の意味を確認する。各数量で以下を検証する。

- 正式な在庫減少・累計販売・自家販売残数が実販売と一致する。
- 現金は既存月次売上・維持費から算出された値と一致する。
- 投影の前後で正式なシリアライズ結果が一字も変わらない。
- 同じネイティブ操作を投影なしで行った分岐と、正式セーブが完全一致する。
- 正式復元後のセーブも完全一致し、同じ月の再読込では再発火しない。

```sh
node --test works/ambertime/tests/retail-sale-events.test.mjs works/ambertime/tests/store-market-main.test.mjs
```
