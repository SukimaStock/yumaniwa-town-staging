# AmberTime 0.23.3 — 操作と表示の細部調整

基準main: `a33a0ad149e4f28fc5560c353842af01775073c1`（PR #550）。AGENTS、Change OS、表現監査、PR #546〜#550、共有iPhone画像IMG_6150〜6153を確認した。Productionは変更しない。

## 変更した表示・操作

- 蒸留ボタンと蒸留室タブの操作寸法を108×45論理pxに揃えた。空の貯蔵庫から戻るボタンも同寸法。樽選択の原酒量は中央寄せ。
- 手動瓶詰めは5・10・15…の候補と「残り全部」。残り3本など5本未満でも選べる。費用を払える候補だけを表示し、前回値が候補外なら合法な近い候補へ調整する。モデルへは従来と同じ実本数を渡す。自動予約の本数は変更しない。
- 発売回は実際の`bottledMonth`から年月を表示。販売棚・商品画面・帳面・歩み・比較・製法元・店舗履歴・完売通知を統一。同月の複数回は樽No.を付け、同月同樽の複数部分瓶詰めにはその組内の1回目・2回目を付ける。内部ID・保存・並び順は維持。販売棚では年月を主表示、同月の識別を2行目に短く表示する。AmberTimeは瓶・商品画面・操作ラベルに維持。納品月や初回販売月を瓶詰め月に流用しない。
- 酒店の実申し出に「AmberTimeの名前を聞きました。」、承認後の既存戻り画面に「これからよろしくお願いします。」を表示。新しい独立ポップアップや保存項目はない。再訪問時はPR #550の既存台詞に戻る。納品済みとは言わない。
- 瓶詰め担当者の時期条件は「12か月で一度だけ」など実設定に合わせた表記。樽ごとの大きな詳細ボタンを、同じ担当者画面のスイッチに置換。オフで既存予約を停止、再オンでその予約を再開するため、途中で共通方針を変えても元の条件が残る。予約取消は同じ画面で行え、取消後に任せる場合は保存済み共通方針から新規委任する。未設定なら短く保存を案内する。樽詳細からの手動瓶詰めは従来どおり。
- 時計は落ち着いた黄系、補充は緑系、停止は赤茶系。既存の形も残す。完了・予約なしはアイコンなし。

## 抽出99/100の原因と扱い

`economy.mjs`の`distillStep`は`distillMax - 1`（99）で止まり、`aroma-extraction.mjs`は抽出位置30〜99の固定係数だけを持つ。保存操作の検証・再現もこの範囲を前提としている。試験で120回進めても99・39.77 Lになり、`aromaPreview(100)`は拒否された。低層モデルの100終端を本編へ単純に通すと、香りの係数や自動停止・保存再生との整合まで変わる。

そのため今回は100の新計算を追加せず、UIの抽出位置の分母を実上限99へ修正した。99/99が採取完了を表す。既存の上限到達→停止→樽選択の自動案内は維持。他室には割り込まず、蒸留室へ戻ったときに一度案内する。途中の手動停止、保存済み樽詰め待ち、担当者の指定位置・指定樽への自動仕込みも変更しない。保存文中の実際の抽出率や過去の文章は書き換えない。

## 冷暗所の検証

機能は維持した。樽画面の月齢の横に、移動後は「冷暗所」と表示する。

| 項目 | 現行の効果・条件 |
|---|---|
| 木の移り | 遅くなる（既存係数0.83） |
| 蒸発 | 減る（既存係数0.86） |
| 刺激の和らぎ | 遅くなる（既存係数0.88） |
| 月齢 | 通常どおり毎月進む |
| 香り | 直接の熟成速度補正はなく、木の増加に伴う減衰を間接的に遅らせる |
| 操作 | 現存する未移動の樽に一度だけ。熟成判断・重要な取引判断がなく、試飲していないか同じ樽を試飲中に操作可能 |
| 費用・保存 | 移動費なし。既存variationを係数適用後0.8〜1.2へ制限し、既存記録へ残す。戻す操作はない |

seed42・抽出65・バーボンの純計算比較では、24か月の木成分は通常0.4343／冷暗所0.3645、残量30.0850／30.3464 L。60か月の香りは0.9467／0.9879。120か月では両方の木成分が既存上限1.35へ達する。冷暗所は変化を止めたり、長期熟成を必ず有利にする機能ではない。原酒を残す判断として自由熟成と併存できるため、廃止・係数変更は提案しない。
