# AmberTime 0.18 — 比較と製法の記録・第一段階

樽と発売回を二つ選び、仕込み・熟成・瓶詰め・販売の事実を比べる。手動で完成させた仕込みを製法帳へ残し、選び直して既存の「次の一樽を任せる」で使う。蒸留・熟成・販売の並行進行と、従来の計算・価格・条件・4樽・世代交代時期を維持する。

## 原典と既存記録の監査

着手時のStaging基点は `6eb9b676f68ada4fd9601cde7a9e8dbd43c56f66`。0.17.1の銘柄別店舗表示、0.17の世代交代、0.16.4の歩みを前提にした。

Codea原典はDriveの [AmberTime.txt](https://drive.google.com/file/d/1cAtwEtLj0DoMbrw7XOwI0XdcA2dopTFi/view) と [当時の紹介記事PDF](https://drive.google.com/file/d/1OOOp4tyGNoD0IvcCwAitXIUOe5lLV5HH/view) を読み取った。ソースの `lastDistillPreset` は前回の設定を復元し、`SalesLedger` は実際の取引を販路別に記録して重複を避ける。今回はその参照・再選択と実取引の区別を採用し、原典の品質ランク、数値、雇用、試験蒸留、利益計算は移植しない。紹介記事で述べられた複数の判断と結果の個性を保ち、優劣を文章で結論づけない。

| 情報 | 正本と取得方法 |
| --- | --- |
| 仕込み年月・抽出位置 | 実際のstart／stop／fill操作を同じエンジンで再生。手動fill直前のprogressを使い、正規化cutから逆算しない |
| 樽種・樽詰め年月 | 実際の樽とfill前後の安定ID。batchId・caskIdを接続 |
| 熟成・原酒量 | 熟成中は現在の樽、発売回は瓶詰め記録の風味・残量。瓶内熟成を加えない |
| 瓶詰め・銘柄・発売回 | records、releases、実際のbottle操作。productId・releaseId・brandIdを接続 |
| 販売開始・稼働月数 | list操作と、在庫がありlistedだった実際の月次だけ。発売からの経過月数で代用しない |
| 価格・売上 | 実際の価格変更と月次販売。販売価格別の本数・売上を集計し、現在価格を過去に掛け直さない |
| 取扱店・卸売・特別注文 | 納品帳、実出荷記録と月次取引。自家販売へ二重計上しない |
| 先代・製法元 | 既存の世代記録と実際に観測できた担当世代。世代導入前の不明な担当はnull |

通常の表示記録は瓶詰め12件、樽archive24件等で省略されるが、操作帳と永続の発売回は別。比較では再生で過去の実記録を復元する。旧origin境界前の欠落は推測しない。累計売上があっても、開始年月・販売期間・抽出位置が不明なら「記録なし」とする。利益は、全原価・維持費の配賦の完全性を今回保証しないため対象外。

## 操作と表示

貯蔵庫の樽、試飲中の樽、ボトル詳細、銘柄／発売回や過去の瓶詰め記録の「比較する」から開く。A・Bを選び、樽同士・発売回同士・混合を比較できる。銘柄をまたいだ選択も可能。各対象を変更・解除でき、閉じると元の樽・ボトル詳細・試飲へ戻る。

表は工程に沿うラベルと値で構成し、異なる表示値には「違いあり」を添える。色だけで判別させず、勝者・総合点・推奨抽出・最適時期を出さない。風味は既存の刺激・原酒の香り・木の移りと表現を使う。熟成中の現在値と瓶詰め時点の値を区別する。

販売中・完売・保管中・卸売出荷を分け、在庫・販売開始・実際の自家販売稼働月数・最初／最後の販売・確認できた価格変更・販路別の本数と売上を表示する。条件が違う売上から製法の優劣を断定しない。

比較の選択・戻り先・キャッシュは一時的なUI状態。開閉は既存のモーダルによる時間停止へ組み込み、試飲・予約・未処理判断・手動停止を変更しない。履歴の読み込み途中でも閉じられる。

## 製法帳と既存の予約

実際に手動で樽詰めを完了した対象から「製法を残す」を選ぶ。製法名は自動で付き、入力は不要。APIでは任意の1〜40文字の名前も扱える。製法帳には抽出位置、樽種と元の樽・仕込み・操作位置・年月・確認できた世代を保持する。同じ元の仕込みの重複登録はしない。64件まで。

蒸留室の「製法」から複数の登録を選び直せる。元の樽・発売回の比較へ進み、残した製法から結果を確認できる。元が通常の表示記録から省かれても、登録済みの抽出位置・樽種・安定した元IDは残る。未登録の手動仕込み一覧は50件ずつ表示する。

選んだ製法は既存の「次の一樽を任せる」で予約時に抽出位置と樽種だけを固定する。熟成期間・価格は指示へ含めない。費用・開始条件・進行は既存のまま。後から別の製法を選んでも、既に予約／実行中の内容は変わらない。新しい手動仕込みは従来の直近製法を更新するが、製法帳とその選択を上書きしない。「直近の手動仕込み」へ戻す選択もある。

手動蒸留では参照する製法を確認できるだけで、自動停止しない。同じ設定でも原酒の揺らぎや樽ごとの変化・熟成結果を完全一致させる補正は追加しない。

## 保存と再現

UI0.18は実行契約v17 `recipe-book` と保存キー `sukimastock.ambertime.wholesale.v17` を使う。v16以下を元の規則で厳密復元してから `enable-recipe-book` の記録された境界で追加する。旧原文は旧キーに残し、`v0171.html` は0.17.1のアプリ／CSSの固定コピーを使う。v17を旧版へ逆変換しない。

永続化する追加情報は `recipeBook.entries` と `selectedId`。全仕込み・全販売を保存する新しい台帳は作らない。製法IDは元の樽に基づき、操作帳のsave／selectで厳密再生する。世代をまたいでも資産・契約・銘柄・製法帳を保つ。抽出途中の操作位置も既存方式で保存し、架空の過去設定を補完しない。

再生中だけの手動fill索引を、既存の検証用チェックポイントと共に一時保持する。cold再生中の製法保存はこの索引を使い、保存操作のたびに再帰的な全履歴再生をしない。既存のJSON一致検証・数値検証・旧操作の意味は緩めない。

## 長期比較の処理

初期の選択肢と現在確認できる値は直接表示し、詳細は専用Workerで同じ操作を再生する。継続用トークンはモジュール内のWeakMapへ保存し、内部状態を外へ渡さない。seed・origin・操作列の完全一致する接頭辞だけを継続し、別シードや途中から異なる履歴では最初から作る。観測コールバックへ渡す事実はコピーする。

一度集計した同じ履歴では再生を省き、新しい操作が加わった場合は追加部分だけを反映する。比較のキャッシュは保存データではない。初回の長期再生が軽くなる仕組みとは区別し、実測を下記へ記録する。通常の製法保存は、起動時や直前保存時に検証済みの索引を利用する。

## 検証結果

Node全525テスト成功、失敗0（約113.5秒）。既存503件に製法帳11件・比較11件を追加した。手動元の正確さ、自動仕込みの登録拒否、直近／選択／予約の分離、抽出途中の操作、改ざん拒否、旧版と同じ操作の風味・費用・販売・世代結果、表示帳から省かれた元の復元、64件上限を確認。自然な65発売回の検査は複数世代をまたぎ、保存・別プロセスの再読込も一致した。独立レビューと関連18件の独立実行でも阻害事項なし。

実Chromium153のPC1280×900／iPhoneサイズ390×844で22シナリオ群が成功。樽同士・発売回同士・混合、同一／異なる銘柄、販売／完売／保管、3店舗納品、実際の販売期間と価格別売上、元の詳細へ戻る操作を検査した。初回の製法保存、選択した製法による予約実行、新しい手動仕込みで登録が変わらないこと、予約内容の固定、再読込・世代交代、試飲・未処理判断・手動停止の維持、v16原文と0.17.1入口も確認した。15発売回の比較では166 DOMノードで、表示件数を増やしても全操作列をDOMへ並べていない。

画像の確認で風味欄が空だった問題を発見。原因は、`shortTaste` が要求する試飲テキストの代わりに生のprofileを渡していたこと。既存 `tasting` の文言を既存 `shortTaste` へ渡す表示修正を行い、化学計算・表現辞書・保存内容は変更していない。修正後はPC・iPhone幅の追加4検証群が成功し、正規の風味文言が空欄なく表示されることを確認。基本22群と修正後4群はソースハッシュを分けて保存した。横はみ出し・ページエラーはなし。実機Safariは未確認。

120年の実操作による旧v16保存（シード1、既存の記録済みハッシュと一致）を厳密復元し、v17へ移行した。これは120年全体をv17で新しく遊んだという主張ではない。4回の世代交代を経た五代目、3銘柄・9取扱関係・163発売回・343納品・70採用を引き継ぎ、現在の短い瓶詰め記録／樽archiveに残らない初代の手動仕込み2件を製法へ登録・選択した。その後、新版で実際に1か月進め、旧版と同じ月次結果を確認した。

比較対象は4樽と252瓶詰め商品（163発売回・89卸売）、手動元256件。原酒と全販路を重複せず接続し、10,860本・総売上£204,769.81が既存累計と一致した。各商品の在庫＋全販路の販売、実価格別の自家販売本数と売上も一致。短期の3価格期間では、差分更新と最初からの再構成が完全一致した。

## 再実行

```sh
cd works/ambertime
npm test
cd ../..
node works/ambertime/tests/comparison-simulate.mjs
node works/ambertime/tests/comparison-browser.mjs
```

ブラウザはPlaywrightとChromiumを使い、実行ファイルは `AMBERTIME_CHROME` で指定できる。ブラウザ用の状態はChromium内の公開操作で作り、厳密再現を通す。実機iPhone Safari・人間の読みやすさと採否は未確認。異なる実行環境間の既存浮動小数点差は今回の修正対象外で、保存検証の許容幅を広げない。

本編の化学計算・経済・評判・店舗条件・最大4樽・世代交代の時期と条件、Production、共有runtimeは変更しない。雇用・職員能力・取扱店コメント・再注文・試験蒸留・新原料・ブレンドは対象外。表現監査6点を確認し、操作名と実際の記録に限定する。正式verificationStateは既存運用どおりUNVERIFIEDを維持する。
