## 操作と記録

瓶詰めは直近の発売回の銘柄を初期選択する。瓶詰め月が同じなら発売台帳で後の回を使い、銘柄IDの大小は見ない。初回は新規銘柄。新規の名前・丸瓶/細瓶・生成り/墨色の下書きは、既存銘柄へ切り替えて戻っても保持する。既存銘柄の名前と見た目は引き継ぐ。

帳面の既存「銘柄と発売の記録」に発売回数、累計販売本数、完売回数、累計売上、現在販売中の在庫を追加する。集計は永続する `releases` だけを使う。商品棚と完成記録は同じ売上の写しなので合算しない。売上はペンス単位で集計する。未陳列の瓶は販売中在庫へ含めない。完売後や商品棚・完成記録の整理後も、銘柄と発売実績が残る。

## 評判と需要

販売本数を S、各発売回について `min(1,販売本数/30)` を足した実売回換算を C とする。

`補正 = 0.15 × S/(S+300) × (0.75 + 0.25 × C/(C+4))`

実売のない発売回はSにもCにも寄与しない。1本だけ売れた発売回を大量に作っても、30本売れた1回と同じ本数あたりの寄与になる。発売回数、瓶詰め本数、倉庫・棚に置いた本数だけで評判は増えない。単一発売回の大量販売だけでも実売に応じて育ち、実際に繰り返し売った履歴は控えめに加味される。発売日から架空の販売期間を推定しない。

| 実績例 | 需要補正 |
| --- | ---: |
| 未販売 | 0% |
| 50本・1回 | 約1.71% |
| 250本・5回 | 約6.06% |
| 500本・10回 | 約8.71% |
| 1,000本・20回 | 約11.06% |

補正は有限の実績では15%未満。価格・熟成・風味の従来需要へ掛け、その後に従来の在庫上限、月24人の共通来客枠、整数への配分を適用する。新規銘柄の基本需要も価格も変えない。価格の自動上昇はない。

各発売回の販売補正には、その銘柄の**先行発売回**で実際に売れた本数だけを使う。自分の発売回の売上や、後から出た発売回の売上で自分の需要を増幅しない。先行発売回の販売が続いていれば、その実売は後続発売回へ反映する。

表示は「まだ知られていない」「少しずつ知られている」「馴染みのある銘柄になってきた」の3つ。補正値、経験値バー、通知、レベル演出は画面に追加しない。

## 限界と戻し方

整数販売なので、生の需要補正15%が月ごとの販売本数の増加率15%を保証するものではない。例えば若い原酒の低い需要が丸めの境界を越えると3本/月から4本/月になる。従来の配分方式を変更せず、この差を計測結果に含める。需要補正だけで売り切れや経営の成功は保証しない。

物理iPhone/Safariと作者による楽しさ・愛着の採否は未確認。既存の実行環境間の浮動小数点差は本変更の対象外で、保存の一致判定を緩めていない。正式なfinal VERIFIEDは既存契約に従い保留。実装SHAに対するScope → Risk → Impactと、GitHubのPlan Risk Gate / trusted-mechanical-evidence / Release Validatorは通過した。

戻す場合は入口を `v011.html` 相当に戻す。v8/v9の保存と読取コードを保持し、保存を削除しない。名称・入口・探索状態は変えていないため、LABの既存の試作作業台への接続をそのまま使う。
