## D. 瓶詰め

C：貯蔵庫の樽詳細BOTTLE→`BottlingScene:onEnter`3255–3319。`draw`3444–3544は左に同じ樽、矢印、右に完成瓶3本と動くベルトを配置。設定に応じた瓶・ラベル・包装のプレビューがある。本数・費用・PROFITは3320–3349/3631–3641、価格5tierとデザインは3642–3681、CANCEL/FINISH→CONFIRM?/YES/NOは3682–3710。

`confirmBottling`3350–3443は費用支払、商品在庫追加、**瓶詰めを収入ゼロの生産費として記録**し、樽をEMPTYへ戻して貯蔵庫へ移動する。樽を在庫から消す処理ではない。

H：実行前から「この樽がこの瓶になる」と見せる点は採用価値がある。一方、価格・包装・見込利益まで同じ窓に入り、FINISH後も汎用YES/NOが重なる。PROFITは全数×価格−瓶詰め費で、売れ行き・全製造費・維持費を含む保証利益ではない。ベルトの動作は確定前にもあるため、確定後の移送演出と同一視しない。

P：本数/費用/瓶詰め後資金/待つ費用だけを一つの確認にし、価格判断は販売室へ移す。0.5の確定後の短い受け渡しと完成記録を維持する。空樽再利用は経営費用を変えるため今回は採否保留。

## E. 共通UI・通知・時間

C：`SceneManager`630–777は場所切替とモーダル積層、最上位優先の入力を持つ。`PopupManager`241–345/443–568はTOP/TICKER/MODALの3レーン、重要度、通常通知のまとめ、150件の履歴。ティッカーから `LogModal`18522–18594を開き、新しい順/ALL・IMPORTANT/3件ずつのページで見る。

C：`Main.draw`2712–2777ではmodalStackまたは重要TOP/PopupModalがあるとGAME更新停止、UI更新は続く。通常通知すべてが止めるわけではないが、重要通知も止め得る。時間ボタン6347–6446はPAUSE→PLAY→FASTの循環で、現在状態でなく「次の操作」をアイコン表示。`TimeFlowSystem:step`2317–2344は一フレーム最大1か月。

H：通知の重要度と履歴への退避は有用。しかし「ニュースを見る」と「意思決定する」が同じ停止効果になりやすく、アイコンだけの循環は現在の速度を読みにくい。P：状態と操作を別表示し、判断だけ停止。重要だが判断不要なら短い通知で済ませる。

### 旧版の並行処理をそのまま採用しない理由

C：`GameMonthRunner:advance`5560–5673は共有月次で蒸留ジョブ、画面側更新、経営、維持費、保存を呼ぶ。ただし樽熟成/販売は `SCENE:autoAdvanceMonth` へ依存する箇所がある。貯蔵庫では7727–7771が熟成と販売、商品棚では16291–16302が販売、蒸留室には対応メソッドがない。

`CASK_ADVANCED`は初期Features2519–2527にも有効化代入にも確認できず、任意のadvanced更新13979–14023はACTIVE、通常樽はFILLEDを判定する。したがって**「必ず二重熟成する」とも「どの部屋でも全施設が更新される」とも断言しない**。画面依存を残したまま旧版を並行処理の完成形として移植しない。

### 自由な試飲の出典を分ける

C：今回のCodea原典では `CaskDetailsModal:getTastingNotes` 等の味メモは確認できるが、任意試飲の前回スナップショット比較・保存経路は確認できなかった。販促のGrassroots Tastingは20本消費の別物。ユーザーの旧体験を否定せず、今回確認できた資料の範囲として明記する。0.4の自由な試飲・履歴比較はWeb実装で直接確認できる。

## 採否分類

| 対象 | 判断 | 理由・今回の扱い |
| --- | --- | --- |
| 同じ樽/瓶の絵を一覧と詳細に使う | Codea版を採用 | 対象を見失わず詳細を退避できる |
| 情報をタップ/確認/履歴へ分ける | Codea版を採用 | 画面密度を下げても情報自体を失わない |
| 3室と共有所持品 | 組み合わせる | Codeaの場所感＋Web0.1の画面非依存の計算層 |
| 自由な試飲と前回比較 | Web版を維持 | 0.4で確認できる能動的な観察。表示は樽横へ変更 |
| 抽出を止める儀式 | Web版を維持 | 0.5の操作が原酒の量/個性に実際に残る |
| 瓶詰め・価格・完成記録 | 組み合わせる | Codeaの樽→瓶の関係、0.5の段階分離と余韻 |
| 時間状態・停止の所有権 | 作り直す | 循環アイコン、画面依存、相互排他clockを統一 |
| 全体phaseと樽別判断 | 作り直す | 複数樽へ単純複製すると月次が重複する |
| 文字なしアイコン・左右矢印 | 作り直す | 短い部屋名と操作名を併記する |
| 通知の3レーン | 組み合わせる | 重要度の発想を使い、判断不要の通知では停止しない |
| 原料/工程/試験蒸留・瓶形設定 | 保留 | 分類の工夫は学ぶが、現行の一操作を増やす理由がない |
| 研究/バー/輸出/設備/ミッション | 保留 | 今回の並行する小さな蒸留所に必要ではない |

結論は「旧版全体が既に正しかった」ではない。**情報を階層化していた事実は確認できた。一方、発見性・窓の収まり・月次の独立性には再設計の余地がある。**
