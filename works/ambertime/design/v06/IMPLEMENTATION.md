# 0.6 実装1 — 月次基盤と樽横の試飲

2026-10-15。PR #398 のロードマップ1・2のみ。通常プレイはまだ一樽、3室と複数樽の操作・新保存形式は次段階。

## 変更

- `monthly.mjs` の `advanceCoreMonth(core, expectedMonth)` が共有月次処理を一度だけ実行。現在の蒸留所もこの境界を利用。対象月の違う古い要求は更新前に拒否する。
- `advanceMonthly({core, notesById}, {expectedMonth, paused})` は二樽以上の熟成・既存商品の販売を一括更新後、各樽の節目だけを観察する。部屋は入力に不要。判断は樽ID順で保持。試飲・未解決判断中は全体停止。終了判定で自動瓶詰めや追加月次処理を呼ばない。
- この樽別記録は**基盤検証用の一時状態**。通常保存への追加・移行はしていない。既存の陳列済み商品が対象。未陳列商品の並行管理はロードマップ3。
- 試飲は樽と同じオブジェクト領域に表示。樽を縮める旧試飲スタイルを置き換え、現在3項目と前回との差を短く表示。香りの減少・木の増加も省かない。元の風味全文と試飲年月は帳面、完成後は従来の一本の記録へ残す。
- 試飲開始で時計を停止し、終了は直前の手動停止状態を尊重する。非表示・再開後は停止を維持。タイマー世代番号で、取消済みコールバックが試飲終了後に実行されても余計な一月を進めない。

## 保存と数値

保存キー、version、経済・熟成パラメータ、販売モデルは維持。旧版の入口も維持。元の `tickCharacter` の既定終了動作は旧版の再現用に保持し、新しい並行観察でだけ判断要求へ差し替える。基準 `acff4c14e404e04bf37712c9697712f45f659520` のコードで事前生成した保存チェックポイントを `tests/fixtures/v05-checkpoints.json` に固定。途中蒸留、樽詰め、試飲、判断、瓶詰め、販売、次仕込みと0.4の早期／長期／冷却を含め、変更後も文字列一致で復元する。

## 公開後の確認（PR #399）

`c6b8dabf254a7d00f867dfdaa324d35c7bfa9975` のPages公開成功。公開Chromeで既存0.5保存（£6,609、2029年6月、仕込み2、試飲・冷却履歴）を0.6で復元できた。保存を使わない試遊で蒸留・樽詰め→0/3か月の自由試飲、三方向の差、帳面の全文、瓶詰め確認取消、手動停止の維持と自動再開を確認。PC1280、390×844、320×568で横溢れなし、試飲の二ボタンは高さ44px。320pxの三方向比較でもグラス・残量と重ならなかった。
