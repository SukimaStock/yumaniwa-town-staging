# AmberTime 0.16.4 — 蒸留所の歩み v0.1

販売室の「蒸留所の歩み」から、保存済みの出来事を年月順に振り返る。経過年数と年ごとの見出しを表示し、選んだ年の出来事を最大50件ずつ開く。銘柄の記録、取扱店の記録へ進み、元の年表へ戻れる。

ゲームの計算・需要・価格・条件・評判は変更していない。0.16.3のボトル詳細、保管・自家販売・順次納品を維持する。成功・失敗の評価、重要度、感情文、エンディングは追加しない。

## 既存履歴の監査

| 対象 | 既存の保存先 | 今回の復元 |
| --- | --- | --- |
| 蒸留・抽出 | 操作のstart/stop、現在のbatch、樽のbatchMonth/cut | 実際の操作を再生し、開始月と抽出完了時の製法・原酒の個性を得る。途中の抽出を完成品として記録しない |
| 樽詰め・熟成 | fill、complete-usual、樽のfilledMonth/type、熟成計算、試飲記録 | 正確な仕込み月と樽種を表示。月次の熟成進行は年表に並べない |
| 試飲・瓶詰め | sample、bottle/bottle-branded、recordsのsamples/choices | 試飲は従来の記録で確認。年表は瓶詰めと発売を代表する出来事として表示 |
| 銘柄・再発売 | brands、releases | 銘柄・発売回・商品・樽のIDを引き継ぎ、再発売は同じ瓶詰めを二重表示せず発売回を付ける |
| 自家販売 | releasesの累計sold/revenue、月次のlastMonth.sales、list操作 | list月を初売上月にしない。実際に月が進み、自家販売が発生した発売回の最初の月を復元 |
| 通常卸売・特別注文 | trade.history、records、操作履歴 | 取引開始・実出荷・特別注文の事実を復元。特別注文の出荷と達成は同じ出来事に統合 |
| 取扱店 | shop.relations、shop.deliveries | 取扱開始月、対象銘柄、納品月・本数・金額。店の記録は初回／最終納品と累計を示す |
| デパート | department.adoptions、shop.deliveries | 採用と5本納品を一つの出来事にし、企画・銘柄・対象発売回を保持 |
| 保存再生 | seed、operations、移行元origin | 既存の操作ディスパッチをそのまま使用。状態と操作列の意味を変更しない |

現在の表示用の瓶詰め記録は12件、樽archiveは24件、卸売trade.historyは120件に制限される。これらを年表の全履歴と誤認しない。操作履歴を再生することで、現在の表示帳から省かれた過去の事実も復元する。

抽出方法の表示は、原酒計算用の正規化比率ではなく、既存の「いつもの仕込み」と同じ実操作の抽出位置（例：40 / 100）を使う。

新しい永続記録は不要だった。既存操作に、今回の事実を再生するための情報がある。年表の出来事・Workerのキャッシュ・展開している年は一時データで、保存へ追加しない。保存モデルv15、保存キー、操作帳の形式、厳密なJSON検証を維持する。

## 日時・識別・重複

月操作の件数から年月を数えない。資金保護で月次が差し戻された場合も、操作が記録されるためである。再生前後の実際のmonthと、取引・樽・発売に保存された年月を使用する。

同月は操作の発生順を保つ。出来事のIDは種類と商品・樽・納品・注文等の安定IDから作る。瓶詰め／再発売、デパート採用／納品、特別注文出荷／達成を重複登録しない。保存済みレコードによる補完も同じIDで統合する。

取扱店の画面には銘柄別の取扱開始、初回・最終納品、回数・本数・金額を表示する。納品が途切れた期間を連続取引とみなしたり、関係を好感度に換算したりしない。

## 旧保存の範囲

現在の操作列が始まる前に旧版のoriginがある場合、その境界以前の原保存の操作再生には今回拡張しない。残存する日時付きの瓶詰め・樽・取引等だけを補完し、画面に記録範囲の制約を表示する。

累計売上から最初に売れた月を推定しない。古い累計販売がある商品の後の売上を「初めて」と表示しない。仕込み年月を熟成年数から逆算せず、熟成後の風味を仕込み時の風味として補完しない。「初めての蒸留」は移行元のない完全な再生範囲に限る。保存にない日時・個性は不明のままとする。

旧保存を年表用に書き換える移行はない。完売・商品削除後も発売回や納品の事実を再生でき、元の銘柄・発売回・樽・店・デパート選考のIDを維持する。

## 表示と負荷

年表の復元は専用Workerで行い、画面のメイン処理へ再生を載せない。読込中も閉じられ、閉じた後の応答は画面を開き直さない。ゲームが変わらず再度開いた場合は、seed・移行元・操作列の完全一致で一時結果を再利用する。失敗は歩みの表示内で知らせ、保存やゲーム進行を停止するエラーへ変換しない。

初期表示は年の見出しだけ。全イベントをDOMへ展開せず、一度に選んだ年の50件までを表示する。表示から省かれた古い出来事も操作帳から削除しない。閉じると通常のモーダル管理へ戻り、自動進行・手動停止・待機中の樽判断や申し出を維持する。

## 再実行

```sh
cd works/ambertime
npm test
cd ../..
node works/ambertime/tests/history-simulate.mjs
node works/ambertime/tests/history-browser.mjs
```

ブラウザ検証はPlaywrightとChromiumを使用し、`AMBERTIME_CHROME` で実行ファイルを指定できる。スクリーンショットの日本語フォントは検証環境に設定し、配布するフォントや画像素材は追加しない。

## 保存上限

既存の上限は操作12,000件、銘柄128、発売回512、店舗納品2,048件。保存復元の長さ制限は6,016,384 UTF-16コード単位未満で、UTF-8バイト数とは異なる。localStorageの容量はブラウザや環境の制限も受ける。

今回の表示機能による保存項目の増加は0。上限を引き上げず、古い操作も削除しない。上限到達後も同じ蒸留所で無制限に続けられることは保証しない。将来は、厳密な再生・旧版読込・履歴を保つチェックポイント方式を別途設計する必要がある。自動の履歴切捨ては今回導入しない。

## 検証結果

全Nodeテスト484件成功、失敗0（履歴の追加10件を含む）。追加分では実売上月、熟成前後の個性の区別、樽・発売回・店舗の識別、完売後の再発売、同月の順序、限定採用・特別注文の重複防止、いつもの仕込み、旧版範囲、書込みのない閲覧、別プロセスの復元を確認した。月次操作306回に対し実経過305か月となる資金差戻しの実例でも、日時を誤って進めなかった。独立レビューと履歴10テストの独立実行でも阻害事項なし。

公開操作で10年・20年・40年の保存を作った。3銘柄の再発売、酒店・スーパー・デパート、通常卸売、特別注文を含む。

| 実経過 | 10年 | 20年 | 40年 |
| --- | ---: | ---: | ---: |
| 操作数 | 332 | 615 | 1,193 |
| 発売回 | 22 | 35 | 61 |
| 店舗納品 | 23回 | 52回 | 113回 |
| 年表の事実 | 134件 | 246件 | 479件 |
| 元保存のUTF-8量 | 99,416 B | 140,148 B | 202,151 B |
| 元保存のUTF-16コード単位 | 79,082 | 114,330 | 175,919 |
| Nodeでの初回復元集計 | 1.73秒 | 5.12秒 | 13.96秒 |

40年時点でデパート採用21件、特別注文の受注8件・出荷4件を確認。10年・20年の全出来事のID・種類・年月は40年時点でも保持され、年表生成前後の保存文字列は完全一致。別のNodeプロセスで保存と年表JSONを厳密再現し、閲覧後の481か月目にも進めた。蒸留・熟成・価格・需要・評判に関する7ソースのハッシュは基準版と一致した。これは1シード・固定製造販売方針の観測値で、全戦略の寿命保証ではない。

実ChromiumでPC1280×900／iPhoneサイズ390×844の12シナリオ群が成功。年月・同月順序・銘柄と店への移動・保存原文不変・再読込・自動進行と手動停止・樽判断と申し出の優先を確認した。40年の初期DOMは年の見出し40件、イベント行0件。展開する年だけを描画し、年の展開は28／29msだった。

初回復元の計算時間は長い。Workerで画面の処理から分離し、途中で閉じられるようにした。操作列が同じならキャッシュを使う。ブラウザの40年集計と初期表示は13.19／12.84秒、同じ履歴の再表示は97／105ms、読込中に閉じる操作は44／44msだった。操作列が更新されると再集計が必要になる。実機の待ち時間を保証する測定ではなく、ブラウザでの実測は `browser/browser-results.json` に記録する。

Nodeで生成した40年の保存をChromiumに移す追加検証で、既存の熟成計算によるroughnessの微小差3件（約2.8〜6.4×10^-16）が厳密復元を妨げることを確認した。該当計算と復元処理は基準版から変更していない。検証を緩めたり保存を書き換えたりせず、ブラウザ検証には同じ公開操作をChromium内で実行して厳密復元を通した保存を使う。異なる実行環境間の保存移送の制約として `browser/cross-runtime-diagnostic.json` に残す。この数値計算の互換性修正は今回の範囲外。

長期結果は `long-checkpoints.csv`、`long-results.json`、`long-notes.md`。実機iPhone Safariでの操作感と作者による採否は未確認。正式なverificationStateは既存運用どおりUNVERIFIEDとし、実際に観測した検査結果のみを報告する。Productionは変更しない。
