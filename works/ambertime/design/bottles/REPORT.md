# AmberTime 0.16.3 — 瓶詰め・販売室

瓶詰めを確定すると、完成した発売回のボトル詳細を開く。自家販売を始めずに保管でき、取扱関係と条件が整っている店へ、その場で納品できる。同じ詳細のまま別の店へ届け、残りを自家販売することもできる。

販売室は発売回ごとのボトル、銘柄名、熟成期間、残数、販売状態に絞った。価格・店舗条件・納品操作はボトルを押して開く共通詳細へ置く。既存の形状・ラベルを使用し、新しい画像素材は追加していない。

## 状態と納品

既存の `productsById[id].listed` を使う。false が保管中、true が販売中。重複する状態や保管操作の保存項目は追加しない。「手元に保管する」「あとで決める」は、販売を始めず詳細を閉じる。再読込や月次ごとに価格決定を強制しない。

保管中は既存の月次自家販売の対象外。瓶内で熟成せず、後から価格を選び自家販売を開始できる。販売開始後の停止機能は追加しない。納品は両状態で同じ在庫を引き渡し、その都度在庫・現金・納品売上を一度だけ更新する。自家販売の実績には加算しない。

酒店・スーパーの条件・買取価格・月間上限は維持。デパートは0.16.2の特選ウイスキーの相談・選考ID・5本で完了する仕組みを維持し、相談がない場合は納品できない。保管中であることだけを受入不可の理由から除いた。申し出に必要な実際の自家販売実績は引き続き必要で、瓶詰めだけで40本・2発売回の条件を満たすことはない。

瓶詰め後の詳細は完成した商品IDを明示して開く。ほかの樽判断が残っていても、ボトルの配分はその判断を消さずに実行できる。試飲・通常卸売の申し出の優先は維持する。詳細を閉じると残る樽判断・申し出へ進み、手動停止の意図を保持する。保管在庫も時間進行の対象となる作業として扱い、保管していることだけを理由に時計を止めない。従来の資金保護による停止と商品・樽の容量制限は維持する。

## 保存互換性

保存モデルv15 / `bottle-storage`、画面の保存キーは `sukimastock.ambertime.wholesale.v15`。旧版を厳密に復元してから、進行途中の蒸留も含む `enable-bottle-storage` 操作で境界を記録する。v14以前の操作は元の意味で再現し、新しい納品の意味を過去に適用しない。JSON一致の検証を緩めていない。

旧版で販売中の商品は販売中のまま。価格・残数・銘柄・発売回・取扱関係・納品履歴・デパート相談と採用履歴を維持する。移行時に旧キーの原文を書き換えない。`v0162.html` から旧画面を開ける。アーカイブしたUI/CSSは基準版とバイト一致し、旧画面は自身のv14保存を使用する。v15から旧版へ逆変換はしない。

## 再実行

```sh
cd works/ambertime
npm test
node tests/bottle-simulate.mjs
node tests/bottle-browser.mjs
```

ブラウザ検証はPlaywrightとChromiumを使用し、`AMBERTIME_CHROME` で実行ファイルを指定できる。検証用の保存は公開操作から作り、厳密な復元を通してから使用する。

## 検証結果

既存Nodeテスト458件と追加テスト16件が成功、失敗0。追加分は保管中の6か月維持、保管→複数店→自家販売、月間上限と在庫不足、相談なしのデパート拒否、限定5本の完了、発売回識別、旧版移行、途中蒸留・いつもの仕込み、別プロセスを含む厳密な再生、別の樽の判断保持を確認した。

実ChromiumでPC1280×900／iPhoneサイズ390×844の10シナリオ群が成功。瓶詰め直後に完成した商品を表示し、残る3樽の判断を保持した。保管だけ・樽なしでも通常の時計は進み、手動停止は維持。酒店→スーパー→デパートの順次納品で同じ詳細と在庫・入金額を確認。相談の後回し・承諾後の元ボトルへの復帰、再読込、旧v14原文と旧版入口も確認した。横はみ出し・ページエラーなし。画像4枚を目視確認し、追加の説明カード・副題・装飾は置いていない。
