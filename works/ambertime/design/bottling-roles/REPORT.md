# AmberTime 0.22.3 — 瓶詰め委任の役割整理

基準main: `2483b6ef27ffcf0108ffddcc602eef61164233da`（PR #544）。AGENTS、Change OS、表現監査、PR #544と関連Planを確認。Stagingのみ。経済・需要・価格・給与・蒸発等の係数、世代交代、月次工程の順序は変更しない。

## 実装

- **在庫連動**は販売中の全発売回の在庫合計で判定する。保管中は除外。販売・発送後の月末に各予約の閾値以下なら補充を試みる。今月末に新しく販売中にした瓶も在庫に含むが、販売・発送は従来どおり翌月から。
- 委任した順番を保存する。毎月先頭から確認し、停止中を飛ばし、実行できない候補には理由を残して次へ進む。在庫連動で1樽が成功したら、その月は他の樽から補充しない。最初の樽が毎回実行可能ならその樽を優先する方式で、輪番ではない。
- 停止・再開では順番を保持し、取消後の再委任は末尾に置く。使える原酒がなくなった樽は完了扱いとし、給与・瓶詰め費用を払わず対象から外す。過去の履歴は削除しない。
- **時期指定**は指定月齢以降の一度だけ。残量が指定本数未満なら、既存の端数処理で瓶詰めできる本数まで実行して完了する。費用・給与・商品枠・判断の失敗では成功扱いにしない。
- 同月に両方式がある場合は、時期指定を先に処理する。その新しい販売在庫も見て在庫連動を判定する。「月1樽」の制限は在庫連動の補充に適用し、別途予約した時期指定を遅らせない。
- 時期指定の成功後は残樽を手動管理と表示し、時計アイコンを消す。再委任は明示操作が必要。短い速報には実本数・樽番号・残量を表示し、既存の帳面／歩みに発売記録を残す。

共通方針と前回設定は維持。新しい条件は新しい委任から適用し、既存の条件コピーを変えない。開いた樽の既存欄に現在の状態・条件・待ち理由を表示する。新しい常設パネルや確認ポップアップは追加しない。

## 再現した問題

旧版の本編APIを使い、シード42、新規ゲームから手動65/refillの3樽を用意。最初の手動1本で担当者を解放・採用し、3樽を明示的に委任した。資金・原酒を注入しない。旧保存の全文とSHA、5か月の実結果をfixtureに固定した。

| 条件 | 旧方式で確認した挙動 | 修正後 |
| --- | --- | --- |
| 閾値5本・補充1本 | 最初の月に3樽から計3本。次月に在庫0になると全予約が`armed=false`のまま停止。各樽に約30L以上残る | 在庫が閾値以下なら毎月再判定し、1樽から1回だけ補充 |
| 閾値5本・補充10本 | 最初の月に3樽から計30本、給与3回 | 蒸留所全体の在庫を見て、1樽10本だけ補充 |

停止の原因は、補充直後の親樽在庫が閾値以下だと`armed`が解除され、在庫が減っても再開しないこと。新方式はこのラッチを使わず、月ごとの在庫水準と実行済み月で制御する。旧方式は新境界より前の履歴再生に残す。5か月の補充回数は1本条件で旧`[3,0,0,0,0]`→新`[1,1,1,1,1]`、10本条件は新`[1,0,1,0,0]`。販売需要の係数を変えた結果ではない。

PR #544のコードでも、`completed`になった予約のアイコン自体は既に非表示だった。一方、時期指定で指定量に原酒が足りない場合は成功せず時計が残り、担当者画面も完了条件を継続予約のように表示していた。今回は残量での単発完了・手動表示・短い完了速報を揃えた。全ての旧アイコン残りを再現できたとは扱わない。

## 保存と検証

記録付きの`enable-bottling-roles`境界を追加。旧保存は旧ルールで厳密復元してから移行する。既存予約の条件・状態を保持し、操作履歴から委任順を復元する。履歴に割当情報がない予約だけは樽番号順を代替順にする。保存キーと既存データを削除しない。新しい保存は委任順・状態・月間補充済み記録・実績まで厳密再生する。新保存を旧readerで読む完全互換は保証しない。

- 新しい対象テスト11件、関連する既存計算・保存・月次・通知61件の計72件が成功。対象テストは `tests/bottling-roles.test.mjs` に分離。
- 対象検証は、全販売在庫／保管除外、閾値以下の補充本数での再開、委任順と停止・取消、原酒不足の候補通過、枠・資金・判断、時期指定の残量・単発完了、混合予約、費用・給与、翌月販売・発送、旧保存・冷復元・改変拒否。
- 390×844タッチ相当の実操作で、委任順3→1→2、全在庫が閾値を超えた月の補充なし、停止・取消・再委任・復元、時期指定10本の完了、残量24.2Lの速報、アイコンなし、残樽の手動瓶詰め画面を確認。各月のUI保存状態は本編モデルと一致し、pageerrorは0。別の保存値も維持。
- 独立コードレビューで旧履歴・順番・費用・残量を照合。月間枠で見送った候補に前月の失敗理由が残る点を1回修正し、使える原酒ゼロの防御処理と合わせて対象プローブが成功。
- テストの初期案で判断イベントを想定した候補は、既存の委任中観察処理によって判断待ちにならなかった。既存仕様を変えず、実際に原酒を使い終えた候補の通過へ再現条件を修正した。資金25を与える合成入力は月次ロールバックの境界検査で、成立したプレイ実績とはしない。その後の実行確認には健全な同条件の別状態を使い、資金不足から回復した履歴とは扱わない。
- 表現監査: 必要な「販売中在庫全体」「1回」と現在状態を既存UIへ表示。完了文は短縮して語の途中の折返しを回避。新しい装飾・説明パネルなし。
