# 原酒の個性を可視化する Phase 1

基準は Staging 0.13（d9fdb71）。抽出・乱数・熟成・販売・卸売・特別注文・銘柄・評判・時間進行とv10保存は変更しない。追加は読み取り専用の `spirit-view.mjs` と蒸留室の表示だけ。

## 表示の意味

抽出位置30未満は「採取中」と収量だけを示し、風味値を出さない。この間の `core.spirit` は初期化用の仮値なので参照しない。

30以降は `cut=(progress-minimumStop)/(distillMax-minimumStop)` を既存の `previewDistillation` に渡す。刺激・原酒の香りはその結果へ、仕込み開始時に決まった `still.distillation.variation` を掛け、既存停止処理と同じ `Math.min(1, value)` を使う。新たな乱数を引かず、「今止めた場合の見込み」として表示する。

固定軸は刺激 `roughness: 0..1`、原酒の香り `character: 0..1`。モデルの値をそのまま最大値で割り、仕込みごとに最小・最大を伸ばさない。色は両方とも同じ落ち着いた色。品質色・点数・星・順位・最適位置は出さない。将来の樽の香り `wood` は別の上限1.35を軸定義に持つが、今回は表示しない。これはモデル上の強さであり、百分率の成分量や品質ではない。

一言は既存 `tasting()` の刺激と香りの区分を短い自然な文へ置換する。境界を別に作らず、現在の抽出範囲で現れるのは6通り。量・刺激・香りが変わる連続性を残し、短い文だけを切り替える。

手動停止後は実際の `core.spirit` を「できた原酒」として読む。自動仕込みは停止・樽詰めが一度に行われるため、直後の新しい樽を前の原酒の `batchId` で照合し、月次の熟成前に実値だけを画面内へコピーする。「樽詰めした原酒」の表示は次の仕込みか初期化まで保持する。保存には加えない。抽出途中・樽詰め前の再読込は既存保存から表示を再計算し、再読込後の熟成済み樽から原酒の初期値を推測しない。

## 検証

`node --test works/ambertime/tests/spirit-view.test.mjs` は8シード×100位置について、最低位置前の非表示、全有効位置の実停止との完全一致、凍結状態の繰り返し読み取り、試飲文の境界、途中保存の別プロセス復元、自動仕込みと並行熟成・販売を検証する。比較原表は `position-results.json`。`node --test works/ambertime/tests/*.test.mjs` で既存回帰も確認する。

`node works/ambertime/design/spirit/browser-run.mjs` はPC1280px、iPhone相当390×844/667pxで、実際の100msタイマーによる抽出、停止、樽選択、途中再読込、自動結果を操作する。ページ内メモリを使いプレイヤー保存へ書き込まない。ゲージが現れる29→30と文の折返しで停止ボタンが動かないよう表示領域を確保する。既存の抽出バーは隠し、蒸留器の採取量の変化と2本の風味ゲージに役割を分ける。確定・自動の表示と見込みの見出しを区別する。

実機iPhone Safariと指での触感・作者の採用判断は未確認。LABは既存の試作作業台を維持し、Productionは変更しない。Change Verificationのfinal/automatic VERIFIEDは保留のまま。

## Phase 2の前に

現行式では抽出位置を進めると刺激・香り・量が一緒に増える。まず今回の表示で、穏やかさと強い香りの間を選ぶことに愛着が生まれるかを実際に触って確認する。独立した風味の選択肢や品質スコアは先行追加しない。熟成との比較へ進む際は、同じ単位と木の香りの0..1.35を維持し、原酒の記憶をどう見せるかもその時点で判断する。

最終実行では全336件合格。ブラウザはPC1280×900と390×844/667の3条件すべて成功した。最低位置29→30および一言の折返しで停止ボタンの位置は安定（PCの初回差は0.2px未満、通常30〜90では同位置）。667px高でも通常の停止ボタン全体が初期視界に入る。99の既存「抽出いっぱい」通知による行追加は従来どおりで、短い画面では樽詰めボタンへ少しスクロールする。

PCの追加境界では、自動完了と月次が同じ100msコールバックに重なり、新生樽が即座に1か月となる場合を操作した。表示が熟成後の数値でなく樽詰め時の実値に一致することを確認した。独立レビューに未解決の指摘はない。
