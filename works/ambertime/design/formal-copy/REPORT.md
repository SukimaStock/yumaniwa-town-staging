# AmberTime — 文言整理と配分版の正式採用

基準: Staging main `016021139581be2f27f367e1f082fc49c01d4445`（#641）。対象は `works/ambertime/` の現在の本編。通常URLと `?placement=1` を同じ正式版へ接続する。Production、旧版・既存Labは変更しない。

## 文言

[承認項目の照合表](approved-copy.json)に21回・103項目を記録した。複数語をまとめた承認項目を個別文字列に展開すると106変更。制作前の表現監査、実装後の独立照合で画面ごとの対象を確認した。

- 蒸留室の選択は「ふつう／ピート」「短め／長め」「蒸留」。見出しのある選択画面だけを短くし、製法の記録に使うカードの正式名は保持。
- たる棚だけ「No.○」。詳細は「かおり」「シゲキ」「詳細」。バー下の強さの文章だけを除き、バーと読み上げ値は保持。試飲の短い味の文章は残す。
- ビン詰めの重複本数を除き、「残り ○L」「ビン詰め後 £○」。配分は「希望 ○本」。瓶棚の名前・本数・発売回は保持。
- 申し出は「受ける／あとで／断る」。町の酒店は「自分で届ける」「希望／納品」。スーパーなどの「注文／発送」と区別し、町の酒店に旧自動発送の案内・注文結果を表示しない。過去の実績は削除しない。
- 担当者は「依頼／設定」「1回」「共通設定」「本数」「保存」「次の予約から」。帳面は「仕込み／たる／発売／取扱店」、詳細・歩みの固定見出しも承認表どおり短縮。
- 資金・ビン詰め済み・元のたるを同用途で統一。「保存済み」は保存状態だけ。「保存しました」は操作通知として保持。重要な保存エラーの理由と対処は短縮しない。

保存済み本文、名前、味の説明、店の台詞、歴史の本文は一括置換しない。既存の `ui-text.mjs` は未変更。変更は固定UI文字列と表示専用の理由変換に限定した。

## 配分版と保存の引きつぎ

通常URLから配分操作を使う。重複していた旧自家販売の選択・販売開始UIを商品小窓から除いた。価格、元の記録、比較、申し出、自動発送店・デパートへの既存導線は残す。

正式保存先は `sukimastock.ambertime.main.v1`。元の通常版 `sukimastock.ambertime.wholesale.v20` と配分版 `sukimastock.ambertime.placement-trial.v1` は読み取り元として残し、書き換えない。

1. 正式保存があれば、それだけを厳密に読む。破損していても旧保存へ黙って切り替えず、書き出し・再読み込みを案内する。
2. 正式保存がなく旧記録があれば「記録を選ぶ」。日付・資金・本数を示し、選択前は確定を無効にする。両方ある場合も自動選択・合成しない。開けない記録も書き出せる。
3. 旧通常版では、販売中の未販売分を「自家販売へ／手元へ」から選ぶ。デパートの確保分は利用可能数から除外する。既存配分版は配分を変更せず原文をコピーする。
4. 候補を検証し、元記録とコピー先の競合を再確認してから保存する。保存確認に成功するまで本編を切り替えない。失敗時は元記録を保ち、成功扱いにしない。
5. 元記録がない新規開始と、選択画面で明示した「新しく始める」だけが新しい記録を作る。旧記録を初期化しない。

本体version20・セッションversion2を維持。stage4導入済みの旧通常版は、既存の全事実と操作記録の接頭部分を維持し、方式の境界を示す `adopt-placement` を1件追加する。stage4導入前の保存は、従来の `enableStage4` によるアップグレード後に `adopt-placement` を1件追加する。`adopt-placement` 自体は月次・資金・世代・町を進めない専用処理とした。試飲中・蒸留途中の状態も冷間再生で維持する。既存配分版は操作を追加しない。地図の旧UI履歴v1/v2は選んだ元記録から互換コピーする。
