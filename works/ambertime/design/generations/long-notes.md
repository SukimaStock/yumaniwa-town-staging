# 世代継承の長期検証

再実行: リポジトリのルートから `node works/ambertime/tests/generation-simulate.mjs`。最初に旧版40年の候補比較を再計算し、新版のシード1・2をそれぞれ1440か月（120年）進める。`AMBER_SKIP_COMPARISON=1` で既に確認した候補比較を省略、`AMBER_SEEDS=1` でシードを限定、`AMBER_MONTHS=1440` で検証期間、`AMBER_OUT=/absolute/path` で出力先を指定できる。`AMBER_GENERATION_SAVE_DIR=/tmp/ambertime-generations` を指定した場合だけ、ブラウザ等に渡す一時保存を作る。保存そのものはコミットしない。

公開操作だけでプレイし、所持金・在庫・樽・履歴を注入しない。抽出40/65/90別の3銘柄を継続し、最初の36か月は2樽・6か月熟成、その後4樽・12/24/36/24か月熟成。バーボンとリフィルを交互に使い、3回に1回は発売後6か月間保管する。自家販売は標準価格。酒店・スーパー・デパートと取引し、港の仕入れ店の通常卸売・特別注文を受ける。条件未達の特別注文は通常卸売へ回す。

世代の区切りが確定したら通知を確認し、通常の空きができた時に一度だけ手動で仕込む。その樽詰め後、同じ世代IDを指定して引き継ぐ。既存の樽を強制処分せず、費用・品質・需要・販売条件を変えない。手動の最後の仕込みを自動予約や以前の仕込みで代用しない。

毎月、最大4樽、在庫非負、商品の元在庫＝残在庫＋販売本数、現金＝初期資金＋売上−費用−維持費を検査する。各継承ではcore・銘柄・発売回・取扱関係・納品・採用・契約・いつもの仕込み・蒸留中状態のJSONが継承直前と完全一致する。最後の樽がある場合、手動開始が一度だけであること、樽IDが他世代と重複しないこと、継承時期が確定から12か月を超えないことを確認する。樽が残っているか、実際の瓶詰め／出荷を観測した後であることも確認する。

両シードの最終保存は独立したNodeプロセスで厳密復元し、元の文字列と比較する。UTF-8入力は明示して読み取る。最初のシードだけ最終の歩みを一度再構成し、日時・ID重複・保存を書き換えないことを確認する。毎月の進行に重い履歴再構成を混ぜない。

この検証は一つの製造・配分方針を2シードで繰り返すもの。自動予約の進行中、満樽のままの猶予終了、出来事がない期限到達、資金不足、途中の保存は別の状態境界テストを参照する。人間の愛着、区切りの適切さ、最後の仕込みの操作感は自動検証だけでは判断しない。

保存量はUTF-16コード単位とUTF-8・UTF-16バイト換算を分けて記録する。復元上限は6,016,384コード単位未満で、ブラウザのlocalStorage容量とは別。操作12,000件・発売回512件・店舗納品2,048件などの既存上限は引き上げない。120年到達はこの検証の観測結果であり、全方針や無制限の継続を保証しない。時間は共有環境の単発測定で端末性能の保証ではない。

## 実測結果

両シードが120年に到達し、4回の継承を経て5代目が活動中となった。8回の最後の仕込みはすべて実際に一度だけ手動で始め、樽詰めまで行った。区切りの確定から継承までの待ちはシード1が0/1/1/7か月、シード2が4/0/1/1か月。自然に空きができるのを待つ場合も、既存の樽や契約を捨てず12か月以内に引き継いだ。

| 120年時点 | シード1 | シード2 |
| --- | ---: | ---: |
| 継承月 | 300 / 605 / 909 / 1216 | 304 / 605 / 906 / 1209 |
| 銘柄／取扱関係 | 3／9 | 3／9 |
| 発売回 | 163 | 166 |
| 店舗納品 | 343回 | 345回 |
| デパート限定採用 | 70回 | 70回 |
| 卸売出荷／成立した特別注文 | 89／12 | 83／12 |
| 現金 | 60,213.81 | 61,416.12 |
| 操作履歴 | 3,486 | 3,483 |
| 保存UTF-16コード単位 | 395,500 | 397,431 |
| 保存UTF-8バイト数 | 424,712 | 426,829 |
| 保存UTF-16バイト換算 | 791,000 | 794,862 |
| 独立プロセスの厳密復元 | 84.90秒 | 83.43秒 |

同じ3銘柄・9取扱関係を保ち、引継ぎの前後で財産と進行中の状態は完全一致した。現金・在庫・売上の月次検査、8回の最後の仕込みのIDと来歴、独立プロセスでの保存文字列の厳密一致はすべて成功した。シード1の最終の歩みは1,390件で、再構成後も保存は一致し、未来の日付と重複IDはなかった。

残る上限は、操作8,514／8,517件、発売回349／346件、店舗納品1,705／1,703件。復元の文字数上限との差は5,620,884／5,618,953コード単位。ブラウザの容量と無関係な上限値を混同せず、これを無期限プレイの保証にはしない。

120年分の完全な履歴再構成はNodeで90.17秒かかった。独立プロセスの厳密復元にも約84秒かかり、長い保存には全操作の再生コストがある。初回の公式シリアライズ検証も行ったが、その所要時間は個別計測していない。これらは共有環境での実測であり、ブラウザや実機の時間を直接表すものではない。高速化のための検証緩和、履歴削除、計算変更は加えていない。120年到達と保存再現を確認したことと、長期データの表示・読込みが軽快であることは別に評価する。
