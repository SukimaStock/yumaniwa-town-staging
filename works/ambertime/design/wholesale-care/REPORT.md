# 卸売樽の熟成判断・最小修正検証

## 再現と変更範囲

旧 v6 の `partners-accepted.json` を厳密復元し、抽出99・バーボン樽を通常卸売へ指定。6か月進めると、樽ID39・月116・熟成6か月で `rough` の `wait/cool` 判断が残った。`observePromisedChanges()` が `cool` を含む通常イベントを除外していたことを、実際の未解決キューと保存再生で確認した。

v7 の明示的な `enable-promised-care` 操作以後だけ、通常卸売樽の rough / wood / fading / fruit / rounded / loss を観察記録へ移す。pending と判断キューも解消し、架空の wait 選択は追加しない。涼しい棚への移動は樽から任意に実行し、既存の実際の冷却処理と選択記録を再利用する。特別注文、funds、last、bottle-ready、order-unmet は対象外。既存 v6 の読取・操作再生は従来のまま。

## モデル回帰

`node --test works/ambertime/tests/wholesale-care.test.mjs` の追加13ケース（先行12ケース成功、追加1ケース個別成功）。既存回帰と UI / ブラウザ検証の総数・公開SHAは PR の検証記録を参照。

- 合法な旧保存から4樽を通常卸売指定し、予定月まで通常熟成判断で停止せず出荷。
- 3樽卸売・1樽通常管理では、通常管理の樽だけ従来の熟成判断が発生。
- 4樽同月の rough/cool イベントおよび4樽同月出荷をトランザクション境界状態で検証。これは合法な開始操作履歴を主張する保存資料ではない。
- 旧 rough/cool の移行、明示的手入れ、一度だけの冷却、試飲中の停止・終了後の月次更新、取消後の通常判断復帰。
- 資金不足・特別注文未達・特別注文中の冷却判断・既存の最終瓶詰め計画を保持。
- 同じ操作の厳密保存再生、樽ごとの試飲履歴、観察記録を確認。
- 旧 v6 で各判断を wait 選択する場合と v7 の自動観察を19か月並走。`core` 全体と出荷明細が完全一致し、熟成曲線、蒸発、現金、収入、費用を変更していないことを確認。
- 帳面上限では旧状態を変更せず移行拒否。残り1枠では移行操作を1件だけ追加し、再実行は冪等。上限境界テストの仮操作列は合法な再生履歴として扱わない。

24試行すべて、現金 = 初期資金 + 累計売上 − 累計製造等費用 − 累計維持費、販売経路別の収入合計、厳密保存再生が一致。進行不能0。資金不足は無視せず、表示された対象樽を明示的に卸売解除（必要な場合）・瓶詰め・通常販売して回復した。卸売中心では6件の解除が必要で、混合では卸売解除0件。これは意図して残す経営上の判断である。

この合法な月1仕込みの方針では同月複数出荷は0件だったため、その原子処理は上記の4樽境界テストで別途確認した。特別注文未達も長期方針では生じないため、既存の合法な未達チェックポイントの厳密復元と操作テストで確認した。

数値モデルは変更しない。最終現金と未販売在庫価値は別項目として JSON に保持。自動操作の試行であり、人間の面白さ、実指の感触、実機 Safari の検証完了は主張しない。

## 保存・画面の分離

新動作は `sukimastock.ambertime.wholesale.v7` へ保存し、旧v6以下のキーは書き換えない。新画面は `wholesale-care-app.mjs`、以前の画面は変更しない `partners-app.mjs` と `v010.html` で保持する。旧データを厳密復元してから有効化操作を追加するため、過去の月次操作を新しい観察ルールで再解釈しない。新キーが壊れている場合も旧キーへ無断で巻き戻さない。旧v6の帳面に移行操作を追加できない場合は元の保存を残して停止し、旧入口を利用できる。

棚移動は既存の契約詳細で選ぶ。通常卸売で、実際に棚移動が可能な観察が記録され、他の重要判断・試飲・申し出がない場合にだけ表示する。選択するまでは熟成曲線に変化を加えない。試飲中・蒸留途中の移行、保存容量エラー、破損した新キー、手動停止保持をUI回帰6ケースと独立レビューで確認した。

PC・iPhoneサイズの実ブラウザ確認と公開SHAはPR本文へ記録する。検証ページはメモリ保存だけを使い、実際の公開操作をブラウザ内で再実行してから厳密保存する。過去に判明した実行環境間の微小な浮動小数点差は今回緩和しない。
