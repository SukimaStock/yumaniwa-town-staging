# H2-3B 後年の評判を回想候補に追加

## 採用方式

C-3を採用する。地域・種類ごとの初回を含む従来資料、各世代での最初の同種反応、保持した問い合わせ・訪問が参照する直近の表示可能な到達を残す。次の世代の評判が30年時点の3記録で選ばれ、13〜16場面で製造・取引や納品・評判・世代交代が混在した。特定地域や世代の採用枠は設けていない。

C-1は地元密着の30年で後継世代の評判が選ばれず、広域展開で17場面だった。C-2は30年の3記録に後継世代の評判が残ったものの、混合で17場面となり、各記録の候補がC-3より多かった。C現行も30年の3記録で採用されたが、候補をさらに29・28・23件増やし、広域展開では同じ地域が6場面中4場面を占めた。

## 選ばれた反応と参照の違い

表のIDは30年時点に選ばれた後継世代の評判。世代交代時点には後継世代の評判を含めていない。

| 記録 | C現行 | C-1 | C-2 | C-3 |
| --- | --- | --- | --- | --- |
| 地元密着 | `inquiry:e1628`、`visit:e1657` | なし | `inquiry:e1628` | `inquiry:e1628` |
| 広域展開 | `visit:e2317` | `visit:e2339`、`inquiry:e2435` | `inquiry:e2435` | `inquiry:e2435` |
| 混合 | `inquiry:e1765`、`arrival:e1885` | `inquiry:e1765`、`arrival:e1885` | `inquiry:e1765`、`arrival:e1885` | `inquiry:e1765`、`arrival:e1885` |

- 地元密着のC-3では、2053年10月、海外の飲食文化圏から問い合わせが届いた（`inquiry:e1628`）。初期の海外到達と同じ地域が再登場する。問い合わせの記録上の到達は同じ発売の `e1584` であり、初期の到達を原因として扱わない。海外への集中はC現行と同じ4件で、うち問い合わせと到達の両方がある。
- 広域展開のC-3では、2055年12月、町の酒店から問い合わせが届いた（`inquiry:e2435`）。参照チェーンの中間IDは根拠に残るが、このチェーンには回想候補となる口コミ到達がない。C現行で6件中4件だった全国の飲食への集中は、C-3では最多の海外でも6件中3件となった。訪問も回想に残る。
- 混合のC-3では、2052年12月、海外の飲食文化圏から問い合わせが届いた（`inquiry:e1765`）。2055年9月、町の酒店に口コミが届いた（`arrival:e1885`）。混合では同地域の最多がC現行の2件からC-3の4件に増えた。これは候補を減らしても抽選の構成が変わるためで、地域集中は全記録で改善したとはいえない。

## 順序・根拠・再現性

従来の `facts.json` はA・B・CとDの比較基準として保持する。D専用の `facts-d.json` は追加事実と、旧資料から位置が変わる行だけの圧縮前位置を持つ。新しい位置は再生から抽出した事実の並びであり、独立した内部処理の厳密な前後を示すものではない。町の記録内の順序は既存の `evidence.townOrdinal` にも残る。世代交代時点は旧資料の月・操作番号・ordinalを抽選シードに使い、表示可能範囲の判定は圧縮前位置を使う。同じシードでも候補集合が変われば選出結果は変わる。

正式保存のSHA-256と旧資料の全事実を照合した。参照チェーンは抽出時のまま保持し、チェーンで参照する表示可能な到達がある場合は候補に残す。直接到達や内部伝播はチェーン中のIDとして現れ得るが、独立した口コミ場面にはしない。24条件で同一入力の再実行、旧資料との境界とシード一致、未来の事実がないことを確認した。

## 容量と性能

従来資料426,658バイトにD専用資料35,585バイトを追加した（約8.3%増、非圧縮）。追加した評判は地元15・広域21・混合20件で、圧縮前位置の差分は40件。Nodeで100回計測したJSONの平均パース時間は従来資料が約1.92 ms、追加分が約0.21 ms。ネットワーク転送・端末の描画時間はこの値に含まれない。

| 方式 | 6条件の編集時間 | 編集前後のヒープ差 |
| --- | ---: | ---: |
| C現行 | 5.4〜10.4 ms | 4.1〜6.8 MiB |
| C-1 | 4.7〜6.8 ms | 4.8〜7.3 MiB |
| C-2 | 3.6〜5.7 ms | 4.2〜6.4 MiB |
| C-3 | 4.2〜6.2 ms | 3.6〜6.0 MiB |

各条件1回のNode計測。ヒープ差は最大使用量ではない。保存の並列再生は別計測で約17.8秒かかった。閲覧時は生成済み資料を読み込み、場面操作では保存を再生しない。

## 再実行

リポジトリルートで次を実行する。出力には24条件の全採用ID、D1.2の文章、参照チェーン、候補ID、保持理由、世代・年代・地域別の内訳を含む。保存ディレクトリを `-` とするとH0のシナリオから再生成する。`--write-d` を追加すると採用したC-3のD専用資料を書き出す。

```sh
node --expose-gc works/ambertime/chronicle-lab/research-h23b.mjs /path/to/h0-saves > /tmp/h23b.json
node --expose-gc works/ambertime/chronicle-lab/research-h23b.mjs /path/to/h0-saves --write-d > /tmp/h23b.json
```

3記録の30年資料を対象とした。複数回の世代交代を含む正式保存、長期保存の復元負荷、実機での読後感はこの比較の対象外。
