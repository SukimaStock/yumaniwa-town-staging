# H2-4 複数世代・100年回想の研究

## 方法

H2-3B（#801）の Staging main を基準に、H0の地元密着・広域展開・混合の3政策をseed 42で継続した。世代交代、出荷、瓶詰め等は正式ゲームモデルの操作を通じて起きた。各チェックポイントを正式形式で保存し、操作再生がスナップショット全体を再現することと、抽出前後で保存が同一であることを検証した。

H2-3Bの資料抽出とC-3候補保持は研究用の入口から再利用した。D1.1・D1.2は既存モジュールをそのまま呼ぶ。既存のH0政策と現行市場ルールは単一銘柄を使うため、複数銘柄間の競合は未検証。同じ銘柄で熟成年数や発売IDが異なる例を調べた。

30年時点の3保存はH0とバイト単位で一致。公開中のA/B/C/D採用ID・順序とDシードをダイジェストで固定し、再生成したDの6条件もH2-3Bの結果に一致した。公開用資料やLab画面の差分はない。

## 再実行

リポジトリルートで実行する。保存・中間JSONはscratchに作る。

```sh
lab=works/ambertime/chronicle-lab
out=/tmp/amber-h24
for id in local wide mixed; do
  node "$lab/research-h24-saves.mjs" "$id" "$out" > "$out-$id.log"
  for month in 360 720 1080 1200; do
    node --expose-gc "$lab/research-h24-facts.mjs" "$out/$id-$month.json" "$id" > "$out/$id-$month.facts.json"
    node --expose-gc "$lab/research-h24-edit.mjs" "$out/$id-$month.facts.json" > "$out/$id-$month.edit.json"
  done
  node "$lab/research-h24-saves.mjs" restore "$out/$id-1200.json"
done
node --test "$lab/research-h24.test.mjs"
```

抽出JSONには元保存のSHA-256、候補、操作再生から採った位置、世代と根拠が含まれる。編集JSONには各時点の採用順、世代・年代・種類、最大空白、選出理由と得点内訳、参照経路、同一入力での再現性検査結果を残す。オフライン抽出は既存スクリプト内の処理を呼ぶため、ソース境界が変わる場合は研究コードの再確認が必要。

## 長期でも残ったつながり

- 地元密着100年。2027年12月の町の酒店への『石蔵』初納品（`delivery:1`）から、第2世代の2057年11月（`delivery:78`）、第3世代の2088年7月（`delivery:153`）、第4世代の2123年4月（`delivery:238`）へ同じ店舗IDがつながる。
- 広域展開100年。最初の『川霧』は2026年7月の6か月熟成46本（`bottling:1`）。第4世代の2111年2月には1年熟成45本（`bottling:29`）が選ばれた。銘柄IDは同じで、発売IDと樽IDは別。町のスーパーも初納品の2030年4月（`delivery:8`）と第4世代の2118年8月（`delivery:300`）で再登場した。
- 地元密着100年。初代の2027年5月、全国の飲食のつながりに口コミが届いた（`arrival:e36`）。第4世代の2116年5月には、同じ地域で銘柄を知った人が蒸留所を訪れた（`visit:e3669`）。これは同じ地域の再登場。訪問の因果は元の参照チェーンで別に扱う。

## 読みやすさと偏り

100年でも初代の場面は多い。初回加点と、後年の候補に対応する起点の同時採用が理由になり得る。交代を挟んで後の世代の製造や納品も選ばれ、必須の世代交代だけが連続する構成はなかった。

広域展開100年では、評判6場面のうち5場面が海外の飲食文化圏に集中した。口コミ・訪問・問い合わせが混在し、別発売も含む一方、同じ地域名が繰り返される。製造5・取引6・日常3の場面も残る。第3・第4世代の『川霧』には「1年熟成45本」が3回あり、発売はそれぞれ異なるが、一文だけでは年月以外の違いが出ない。同一熟成・本数の並びは発売差が文面に現れにくい例。

D1.1は未登場の48か月区間を加点し、選出数に応じて負担を二次的に増やす。候補数に比例して場面は増えなかった。一方、時間分布は抽選に委ねるため、空白は埋まり切らない。広域展開100年は創業60〜69年の区間が空で、最長129か月。地元密着100年でも150か月空く。同一世代・店舗・銘柄の類似納品には専用の減点があるが、同じ熟成年数の瓶詰めにはこの減点を適用しない。

現在のC-3とD1.1を長期回想の基準にできる。次に調整する場合は、世代別の固定枠や場面数上限を加える前に、長い空白と類似文の実機での受け止めを確認する。境界付きの歴史再現には、先に次節の候補閉包を検証する。

## 交代の指定と、候補を切る時点

`targetGeneration` は交代イベントの所属、つまり引き継ぎ元の世代を指定する。第1回は公開Labと同じ既定呼び出し、第2・3回は引き継ぎ元の2・3を指定した。第1回を明示的に `1` で指定すると境界は同じだが、シードの世代が既定の引き継ぎ先2から1に変わる。例えば地元密着30年は既定の1951059788と明示の859827745。複数世代の導線を追加する際は、交代の選択キーとシードに使う世代を分け、公開中の既定シードを維持するのが最小の整理案。

同じ交代を30・60・90・100年の各資料から呼んだ結果も、比較できる全ケースで採用IDとシードが一致した。同一保存・時点・指定では選出が再現され、未来の事実は一度も場面に入らなかった。一方、全履歴のC-3には、未来の訪問・問い合わせが参照することで保持された境界前の口コミが含まれる。例えば広域展開の第3回交代（930か月）では、903か月の `arrival:e4721` が935か月の `visit:e4871` に、923か月の `arrival:e4808` が951か月の `visit:e4962` に参照される。当時までの記録だけで候補を閉じる独立実験では、候補669→667、場面23→22。境界・抽選シードは同じでも、候補が変わると選出は変わる。

厳密な「その時点で見えた回想」が必要になった場合は、交代境界を適用してからC-3で参照元を保持する。公開中の30年回想の候補・シードは今回の研究で固定している。独立比較は次で再現できる。

```sh
node "$lab/research-h24-facts.mjs" "$out/wide-1200.facts.json" --prefix
```
