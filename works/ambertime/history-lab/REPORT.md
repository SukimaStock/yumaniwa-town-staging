# AmberTime H0 · 蒸留所の歩み

## 比較方法

基準 main は `d07ff7ba071163de2b56ef07a2294580d312cc07`。現在の本編と同じ `newMarketRulesDistillery` を使い、seed 42 で3種類を360か月進めた。原酒の採取、樽詰め、瓶詰め、棚への配置、店の申し出、月次進行、引き継ぎを本編の公開操作で行った。販売や評判、手元資金、乱数を直接設定していない。資金と初期供給を確保するため、全例で初期に6か月熟成を使う。

地元密着型は以後36〜48か月を目安にして酒店のみ、広域展開型は12〜24か月を中心に3店、混合型は短熟と長熟を並行し、16年目から追加の店を受ける。卸売の申し出があれば辞退する方針とした。この試行では卸売履歴は空だった。単一seedの実例で、経営方針ごとの一般的な成績は推定できない。本編の現行銘柄設定の範囲では、複数銘柄への拡大よりも、同一銘柄の反復瓶詰めを検証できる。

| --- | ---: | ---: | ---: |
| 累計実売 | 505本 | 603本 | 524本 |
| 自家販売 | 432本 | 463本 | 435本 |
| 酒店への納品 | 73本 | 78本 | 77本 |

地元密着型の酒店には23〜356か月目に納品があり、初代が65本、次の世代が8本を届けた。間に最長10か月の納品空白がある。混合型は23〜358か月目まで同じ酒店に納品し、世代別では64本と13本。長い空白や長い期間は、実際の納品月から計算した値で、契約の休止や連続納品を示すものではない。

混合型では1年以下の熟成で503本、3年以上で128本を瓶詰めした。酒店は両方を扱い、スーパー7本とデパート5本は3年以上の発売分だった。

広域展開型は口コミの到達地点が最も多かった。3例とも間接到達と海外からの問い合わせがあり、地元密着型が一番早く問い合わせを受けた。現在の外部接続モデルは評判の反応を記録する。海外での契約や売上は、この3例の再生には存在しない。

## 根拠の構造

`fixtures.json` に表示対象を保存している。各タイムライン項目は `id`、発生月、世代ID、関連ID、操作番号、証拠の参照、事実文を持つ。選出理由・点数は選出用、納品期間や銘柄の継続は `interpretation` に分けた。先に決めた重みと種類ごとの上限で選び、表示は年月と同月の操作順で並べる。同じ記録は同じ順で表示する。優先したのは世代をまたぐ納品、引き継ぎ、取引開始、長期熟成、初回の出来事と新地域の到達。

- **瓶詰め**は `releases` と旧版の `records`。同じ商品は重複させず、熟成年月と本数を参照する。
- **納品**は `shop.deliveries`。棚への仮配置は含めない。現行版の月次成立では納品行と店頭の実売行が同じ取引を表すため、売上の合計には重ねて加えない。
- **実売**は各操作前後の `core.totals.bottlesSold` と `lastMonth.sales`。旧方式の月外売上は内訳不明として残す。
- **口コミ**は本編地図と同じ非直接到達。間接的に瓶が届いた地点も含む。問い合わせは `town.events` の問い合わせだけを数え、訪問や契約と分ける。
- **取引・引き継ぎ**は店の関係記録、百貨店の初納品、正式な卸売受諾、`generations.completed`。引き継ぎ時に両側で観測できる樽IDと店舗IDを保持する。後継の継続納品は別の証拠とする。
- 旧版は起点以前の記録が欠ける。残った日付つき記録は表示するが、操作番号と世代を補わない。街の連携を途中から導入したセーブは、連携以降を観測範囲とする。

## 履歴保存の監査

| データ | 現行の保持・復元 | 到達時の挙動 |
| --- | --- | --- |
| 正式操作 | 最大12,000件、末尾への追記。現行区間の再生に利用 | 上限後の新しい記録付き操作は拒否される |
| 店舗納品 | 最大2,048件。百貨店で予約した枠を含む | 新規納品の確定を制限。自家販売と月次進行には別条件が適用される |
| 卸売 | `trade.history` は120件の移動窓 | 古い行は消える。現行操作の再生中に差分を観測できる |
| 月次記録 | `lastMonth` は最新のみ。日誌120項目、商品32件、樽アーカイブ24件 | 累積実売は残る。月ごとの実績は再生して回収する |
| 発売・商品記録 | 発売512件、銘柄128件、最近の瓶詰め記録12件 | 発売上限は新規発売を制限。古い最近記録は発売台帳や操作で補う |
| 熟成観測 | 樽ごとの化学スナップショットは3か月ごと、最近12件 | 保存から長期曲線を直接読めない。操作再生の観測が必要 |
| 世代 | 再生時の実行世代と世代終了行を参照 | 移行前や世代機能導入前は世代別数量が部分的 |
| 評判 | 連携導入後の街の配列を保存。外部接続には独立Labの1,200か月上限を適用しない | 配列と保存が成長し、ブラウザー保存容量・復元時間の影響を受ける |
| 保存サイズ | 生の正式モデル入力は6,016,384 UTF-16コード単位未満。コア単体の復元は100万未満 | ブラウザーの容量不足は別の制限。H0のファイル選択は元の保存に触れない |

`history-worker.mjs` は本編帳面の投影をキャッシュする。H0の保存ファイル分析では別のWorkerで正式検証・再生を行う。切替でWorkerを終了できる。比較3例は生成済みの分析結果を即時に切り替える。選択ファイルはWorkerへ渡し、送信や本編保存への書き込みを行う経路はない。

## H1以降

| 優先度 | 追加する記録 | 理由と保存互換性 |
| --- | --- | --- |
| P0 | 検証できる再生チェックポイントと履歴容量の計測 | 長期再生と保存負荷が先に問題になる。元のログとルール版に紐づく派生記録から試し、既存セーブは現在の入口で復元できるようにする |
| P1 | 取引の開始・終了・再開、世代交代時の樽・取引先、月別販路集計 | 実際の中断と単なる納品空白を区別できる。追加時点から記録し、旧版の期間は不明のまま保持する |
| P1 | 事実の恒久IDと操作番号、口コミ・問い合わせ・契約・実売間の参照 | 物語内の一文から根拠を引ける。既存IDを参照し、欠落を許容する |
| P2 | 店主の人物ID、在任期間、実際に届いた手紙の記録 | 店主本人の思い出や差出人が確定する。人物のない既存セーブへ、過去の人物や発言を遡及追加しない |

## 長期計測

広域展開型を同じ方針で1,200か月まで進め、途中の状態を保存した。Node v24.22.1上の計測値。別プロセスも動く環境での単発値であり、端末の所要時間を示すものではない。RSSは復元などを含むプロセスの最大値で、Workerだけの使用量とは異なる。

| 経過 | 操作 / 納品行 / 街イベント | 保存 UTF-8 | 正式復元 | H0分析 | 最大RSS |
| --- | --- | ---: | ---: | ---: | ---: |
| 30年 | 515 / 91 / 2,446 | 2.61 MB | 19.75秒 | 25.91秒 | 271 MB |
| 50年 | 802 / 158 / 3,502 | 3.73 MB | 39.38秒 | 61.69秒 | 374 MB |
| 100年 | 1,528 / 324 / 6,138 | 6.54 MB | 101.59秒 | 171.02秒 | 584 MB |

全3時点で正式復元と再シリアライズの一致、次月への進行を確認。100年時点のヒープは分析前39.94 MB、分析直後313.19 MB、強制GC後41.34 MBだった。100年時点の保存は5,838,093 UTF-16コード単位で、モデルの復元上限まで残り178,291単位だった。操作・納品の件数上限より先に、街の記録を含む保存容量が問題になる可能性がある。この試行ではブラウザーの保存容量を測っていない。


## 検証結果

- 3例の30年正式セーブを復元し、累計・月次・世代別の実売、店舗の納品本数、タイムラインの瓶詰め・納品・口コミ・問い合わせの参照先と発生月を照合した。
- H0テスト4件成功。同じ記録を再分析した結果、正式セーブのバイト列、月次と販路の集計が一致。旧版の移行前は残った瓶詰めを表示し、世代や最初の実売を補完しなかった。
- 既存の履歴関連テスト24件成功。全体回帰から残った4件（A1-3のキャッシュ逆置換、R4とR5の基準ハッシュ照合、visual-14のボタン文字列）は変更前のmainでも再現した。今回の差分に本編の実行ファイル、セーブ形式、経済計算、乱数消費は含まれない。
- Chromiumの360px・1280pxでLabを確認。3例の切替、キーボード、正式セーブの読込、不正ファイルからの復帰を確認。30年保存のWorker分析中も0.8秒で48フレーム進み、比較への切替ができた。検査中にブラウザー保存とデータ送信は発生しなかった。
- iPhone実機での操作、ブラウザーで100年保存を最後まで解析したときのメモリは未確認。
