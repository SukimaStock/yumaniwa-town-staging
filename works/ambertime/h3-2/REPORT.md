# H3-2 世界の動きの増分収集・世代回想の確定

2026-11-06。基準main `2df1ca9db957de576fbf9fa7e29b762c83023cb3`、積み重ね基点H3-1 `bc73b8558648a1cfe736860b2c9bc99b76659563`。H3-1／PR #820はDraftのまま。H3-2もDraftのみ、mainマージ・本編・正式セーブ・Production変更なし。

## 結論

**H3-1のC案と「現役候補＋確定回想」は、実際の正式操作の前後状態から増分で動作した。小さい保持Bを次の本編統合の基礎として推奨する。** ただし、現在の研究用Node seamやmemory取引をそのまま正式セーブへ移す段階ではない。

3方針の30年・100年を独立に入力し、12行・9種類の世代交代を検証した。全9境界で確認済み口コミ経路の主場面ペアが残り、当代の世界の出来事が中心になった。小さい保持Bと広い保持Aは8境界で採用ID・文・情景・関係が一致。残る1境界は地元初代の通常納品 `delivery:3` が最初の納品 `delivery:1` に替わった。失われた通常場面がないとは言わない。

必要な由来・確認済み因果を残すという契約は、この実記録と追加境界試験で成立した。将来の任意の選定方式、別seed、多銘柄、途中移行までの無欠落保証ではない。

## H3-1との一致と相違

既存の公開12行を同じ入力でadapterへ通すと、C案のseed・全場面が完全一致した。一方、実操作からの入力は、C-3で既に整理されたH3-1入力より広い。初代の採用IDは3方針とも大きく変わる。H3-1の同じ候補IDで比較した月・操作index・同操作順・世代の差はゼロ。未観測のH3-1 IDは、その場ではまだ実行していない当該世代のhandoverだけで、世界の出来事の欠落はなかった。

H3-1との差はcomparison.jsonの各境界 `broadVsH31` / `smallVsH31`、保持による差は `smallVsBroad` に分離した。共通IDでも背景となる最初の事実が増えれば関係が変わり得るため、IDだけでなく文章・情景・関係の差も記録する。採用不一致を消すために元の事実を捨てていない。

100年で観測した全事実は地元3,280／広域5,093／混合4,285件。うち保持対象の世界・樽・発売は3,254／5,057／4,253件。これらの全件を新しい正式履歴として保存する設計ではない。比較用の全観測リストはハーネスだけが持つ。

## 一世代の回想全文：地元密着・二代目

以下は小さい保持Bの実際の選出。プレイヤー本文は一文ずつで、研究ID・理由は別のSCENES.mdに掲載する。

1. 2054年1月、先代が樽に詰めた『石蔵』を瓶詰めした。
2. 2054年4月、自家販売で『石蔵』に「果実の香りがよく出ていますね。」という反応があった。
3. 2056年5月、海外の飲食文化圏に口コミが届いた。
4. 2058年10月、海外の飲食文化圏で銘柄を知った人が蒸留所を訪れた。
5. 2063年1月、全国の飲食のつながりから問い合わせが届いた。
6. 2078年1月、先代の頃に酒を届けた町の酒店に『石蔵』が届いた。

口コミ到達 `arrival:e1747` と訪問 `visit:e1850` は正式sourceIdチェーンで同じ経路を確認できる。全国からの問い合わせは隣の訪問の「結果」とは書かない。最後の酒店納品は昔の納品と同じ店・別発売であり、30年連続取引の証明とは扱わない。先代の樽の瓶詰めと、先代発売が後年の地域反応・納品に関わる事実を、内部の作業報告だけにせず組み合わせられる。

## 体験の評価

- 小保持の全52場面中、世界の出来事49、内部の出来事3。内部の3場面は先代の樽の瓶詰め。過去世代を独立した主場面として並べ直した場面はゼロ。
- 9境界すべてに実際の口コミ経路の主場面ペアがある。選出場面の因果リンクは地元6／広域7／混合6、再登場リンクは12／10／9。因果と再登場の両方がある場面も区別して保存する。
- 先代の樽は地元1／広域0／混合2場面、先代発売の参照は7／5／3、同じ店・銘柄の別発売参照は2／3／2。広域で先代樽が選ばれないことを、存在しない由来で埋めない。
- 同一回想内の正規化した完全同文はゼロ。ただし「到達→問い合わせ／訪問」「客の反応」「同じ店へ納品」の組合せが代を越えて似る。完全一致ゼロだけで文の多様性が解決したとはしない。
- 最長15年の空白を許容した。地元二代目の中間には月526の客反応があるが、早い場面と同じ「果実の香りがよく出ていますね。」で、追加すると説明の繰返しになる。空白を埋めるだけの採用は見送る。一方、広域初代は最初の10年に4場面が偏り、視覚で時間が流れたと感じられるかは未確認。

全世代・両保持案の本文、分類、月、ID、理由、主場面／背景参照、情景は [SCENES.md](SCENES.md)。数字は選定結果を説明する指標であり、件数が多い案を勝者にする評価ではない。

## 保存失敗と再開

通常操作・月次・交代直前・確定直後のJSON往復と再開を確認した。100年各実行でも別のcollectorを途中でJSON復元して継続し、採用ID・文章・情景・根拠と全collector状態が一致。後の世代を進めても確定回想は不変。

研究一体保存は、候補生成失敗、encode失敗、容量不足、書込み失敗、readback異常、競合、破損、再試行を検査する。地元30年の本物のhandoverGenerationにS2・S4・時計・collectorを同時接続した結合試験でも、保存失敗で旧世代の全状態を保ち、再試行後に再生記録と同じ新世代状態になった。詳細は[SAVE.md](SAVE.md)。

memory adapterの原子的CASを検証したのであり、localStorageの複数タブや書込み後障害が同じ保証を持つと主張しない。正式保存の巻戻しをどう維持するかは、統合時に既存committedSessionと同じ成功境界で接続して実ブラウザーで検証する。

1. 研究seamを正式な増分APIへ整理し、S4の由来情報を共通参照して二重保存を減らす。仕込み開始世代と樽詰め世代の違いを失わない。
2. 正式saveCandidateにゲーム・時計・帳面・歩み・collectorをまとめ、競合時の旧状態保持、quota、readback、複数タブを実ブラウザーで確認する。session v7は今回変更していない。
3. 閲覧中の未確定回想を閉じる／再開する場合と「次の代へ」で確定する場合の保存境界を決める。閲覧開始時に先行交代しない。
4. Bの48か月帯と到達の初回／直近保持は今回の比較条件。複数銘柄・別seed・極端に取引が少ない／長い休止のケースで、普通だった出来事が後年の意味を失わないかを追加確認する。
5. 海外ペアの反復、年代偏りの見え方を回想画面で確認する。Cの重みをこの研究の結果に合わせて再調整してはいない。

推奨は「C案＋小さい保持B＋正式町本文への位置索引参照＋確定回想の本文保存」。今回の記録では機能的に成立し、次の統合研究へ進める。ただし、正式保存導入とSafari上の実用性を完了扱いにはしない。
