# H1-B1 — 歴史回想の保護検証

## 検証方法と再利用条件

100年・4世代の地元密着／広域展開／混合の3記録、計9世代交代境界を対象とする。A（現行）・B（到達ID参照）・C（到達索引を派生）の保存表現を正式状態へ戻してから、従来の抽出・回想処理へ渡す設計を検証する。正式モデル・C-3・D1.1・D1.2・H2-5は変更しない。

`history-run.mjs` は各100年入力のSHA-256をH2-5公開記録および完了済みH1-A3の入力SHAと照合する。各案のdecode結果を元の正式JSONと**全文字一致**させ、全状態のdeep equality、町events・operationsのハッシュ一致も確認する。このため、圧縮していないraw事実・sourceId参照チェーン・ID・乱数・seen等を含む元データが復元時に保存される。

100年の操作再生・raw抽出を今回新しく3案ずつ繰り返すことはしない。H1-A3の `independentRawEqual`、9境界の `immediateEqualsLater` と `publishedEqual` が成功した証拠を再利用する。再利用は入力SHA一致に加え、抽出・モデル・編集の関連ソースと再帰的importをH1-A3マージcommit `00e6a0090d068b5d917dd806244a654dfa09bba3` とバイト比較できた場合に限る。対象ファイルとSHAは `history-results.json` のdependencyManifestに記録する。

公開済みH2-5資料は全raw列ではなく、境界別候補が参照する共有候補実体プールである。今回はこのプールから各境界のID順・ordinal補正を適用し、既存C-3確定済みの境界候補を復元した後で回想編集を実行する。C-3による候補確定自体は、依存不変を確認した既存の完了証拠を再利用する。9境界×3案の27回について、全候補・根拠・ordinal・replayOrdinal・境界・抽選結果・D1.2文を含むmaterial全体のSHAをH1-A3と照合する。別途rawイベントID・月・世代・operationIndex・ordinal・replayOrdinal・参照情報のdigestも記録する。

これは新規raw再生の実測ではなく、**同一入力・同一コードに基づく再利用証明と、候補復元・編集の再実行**である。採用された場面だけを保存する方式には変更していない。

## 再現

入力は既存のSHA照合済み研究用複製 `local-1200.json`、`wide-1200.json`、`mixed-1200.json` を使用する。

```sh
node works/ambertime/reputation-dedup-research/history-run.mjs /tmp/h1-b1/saves
node --test works/ambertime/reputation-dedup-research/history.test.mjs
```

テストは完了証跡を入力・コード・元研究成果のSHAへ結び、9境界の既存material digest・seed・採用ID順・文が3案で一致していることを再確認する。正式コードやadapterが変われば結果の再生成が必要になる。元保存の内容はrunner終了時にも再照合し、書換えない。

## 結果

3入力すべてでH2-5・H1-A3のsourceSHAが一致し、53依存ファイルがH1-A3時点と同一だった。A/B/Cすべてが元JSONへバイト同一に復元した。9固有境界について計27回の候補復元・編集が完了し、各material digest、候補数、seed、採用ID順、D1.2文がH1-A3と一致した。実行時に不一致はなく、境界外の未来イベントの混入もなかった。

`node --test .../history.test.mjs` は4件成功、失敗0。重いraw再生を再測定したという主張はしない。今回の結果が保証するのは、**今回照合した入力・コードと、正式状態へ復元してから既存処理を実行するadapter境界**における歴史の同値性である。
