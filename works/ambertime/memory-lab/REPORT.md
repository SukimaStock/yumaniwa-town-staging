# AmberTime H1-B 日常と歴史の接続Lab

H0の30年記録3件を使い、数字、短い出来事、既存素材を使った場面を、同じ関係に対して切り替える。比較の初期表示はAの数字。Cでは日付を自分で進められる。店の場面は当時の地図を再現したものではなく、現行の同じ地図素材・店舗座標を使って過去と後年の出来事を並べる。

## つながりを確認できた記録

| 関係 | 確認する根拠 | 記録だけで分からないこと |
| --- | --- | --- |
| 店 | 同じ店舗IDの取引開始・納品行、納品を記録した操作と世代 | 納品の空白の理由、休止や再開、店主の交代、プレイヤーが何回店を見たか |
| 銘柄 | 同じ銘柄IDと別の発売ID、各発売の世代 | 受け継ぐ意図、何を覚えていたか |
| 樽 | 同じ樽IDを参照する樽詰めと瓶詰め、経過月と瓶詰め記録 | 樽に対する思い入れ、操作に残らない日々の確認 |
| 評判 | 街の到達・問い合わせのID、問い合わせからさかのぼれる参照 | 参照のない到達との因果、プレイヤーが通知を読んだか |
| 世代 | 交代の操作番号、引継ぎ元と先、前後の納品 | 交代が納品を引き起こしたか、交代後も同じ人物と付き合ったか |

地元密着型は17か月目に町の酒店と取引を始め、23か月目に最初の納品があった。321か月目に世代が変わり、356か月目にも同じ店舗IDで納品を確認できる。累計は73本、最初と最後の納品間隔は333か月、最長の納品空白は10か月。17か月目の取引開始と356か月目の納品は339か月離れている。333か月と339か月は起点が異なる。

全国への口コミは16か月目で、酒店との取引開始より先に起きた。76か月目の海外到達と171か月目の問い合わせは時間順に並べられる。問い合わせの参照をたどると、86か月目の発売に関連する別の160か月目の海外到達と関心の記録が見つかる。口コミの到達、問い合わせ、取引、販売は別の事実として扱う。

証拠の分類は、共通IDで照合した事実、元記録の参照で結ばれた事実、時間順のみを比較した事実の3つ。世代交代の前後関係や店舗IDの一致から因果を推定しない。手動で棚へ配置したことと、月次処理が納品を確定したことを区別する。雇用・予約が記録にあっても、その事実だけから個々の仕事の担当を補わない。表示用の短文は派生データであり、正式な履歴イベントではない。

## 日常のどこにつなぐか

| 場所 | 日常で残すもの | 節目で再登場させるもの |
| --- | --- | --- |
| 販売室 | いまの棚と瓶を直接触る操作。取引開始時にだけ、いつもの棚に店が加わる | 使ってきた店のアイコンや銘柄の瓶 |
| マップ | 店の座標と識別できる見た目。店名から必要な取引情報だけを開ける | 同じ座標、同じ切り取り、日付だけが変わる場面 |
| 帳面 | 初回の取引・初回の瓶詰め・引継ぎなど、後で参照できる事実とID | 場面の根拠を必要なときに開ける短い記録 |

せり上がりやマップチップを試す場合も、店舗ID・基準座標・識別しやすい形を引き継ぐ。既存の配置と販売室の操作は今回のLabから変更しない。取引の休止・再開を描くなら、その事実を記録する必要がある。店主本人の言葉を扱う段階では人物IDと在任期間、実際に出会った記録が必要になる。今回の3案は場所や物だけで成立するかを先に試す。

## H2への引き継ぎ

設計上はCを第一候補とする。同じ店を別の年月で見比べられ、説明が短くても関係をたどれる。Bは短い一文で確認したい場面に向く。Aは数字の照合と比較の基準に使える。どの案が自然に感じられるかは試遊で判断する。

IDの照合、期間、操作の関与、参照の有無、候補の優先順位は計算で扱える。将来AIを使うなら、確定した場面候補を並べ、説明を短くする作業から検討する。根拠のない人物・感情・台詞・因果を加えず、一文ごとに元の記録へ戻れるようにする。

試遊では、まず根拠欄を閉じたままCを進める。同じ店だと気づいたか、年月が進んだことが分かったか、何が実際に起きたと受け取ったかを聞く。その後にBとAを比較する。初めて見た人が同じアイコンだと認識できることと、自分のプレイで見覚えがあることは別々に確認する。本編へ接続する前には、実際に遊んだ本人の記録で、節目を邪魔せず必要な情報だけで理解できるかを見る。

## 再現と負荷

配信時はH0の比較JSONとH1-Bの小さな派生JSONを各1回読む。画面内の切替や場面送りは正式記録を再生せず、ブラウザー保存へのアクセスも不要。H0とH1-Bのキャッシュやデータを正式セーブとして扱わない。H1-Aのチェックポイントや保存上限は別作業とする。

派生データはH0の元記録と同じSHA-256を持つ3件から、既存の操作再生を各1回使って生成した。H0の分析処理を画面でも生成工程でも再度呼んでいない。保存ファイルを用意せずに再生成する場合は、H0の同じ3方針を実行する。

```sh
node works/ambertime/memory-lab/generate.mjs > /tmp/ambertime-h1b-connections.json
cmp /tmp/ambertime-h1b-connections.json works/ambertime/memory-lab/connections.json
node --test works/ambertime/memory-lab/*.test.mjs
node tools/work-lifecycle.cjs --check
```

## 試作での検証

地元密着型6件、広域展開型8件、混合型8件の関係を収録した。3例とも初代と後継世代で同じ銘柄の瓶詰めを確認した。広域展開型・混合型では酒店とスーパーの納品を世代の前後で確認できた。デパートは各試行で納品1回のため、再登場の候補から外した。

- H1-Bの4件、H0・既存履歴関連の28件が成功した。表示する62件の記録の操作キー、納品・発売・街の参照を元記録と照合した。比較で使った3保存には、分析対象に該当する委任実績がなかった。
- Chromiumで360・390・1280pxを検証した。全3記録・全関係でA/B/C切替、前後操作、根拠表示を確認。店舗の場面は前後で地図の描画が一致した。比較中にデータの再取得、保存への書き込み、送信は発生しなかった。
- 本編とH0のコードに差分はない。既存の全回帰で残る基準照合・文言の失敗はH0で変更前にも確認した4件。iPhone実機での認識・読みやすさや、本人が自分のプレイで店を思い出すかは試遊待ち。
