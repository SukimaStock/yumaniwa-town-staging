## 引き継いだ計算

| 項目 | 再利用する現行経路 |
| --- | --- |
| 蒸留 | `partner-orders.newStaffDistillery → startDistillation → distillStep → stopDistillation → fillBarrel`。採用済みaroma-a/1の山型原酒香。古い線形previewや未採用実験は使用しない |
| 熟成・蒸発 | `model.ageCask`。月次では`economy.economicMonthly → monthly.advanceMonthly → model.advanceMonth`を経由する |
| ビン詰め | `model.bottleQuote / bottle`。0.7 L/本、ビン詰め時点の3軸と月齢を商品へ固定。指定本数だけ取り分ける |
| 価格 | `economy.salePrices(...).standard`。現行の最低価格と価格係数を維持 |
| 販売 | `economy.economicMonthly`。販売中商品のみ、翌月以降に販売。若い商品の共有需要、24人上限、商品間の配分・端数処理を維持 |
| 仕込み保護 | `economy.canStart`の4樽・商品容量・同月仕込み制限を利用。実験費用に応じた予約金を別途検査 |
| 資金保護 | 全樽をビン詰めする費用を予約し、次の月の入金・維持費・蒸発後に予約を下回る場合は、その月全体を確定しない |

原酒を作る際は独立した本編モデルのインスタンスから実データだけを取り出し、実験内でIDと作成日時を一意に割り当てる。仕込みを押すと抽出・樽詰めまでまとめて進むが、同じ月に複数回仕込めない。これは蒸留操作の面白さを再検証する画面ではない。

`economicMonthly`は、古い観察イベントの判断待ちがあると熟成だけ止まり得る。実験ではその前後に観察イベントのpending・試飲待ち・decisionsを解除し、必ず1か月だけ進んだことを確認する。専用の強制ビン詰めイベントは追加せず、自分で試飲・ビン詰めを選ぶ。操作履歴の本編replay検証は使わず、本編用セーブとして読めるとは主張しない。

## 4つの条件

全条件で同じシード・初期の樽・所持金・月から始める。条件変更時にはリセットする。初期資金だけを変えて資金圧力を表現する方式にはしていない。

| 条件 | 熟成・蒸発 | 費用 | 季節需要 |
| --- | --- | --- | --- |
| 現行基準 | 現行 | 現行 | なし |
| 熟成＋資金 | 現行 | 強化 | なし |
| 熟成＋季節 | 現行 | 現行 | あり |
| すべて | 現行 | 強化 | あり |

| 費用 | 現行 | 強化条件だけ |
| --- | ---: | ---: |
| 蒸留 | £120 | £150 |
| リフィル | £100 | £125 |
| バーボン | £160 | £200 |
| ビン詰め | £3/本 | £3.75/本 |
| 月次維持費 | £4＋£8×保管樽数 | 左の1.75倍 |

強化時は本編関数が請求した額との差額をcashと費用の集計へ追加し、帳尻を一致させる。販売価格の自動引き上げで費用を埋め合わせない。蒸発率・蒸留の3軸・瓶の容量は変えない。

## 初期状態

最初から違う状態を試せるよう、準備済みのスナップショットを3種類用意した。

| 初期セット | 樽 | 資金 |
| --- | --- | ---: |
| mixed | 抽出99リフィル6か月、66リフィル18か月、50バーボン30か月 | £1600 |
| full | 抽出99リフィル0か月、66リフィル12か月、50バーボン24か月、30バーボン36か月 | £1600 |
| lean | mixedと同じ3樽 | £620 |

全セットは実験の同じカレンダー月から始める。元の製造履歴を最初から再現した経営状態ではなく、準備済み資産と現金である。初期資産の費用を差し引いた経済戦略同士の公平な競争と解釈しない。各セット内の4条件では初期資金と全ての樽が一致する。

## 季節は販売へ作用する

冬（12〜2月）1.2、春（3〜5月）1.0、夏（6〜8月）0.8、秋（9〜11月）1.0を基本需要係数とし、既存の3軸に応じて±10%以内の係数を重ねる。

- 冬：木のかおりがあるビン。
- 春：原酒のかおりがあるビン。
- 夏：穏やかなシゲキと控えめな木。
- 秋：原酒と木の重なり。

これらは現実の市場の主張ではなく、今回の仮説。風味ごとの影響は `retailFactors` を通して現行の需要式へ渡す。全体で月24人の上限を外さないため、需要が十分に大きければ季節差が販売本数に現れないこともある。

ビン詰めしても即売れない。まず「保管中」の商品ができ、「販売する」で販売対象にする。その後、月を進めると残り在庫から売れる。保管中の風味・月齢・本数は固定で、木香が増えたり天使の分け前で減ったりしない。秋にビン詰めして冬に販売することと、樽のまま冬まで待つことは別の選択になる。

## お金が少ない時

次の月の費用を払うとビン詰め予約を割り込む場合は、月の進行を確定しない。熟成だけ進む・売上だけ入る・費用だけ失うような部分適用はしない。

手元にあるビンを販売する、一部の原酒をビン詰めして販売する、樽全体をビン詰めして維持費と空きを減らす、という回復を試せる。保管中のビンは、販売しない限り資金にならない。融資や借金は追加していない。

この保護は資金不足自体を面白くするものではない。操作が止まるだけ、ビン詰めしか選べない、立て直しても同じ動作を刻むだけになる場合は、比較結果の問題として残す。

## 記録と作者の確認

ビン詰め時に経過月、樽番号、季節、風味、残量、費用、前後の現金・在庫、空き枠を記録する。月次の売上・維持費、販売開始・保管、新しい仕込みも追える。理由の入力は任意で、空欄でも進められる。

任意の問いは「なぜ今ビン詰めしたか」「もう少し待ちたかったか」「次に試したいこと」。JSONに一緒に残せる。分析用の機械方針が早くビン詰めしたことと、本人が自発的にビン詰めしたくなったことは区別する。

## 有限比較の結果

シード `20261020 / 42` × 初期3セット × 4条件 × 4方針＝96本。各36か月を上限とし、資金保護で止まった方針はそこで終了する。追加の無制限探索や、有利な結果に合わせた係数変更はしていない。`node works/ambertime/experiments/decision/analyze.mjs`で再生成できる。

機械方針は、最も古い樽を対象に、6か月で回収するearly6、36か月を待つwait36、24か月または予約後資金が維持費3か月未満で回収するcashAware24、秋冬に12か月以上を詰めて冬に販売するautumnStock。空き・資金があれば同じ66/リフィルを仕込む。これは人間の動機の代用でも最適解の証明でもない。

| 条件 | early6 現金増減 | wait36 現金増減 / 停止 | cashAware24 現金増減 | autumnStock 現金増減 / 停止 |
| --- | ---: | ---: | ---: | ---: |
| 現行基準 | +£5190.27 | +£387.14 / 2件 | +£2124.49 | +£1988.54 / 0件 |
| 熟成＋資金 | +£2909.43 | −£579.88 / 4件 | +£545.66 | −£64.97 / 2件 |
| 熟成＋季節 | +£5475.93 | +£387.14 / 2件 | +£2124.49 | +£1988.54 / 0件 |
| すべて | +£2938.72 | −£579.88 / 4件 | +£524.19 | −£64.97 / 2件 |

各セルは6本の平均。停止した方針も含み、期間・残存資産・在庫が違うため利益率ランキングとして扱わない。全96本で現金＝初期現金＋売上−製造/瓶詰め−維持費を照合した。

**資金**：cashAware24は全条件で36か月完走し、強化時の平均瓶詰め月齢は約23.7〜23.8か月。待つ余地は残る。停止は計16件あり、各停止状態から別枝で「保管品を販売」または「5本だけ詰めて販売」を試すと、全件で次月へ進めた。元の方針が停止した事実は消していない。さらにleanの資金強化2条件×2シードでは、月2の停止から5本販売で月3へ進み、残り32本の瓶詰め・販売を経て月5に新しい仕込みを再開できた。全状態で行き詰まらない証明ではなく、少量回収を刻む負担も未評価。早期方針の現金増加は強化後も大きく、資金が一方的に増える問題を解消したとは言えない。

**季節**：同一のビン在庫3商品に季節係数だけを変える比較では、4季節とも共有上限24本に達し、秋の配分が1本変わるだけだった。wait36やautumnStockは季節有無で最終現金が一致し、味の需要差が丸め・在庫・上限に埋もれる問題がある。係数を強めて結果を作る変更はしていない。

**事前準備と待機**：同じ秋の状態から、20本を秋に詰めて保管する枝と、冬まで樽で待って20本詰める枝を比較した。最初の冬の販売月後では待機側が£5.85〜7.20多い。一方、全量瓶詰めでは秋に空きを作り維持費を減らす枝が£16.80〜36.15多い。本数を揃えるか全量かで結果が変わり、瓶詰めと販売の時期は区別できた。冬の一律優位や季節だけの効果を示す比較ではない。

**熟成と蒸発**：6製法を0/6/12/24/36/48/72/96/120か月で確認。例として抽出30・バーボンは原酒香が0か月0.239→48か月0.483→96か月0.136→120か月0へ変化し、木香は増える。24 L・34本から36か月21.84 L・31本、120か月17.54 L・25本へ減る。長く待つと失うものは既存モデルだけでも存在する。ただしこの長期曲線は経営36か月比較とは別で、全ての長期経営を実証してはいない。

## 実施した検査と差分

- 現行モデル再利用、基準販売との一致、費用帳尻、容量、月次原子性、資金保護と回復、条件リセット等の11モデル検査を実施。追加修正は該当検査だけ確認した。
- Chromiumの390×844タッチ相当で、試飲、部分瓶詰め、保管と翌月販売、風味固定、新規仕込み、満杯から空きを作る、4条件リセット、資金停止と少量回復、理由なしの操作、任意メモ、JSON読み戻し、LAB往復を確認。360幅/1280幅で横はみ出しなし。画面画像を目視確認。実機Safariとは区別する。
- 既存保存キーに不透明な文字列を入れ、操作前後で全保存値が一致。実験はセーブ内容を解釈しない。新規LAB登録の関連回帰24件と生成整合検査に成功。
- 独立レビューでJSON末尾の改行エスケープ不備を発見し、画面書き出しと分析保存を修正。ブラウザでJSON.parse成功を確認。分析用季節比較はカレンダーだけ変えると既存整合検査が失敗したため、同じ有効状態に需要Mapだけ渡す比較へ修正。モデル係数は変更しなかった。ブラウザ検査側の連続ダウンロード待機と閉じたメモ欄の操作も修正した。
- 表現監査：操作と必要な費用・季節予告を中心にし、点数、最適製法の指示、祝福、架空の感情、説明カードを追加していない。任意メモは折りたたみ、樽と販売在庫を区別する。
- Planとの注記：固定済みr0のrulesAppliedにContest由来の「Three fixed seeded rivals」が1行残るが、expectedChanges/非対象/実装は一貫してコンテストなし。比較対象は固定の機械方針であり、対戦相手は実装していない。固定Lockを事後に書き換えず、この文言差を記録する。既存Contest Planとの差分は外部評価を扱わず、資金と季節販売を扱う点。
