# 手札と場 Lab 0.4 — 店からの注文

店の注文を選び、手札を渡すと在庫が減る。渡した一本と店に残った分から、次の注文が変わる独立Lab。手動で渡す体験が分かりやすく、また造る理由になるかを作者が試す。

基準main `0d58fdb189bec9c6f3ca2f62c71aa2177ab26116`（PR #625）。最新main、AGENTS、Change OS、表現監査、v02/v03のREPORTと実装、既存仕込み・熟成・瓶詰めを確認。`.change-plans/ambertime-hand-place-v04/r0.lock.json` を実装前に固定。既存Lab・本編・保存形式・Productionは変更しない。

## 1. v03から組み直したこと

| 項目 | v03 | v04 |
| --- | --- | --- |
| 中心 | 店へ紹介し、取扱いを成立させる | 店から来た注文へ、一本を選んで渡す |
| 店 | 3店 | レストラン・酒屋の2店 |
| 最初の手札 | 3種類・各12本 | 同じ風味の3種類・各6本（少量条件は1/2/2本） |
| 在庫が減る時 | 後の自動配送 | 「渡す」を押したその場 |
| 反応 | 店主の返事と条件付きの後日談 | 返事に加え、次の注文・数量・時期が変わる |
| 店の在庫 | 継続取扱いと倉庫在庫が中心 | 前に渡した一本が、店に何本残っているか |
| 次の行動 | 置換・別の店・再仕込み | 残りの手札、次の注文、別の一本、再仕込み |

v03を小型化した配送モデルではなく、新しい手動注文モデルを作った。取扱いの相性ゲート、継続契約、自動発送、予約・確保、紹介の記憶、店主/客の反応比較はv04へ持ち込んでいない。

## 2. 最小ルール

- レストランと酒屋に初回2本の注文がある。注文は1〜3本で、同じ店の未対応注文は1件まで。
- 注文→手札→渡す。希望と違う味も選べる。相性でボタンを無効にしない。
- 渡す量は「注文数」と「手札残数」の小さい方。倉庫から引いた量と同じ本数が店に入る。
- 一部しか渡せない場合も、その分で注文を閉じる。不足分の借りや未納タスクを自動で残さない。
- 店に前回分が残っていれば、新しい注文は出ない。待機は失敗や取引終了ではない。
- 店の残数が0になると、前回の**実納品**から次の注文を作る。注文は何か月待っても失効せず、放置して別の店や仕込みへ進める。
- 「今回は見送る」では在庫も店の評価も変えない。2か月後に再度声をかけるだけ。自動受諾・自動納品はない。

注文がない間に進むのは時間・熟成・店の残数だけ。新しい注文が届いても、本人が渡さなければ手札は減らない。

## 3. 前回の一本から次の注文へ

両店は同じ仕組みを使い、前の納品の味・量・月と店の用途だけで分岐する。

| 店・実納品の特徴 | 店の残数の減り方 | 使い終えた後の希望 |
| --- | --- | --- |
| レストラン・煙>0.45または樽影響>0.45 | 2か月ごとに1本 | もう少し軽いもの |
| レストラン・その他 | 1か月ごとに1本 | 同じ一本 |
| 酒屋・樽影響>0.45かつ72月以上 | 1か月ごとに1本 | 同製法の若い一本 |
| 酒屋・煙>0.45 | 1か月ごとに1本 | 同じ一本 |
| 酒屋・その他 | 1か月ごとに1本 | 別の特徴の一本 |

樽影響は既存の木/バニラの最大値。新しい風味式・需要点・客層はない。閾値は少数の試遊例を分けるためのもので、現実の販売速度や味覚の正解を意味しない。

同じ一本を希望するときは「前回実際に渡された量＋1本」を1〜3本へ収める。別の希望は前回実納品量を1〜3本へ収める。2本を渡した後なら再注文3本、1本だけ渡した後なら次は2本となる。注文書の希望数を納品済みとみなさない。

店の残数は、前回納品月から上記の間隔で1本減る。0本になった月に新しい注文が届く。売上・価格・客一人一人は計算しない。「店頭で選ばれた」「食後に合った」という言葉も、この限定した試遊上の使用ルールを表す。精密な需要予測ではない。

注文内容に従う義務はなく、同じ一本の再注文へ煙や樽香を替えて渡してよい。その場合は**今回渡したもの**から次の希望を決め直す。同じ製法・同じ熟成月数の別発売回なら、再現した今回分として返事をする。希望を満たしたかの点数や報酬はない。

## 4. 画面と短い操作

上段に2店の注文と現在の残数、その下に3枚の手札を表示する。注文には店名・本数・理由・元の納品番号/発売回を表示。店に在庫がある場合は「今は注文なし」と残数を示す。

選択中は枠と「どの注文へ、どの発売回を何本渡すか」が見える。手札が1本しかなければボタンも「1本だけ渡す」になる。確認画面は挟まず、押した瞬間に「6→4本」、店に2本、短い返事が一緒に分かる。

0本のカードは通常一覧から外し、「過去の一本」で呼び出せる。品切れの時も元の製法は残る。手札が増えるたびに1本ずつカードを作らず、発売回ごとの残数で扱う。

時計を主画面へ出し、店の在庫が減り、次の注文へ変わるのを見られるようにした。新着注文は既存の返事欄と店のカードへ残す。新しい通知一覧やポップアップはない。変化のない月に、同じ返事を再通知しない。

## 5. 再仕込みと、長い空白を避ける初期条件

既存の風味モデル `ambertime-flavor-lab-v02/model.mjs` を読み取り専用で利用する。麦芽・発酵・採取範囲・樽・名前履歴・熟成を保持。新規の再仕込みは1か月の準備、その後0か月から熟成し、瓶詰めは本人が選ぶ。4樽上限。新しい完成品を自動生成しない。

| 初期条件 | 手札の本数（果実/煙/樽香） | 最初から熟成中の樽 |
| --- | --- | --- |
| 各6本 | 6 / 6 / 6 | 果実香の製法・22か月、元の一本24か月 |
| 手札少なめ | 1 / 2 / 2 | 同製法・23か月、元の一本24か月 |

この樽は試遊前に仕込んであった明示的な初期資源で、新しく再仕込みした瞬間に完成する仕組みではない。元の24か月なら標準条件では2か月、少量条件なら1か月後に瓶詰めできる。早め・遅めに瓶詰めしてもよい。樽の存在と現在月齢を主画面に出した。

1回の瓶詰めは6本。新しい発売回に元の製法・発売回ID・実際の月齢を保存する。v04はその場の手渡しなので、瓶詰めしたその月から本人が選んで渡せる。v03や本編の月次自動発送の翌月ルールを変更したわけではない。

最初の樽のおかげで、手札が足りないときも次の瓶詰めを早く試せる。一方、通常の再仕込みを24か月待つ操作も残り、取引の短い周期と長い熟成が合うかは未解決の評価点。

## 6. 追加した状態と、削ったもの

| 状態 | 内容 |
| --- | --- |
| 発売回 | 風味・製法・月齢・残数・再現元 |
| 注文 | 店・1〜3本・理由・元の実納品/発売回・未対応/完了/一部/見送り |
| 実納品 | 選んだ発売回・量・前後の手札/店の残数・短い返事・次の希望/使用間隔 |
| 店 | 現在の残数・前回納品・現在の注文・使用間隔・見送り後の声かけ月 |
| 樽 | v01〜v03と同じ製法再現と実熟成状態 |

予約・発送計画・取扱契約・店ごとの複数商品在庫・価格・売上・評判・客の個別行動を削った。店の在庫は一つの納品分だけ。使い終わるまで次の注文を出さないので、異なる商品を店で混ぜ合わせる処理も不要だった。

「しばらく注文がない」ための別のランダム判定は作らなかった。残っているから注文がない、という同じルールで表現できる。見送り後の再連絡だけは2か月の固定間隔を持つ。

## 7. ログと因果関係

固定シード42、2種類の初期条件と、ゆっくり使う例を同じ操作から再現できる。乱数で注文の種類を増やしていないため、シードは条件記録であり、余計な揺らぎはない。

ログには届いた注文と理由、選択した発売回、実際に渡した量、前後の手札、店の残数、店の返事、使用した量、次の注文、後から本人が選んだ操作を残す。次の注文の `sourceDeliveryId` と `sourceLotId` から、元の実納品へ戻れる。見送った注文を実納品として参照しない。

操作を再実行して全結果とチェックサムを照合する。v04専用ログで、v03・本編の保存形式には触れない。全月の手札コピーを増やさず、重要操作の前後だけを記録する。

付属ログ：`tests/seed42-standard.json`、`tests/seed42-scarce.json`、`tests/seed42-slow-order.json`。`tests/comparison.json` に注文と納品の対応を整理。「ログを再現」で読み込める。生成：`node works/ambertime/experiments/hand-and-place/v04/tests/scenarios.mjs`。

## 9. 作者が試す5場面

1. 初回：レストランの2本を選び、果実香を渡す。6→4本と店の2本が、自分の操作の結果として分かるか。
2. 再注文：2か月進める。前の果実香を3本ほしいと言われ、残り4本を渡すか、別の一本にするか考えたくなるか。
3. 違う希望：酒屋へ樽香の一本を2本渡し、2か月後の若い一本への希望を見る。応える義務ではなく、次に試す材料になるか。
4. 注文なし：レストランへ煙を2本渡す。1か月後は2本、2か月後は1本残り、4か月目に軽いものの注文が来る。停止や失敗ではなく、前に渡したものがまだあると理解できるか。
5. 不足と再仕込み：「手札少なめ」で1本だけ渡す。初期樽を1か月進めて瓶詰めし、再度渡す。品切れの記録から新しい再仕込みも試す。

## 10. 次に残す課題

v03より「渡す→手札が減る→店で使われる→次の注文」が直接見える構造になった。ただし、それが楽しいか、取引数が増えても手動操作を続けたいかは作者評価を待つ。

初期樽は空白を短くする試遊条件で、継続生産のバランスを証明しない。1回の注文を小さくしても、同じクリックを2店分繰り返すだけになれば管理作業になる。反応文やイベントを増やす前に、注文の頻度・量・必要な操作を減らす方向で検討したい。

希望と違うものを選んでも次の注文が変わることが分かるか、1枠の店在庫と1本ずつの使用で十分か、24か月の再仕込みを待つ間に退屈しないかを残す。本編へ統合せず、この独立Labの試遊で判断する。
