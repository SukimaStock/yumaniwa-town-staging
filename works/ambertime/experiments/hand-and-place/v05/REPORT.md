## 2. 画面と、どこを見るか

上に2店、その下に手札・渡す操作・時計を置く。各店は「店名と注文印→今の一本/棚/残数→届いている注文→前回の納品元」。手札は名前・特徴・熟成年数/樽・残数を持ち、詳細風味と製法は既存の詳細へ残した。

| 起点 | 見る場所 | 即時に確定する結果 |
| --- | --- | --- |
| 自分で渡す | 選んだ手札と受取先の棚 | 手札6→4本、店0→2本。両方に受渡し量 |
| 1か月経つ | 使用があった店の棚 | 店2→1本。手札の瓶・残数は変わらない |
| 次の注文 | 店名横の注文印と注文書 | 店0本、前回の一本を参照する3本注文。手札は変わらない |

B/Cの瓶は最大3本。6本なら3本の絵＋「+3」と正確な残数、0本なら空の棚。大量のオブジェクトを増やさない。受渡しは琥珀色、時間経過は青灰色の短いラベルでも区別し、色だけに依存しない。ラベルはその場所の最後の変化で、毎月の新通知ではない。

数字は常に正確で、瓶の絵はaria-hidden。注文・カード・ボタンの文字とaria-pressedで選択と残数を読み取れる。美咲、暗い背景、矩形の輪郭、既存配色/44px以上の主操作を継承。手札3枚・2店・時計を優先し、新しい情報パネルは足さなかった。

## 3. A/B/Cの違い

| 方式 | 表示 | 狙いと残る評価 |
| --- | --- | --- |
| A 数字 | v04と同じ数字・文章中心。瓶なし | 正確な数量は読める。視線を数字へ向ける必要がある |
| B 瓶（初期） | A＋手札と棚の静止した瓶、空の棚 | 受取先に物が残り、減って空く違いを見比べられる |
| C 動き | B＋実イベント時だけ360msの移動/変化 | 変わった場所へ視線を導ける可能性。Bで足りれば不要 |

比較のため、配置・注文印・短い変化文・操作は共通。Aはv04のピクセル完全再現ではなく、数字中心の比較基準。すべて同じ初期条件・操作・ゲーム状態を使う。方式切替だけでは時間や選択も変わらない。

Cは納品時に実納品数の瓶が手札位置から受取先へ移動し、使用時は該当の棚だけが少し変わり、注文時は注文印だけが短く現れる。状態は**演出より先に確定**し、操作待ちや演出キューはない。複数の出来事は並行し、次の実イベントが来れば古い動きを取り消す。注文印は演出後も静止して残る。

初期表示・方式切替・選択・再描画・ログ再現で過去の動きを再生しない。モーダル/画面外では開始せず、後から遅れて再生もしない。瓶詰めは手札に6本と短い表示を追加するだけで、新たなモーダル終了待ち演出は作らなかった。

## 4. 状態と負荷

追加したのは一時的な表示方式、各場所の最後の変化、DOM文字列キャッシュ、実行中の有限演出集合、検証用カウンタだけ。ゲームモデル、注文の状態、乱数、保存項目は増えていない。

- 発売回/店をkeyにしたDOMを保持し、内容が変わった領域だけinnerHTMLを更新。選択は属性だけ更新。関係ない店や手札を月ごとに作り直さない。
- 時計はv04と同じ単一setTimeout・3秒/月。常時RAF、setInterval、装飾用の繰返しタイマーはない。時間を止めている間の待機更新もない。
- CだけWeb Animationsの有限transform/opacityを使用。終了後は移動用の非操作・非読み上げ要素を除去。描画フレームからdispatchやDOM再構築をしない。
- 停止・モーダル・非表示/pagehide・方式切替・reset/import・reduced-motion変更で動きを取り消す。スクロール/サイズ変更で対象が画面外へ出た場合も取り消す。背景へ移れば時計も停止し、復帰時の追いつきや自動再開はしない。
- prefers-reduced-motion時のCはBと同じ静止表示。瓶/数量/変化文/注文印は消さない。

### 同じ短い操作列での計測

`tests/browser/results.json`。納品1回→月次2回→別カード選択→副作用のない再描画を各方式で実行。開始時の方式設定と切替確認は計測区間から除外した。

| 代理指標 | A | B | C |

| それ以外のカードの内容更新 | 0 | 0 | 0 |
| 開始した有限アニメーション | 0 | 0 | 4 |

内容更新はアプリのDOM領域更新回数で、ブラウザのpaint回数ではない。B/Cには少数の瓶DOMが加わり、Cはブラウザ内部でアニメーションを描画する。Cの追加負荷をゼロとは扱わない。短い操作列では4演出中2つが後続イベントで取り消され、入力を待たせず進んだ。通常の時間再生と停止は実際の3秒タイマーでも確認した。

実機iPhoneの温度、消費電力、Safariのcompositor負荷は測定していない。発熱改善/無影響とは断定しない。

## 6. 作者が比べる場面

各方式で「最初から」を使い、同じ操作をする。切替だけで動きの再上映はしない。

1. 標準条件でレストランへ果実香2本。手札6→4、棚0→2の両方へ目が向くか。
2. 1か月進める。棚が1本になり、手札は変わらないことが分かるか。
3. もう1か月。空の棚と3本の再注文に気づき、次に渡す一本を考えられるか。
4. 最初から、レストランへ煙、酒屋へ樽香を各2本。1か月目は酒屋だけ減る。変わらない店に余計な動きがない方が見やすいか。
5. 少量条件で1本だけ渡す。0本カードが通常手札から外れ、履歴製法と熟成中の樽を使えるか。
6. 連続進行→停止→再開。画面は静かでも、停止中と進行中を読み分けられるか。Cを動きを減らす設定でも比べる。

## 7. 必要だった表現と、次の課題

瓶と空の棚は、既存の数量を別の見え方で示すために必要だった。注文印は「対応できるもの」を棚と同時に見つけるために置いた。常時点滅・客の歩行・完了待ち・通知一覧・瓶一本ずつの長い運搬は不要だった。

アニメーションが本当に必要だったかは未確定。Bでも状態はすべて伝えられ、Cの追加は注目の補助に限る。Cの動きを見落としても次の選択は失われない。作者がBだけで十分と感じれば、Cは採用しない判断ができる。

何も変わらない月は静かなまま。時計/樽の実月齢と、店に残る瓶を同時に見て「時間に任せている」と感じられるかは試遊待ち。説明や装飾で活動を捏造しない。

熟成へ応用するなら、実月齢・試した時の風味・前回との差分を必要な箇所だけ更新する考え方は使える。一方、元の月齢は参考であり完成期限ではない。progressを削った以外、今回の貯蔵庫は作り直していない。風味変化の見せ方は次の実験に残す。

瓶の上限3本表現が数量を誤解させないか、短いラベルが増えて窮屈でないか、Cの移動で目が疲れないか、長い銘柄/注文で時計までスクロールが必要になる場合、実機Safariでの発熱・触感を確認したい。本編への統合・Production公開は行わず、作者の試遊評価を待つ。
