# 手札と場 Lab 0.3 — 一本へのさまざまな反応

取扱いの成立と、店主自身の好みを分けた独立Lab。紹介した一本にどんな返事が返り、それを見て次を試したくなるかを確かめる。反応の数や取扱い成功率で楽しさを認定しない。

基準main `dc58d560740717161e3ba042a71a1e69b8392963`（PR #624）。AGENTS、Change OS、表現監査、v02のレポートと実装、既存の風味・取扱店・口コミLabを確認。`.change-plans/ambertime-hand-place-v03/r0.lock.json` を実装前に固定。v02・本編・既存の風味計算・保存・Productionは変更していない。

## 1. v02との差分

- 3枚と3店の画面、選ぶ→店→出す、棚への残存、維持／入替え、仕込み・熟成・瓶詰めを維持。
- 反応Aはv02の相性による二択を保持。B/Cは取扱いを広く受け入れ、その上で店主の感想を返す。
- Cだけ、実納品後の客の様子を一度だけ返す。毎月の新しい通知一覧や別の履歴画面は作らない。
- 店主と客の様子は既存の返事表示と棚へ。店を選ぶと元の店主の返事と後から分かった様子を読み返せる。
- 反応比較A/B/Cと、従来の配置条件A自由／B翌月確保を別の設定として保持。画面にも「配置A / 反応C」のように区別して表示。

## 2. 最小の反応モデル

既存の `profile` には果実・麦・煙・厚み・刺激・木・バニラ・スパイスがあり、発売回には月齢・樽・原酒香の種類がある。新しい風味計算は不要だった。

v02の相性は3軸を中心に一部の香り種別も参照するため、「食堂のヒントは果実なのに煙も合う」などの制約がある。今回、Lab内の返事だけで既存の煙成分・樽影響・月齢を直接参照する。従来の相性式や値は変えない。

店主の返事は一つのオブジェクト：`accepted`、短い文章、主な理由、任意の希望。分類名はログと検査のためで、UIへランクとして表示しない。希望は `same` または `younger` の二つだけ。

| 条件（B/C、上から適用） | 取扱い・返事 | 根拠 |
| --- | --- | --- |
| バー、樽影響>0.45、72月以上 | 今回は見送る。原酒香が前に出る一本を扱いたい | 店の方向、実際の木/バニラの最大値、月齢 |
| 食堂、煙>0.45 | 普段は煙の少ないものを選ぶが、食後の一本として置く | 煙の成分と食堂の用途 |
| その他の樽影響>0.45、72月以上 | 扱い、同じ製法の若い一本にも興味 | 樽の影響と実際の熟成月数 |
| バー／専門酒店、煙>0.45 | 自分は好き。同じ一本をまた希望 | 煙の成分と店の方向 |
| 従来相性が低い、上記以外 | 普段と違うが少し扱う | 従来の最も離れた軸と、その強弱 |
| その他 | 普通に扱う | 原酒香の種類と店の用途を短く述べる |

閾値はこのLabの少数の会話条件で、普遍的な味覚・科学的な閾値ではない。新しい点数、客層、取扱いランクはない。初期3枚×3店のB/Cは8組が取扱い可能だが、それを改善点数としては使わない。見送りを減らすだけで体験が成立したとは言えない。

## 3. 希望を増量・課題にしない

「同じ一本をまた」は店主の希望の言葉として残す。毎月の注文は従来通り各店2本までで、希望による追加発送・自動増産・売上加点はない。プレイヤーはそのまま扱い続けても、再仕込みしても、別の味を試してもよい。

若い一本への希望も達成条件ではない。元の製法で再仕込みし、早めの月齢で瓶詰めする既存操作を使えるだけ。若くしたことで必ず好評になる規則や報酬はない。無視しても不利益はなく、元の取扱いも続く。

## 4. 翌月以降の客の様子

反応Cでは、実際に取扱いを確定し、その元の発売回が実納品された翌月以降に、次の少数例を一度だけ返す。

| 紹介時の条件 | 後から分かる様子 |
| --- | --- |
| 食堂が煙を好みと違うが扱う | 食後に飲んだ客は煙の香りを面白がった |
| 専門酒店の店主が煙を気に入る | 強く感じる客もいて、ゆっくり出ている |
| 長期の樽香を扱い、若い一本にも興味 | 飲んだ客からも、同製法の若い一本への関心 |
| 普通の取扱いなど上記以外 | 新しい返事なしで静かに続く |

これは客の売れ行きを別計算した結果ではなく、実納品を入口とする小規模な試遊用の事例。棚の「客の様子」は店主から聞いた報告であり、客本人の台詞や実測の販売データではない。出荷2本を客が2本買ったことにしたり、新しい需要曲線を持たせたりしていない。

実納品のない店、未確定の提案、見送った紹介から客の声は発生しない。反応Bは紹介時だけ、Aは従来の二択だけ。まだ起きていない返事はUIに出さない。

## 5. どの紹介から起きたか

追加状態は次の最小範囲にした。

| 状態 | 用途 |
| --- | --- |
| `responseMode` | A/B/Cの比較条件 |
| `introductions` | 店×元発売回の紹介番号、時点、店主の返事、確定・終了時点、後の返事一つ |
| 取扱いの `introId` | 今の棚がどの紹介から始まったか |
| 入替え待ちの `introId` | 提案中の返事を、現在の棚と混ぜない |
| 納品・返事の `introId` / 発売回ID | 実納品と後の返事の出所 |

後の返事専用キュー・通知一覧・既読状態・店主と客それぞれの評価値は作っていない。同じ店へ同じ発売回を再提案しても、紹介の記憶を再利用し、同じ客の出来事を増やさない。一度棚から外して戻しても、既に分かった客の様子を再抽選しない。

入替えはv02通り確認後に確定。旧紹介は終了し、旧商品の未発生の返事が新しい棚に出ない。「今の一本を続ける」や見送りは旧棚を保持する。

同製法・同月齢の自動補充は同じ取扱いを続けるが、会話の元発売回は固定。新しい発売回へ自動更新しただけで、新しい客の話を生成しない。棚と返事には対象の発売回番号を表示し、店を選ぶと店名・元の名前・発売回・紹介番号を確認できる。元の返事が生まれた時点は記録へ残し、後の再紹介で書き換えない。

## 6. 画面と操作

画面はv02の配置を保ち、店の棚の下に短い返事を最大2行で表示。長い文章は店を選んだ際に既存の返事欄で読む。店主の言葉、客の様子、プレイヤーによる維持／置換、在庫不足の操作結果を同じ話者として表示しない。

紹介時は返事と棚の変化。後の様子が分かったときは棚と既存の返事欄を更新する。複数店で同時に分かった場合、返事欄は一件、各棚にはそれぞれの様子が残る。新しいポップアップや通知パネルはない。

手札や店の選択、製法確認、再仕込み、月齢を変えた瓶詰め、翌月納品、共有在庫、確保・解放、時計開始停止、hidden時の停止、キーボードフォーカスを維持した。

## 7. 比較結果

固定シード42、同じ初期3枚・3店・同一操作列で比較した。各配置条件でA/B/Cを別々に実行する。操作列：果実香→食堂、煙→食堂へ入替え、煙→バー、樽香→専門酒店、樽香→バー、3か月進行、樽香から再仕込み。入替え確認も全条件で同じ操作。

| 配置 | 反応 | 煙の在庫（3月後） | 樽香の在庫 | 後の返事 |
| --- | --- | ---: | ---: | --- |
| 自由 | A 従来 | 0 | 12 | なし |
| 自由 | B 紹介時 | 0 | 6 | なし |
| 自由 | C 後の様子も | 0 | 6 | 食堂の煙、専門酒店の樽香について各1件 |
| 翌月確保 | A 従来 | 0 | 12 | なし |
| 翌月確保 | B 紹介時 | 0 | 6 | なし |
| 翌月確保 | C 後の様子も | 0 | 6 | 食堂の煙、専門酒店の樽香について各1件 |

A/Bの数量差は、専門酒店が樽香を扱うかの差。B/Cは取扱いと発送が完全に同じで、後の情報だけが違う。Cで返事が増えても自動的に注文が増えるわけではない。どの条件が楽しいかは未判定。

別の固定ログでは、同じ煙を食堂と専門酒店へ紹介し、1か月後の「店主と客で好みが違う」二方向の例を確認できる。在庫が他店で尽きて元の一本が一度も届かなければ、その店から客の返事は出ない。これは品切れを客の評価へすり替えないための境界。

## 8. 操作ログと検証

v02同様に操作の再実行とチェックサムで全結果を照合。v03専用schemaで、既存の保存やログ形式は変更しない。比較条件、選んだ一本と店、紹介前後の手札と棚、返事と主な理由、確定／見送り、納品の元紹介、後の出来事、その後の実操作を残す。全月の手札コピーや反応データの二重保存は避ける。

付属ログ：`tests/seed42-{A,B,C}-{free,reserve}.json` の6条件、`tests/seed42-customer-contrast.json`。`tests/comparison.json` に結果を整理。いずれも「ログを再現」で読める。生成は `node works/ambertime/experiments/hand-and-place/v03/tests/scenarios.mjs`。

検証済み：

- モデル14件：Aのv02一致、B/C即時反応の一致、6事例、納品・翌月の条件、普通の取扱いの静かな継続、確定前／維持／旧紹介の抑制、同じ提案の重複防止、複数店の出所分離、共有在庫、予約、再仕込みと自動補充、再紹介後も元時点を保つ検査、遅延を含むログ再現・改ざん拒否。
- Lifecycle24件、LAB生成・check、構文、Scope→Risk→Impact。
- 対象ブラウザ：360/375/390pxの初期3店＋3枚、768pxの横はみ出しなし。紹介時の6事例、店主／客の表示、維持／置換、翌月後の出所、同じ返事の非反復、A/B/C切替と配置条件の分離、再仕込み・25か月の工程・瓶詰め、時間開始停止、時計／カードのキーボードフォーカス、ログ書出し・読込。JS/HTTPエラー0。
- 実装担当以外のUI/APIレビューで、店主の客の報告を客本人の台詞に見せる表示と、操作結果への誤った話者付けを修正。自動補充後も元の発売回を明示した。モデルは別担当の実装をメインが差分と境界テストで確認。
- 表現監査6点：話者と対象が分かる短い返事を優先。新しい説明パネル、物語、品質表現、作られた感情の総括、ミッションや達成コピーを追加しない。店主の好みと客の様子は試遊モデルとして明記。

必須CI・最終公開SHA・公開配信のバイト照合と基本操作はPRへ記録する。包括E2E、実機Safariの触感、楽しさの自動認定は行わない。

## 9. 作者が試す場面

| 場面 | 操作 | 見たいこと |
| --- | --- | --- |
| 普通に続く | 果実香を食堂へ | 特別な返事が増えなくても取扱いが続くことに納得できるか |
| 好みとは違うが扱う | 煙を食堂へ | 「合わない＝置けない」という正解探しから離れられるか |
| 気に入られ同じ一本を希望 | 煙をバーへ | また造る理由になるか。義務には感じないか |
| 若い一本への関心 | 樽香を専門酒店へ | 元の製法から早めに瓶詰めして試したくなるか |
| 予想と違う客の様子 | 煙を食堂と専門酒店へ、翌月へ | 自分の紹介と後の話がつながって見えるか |
| 今回は見送り | 樽香をバーへ | 棚を失わず、理由を理解して次へ進めるか |

反応Cの次にBへ切り替え、後の返事が本当に必要だったかも比べる。設定変更は最初からになるため、残したい試遊は先に書き出す。

## 10. 残る課題と引き算

必要だったのは、取扱いと店主の好みを分けること、後の話を元の紹介へ結びつけること。別々の大規模な店主評価・客評価は不要だった。追加状態は紹介の記憶と一件の後日談に集約した。

一方、現在の客の様子は少数の条件付き事例であり、実際の売れ行きの計算ではない。短文だけでは意外さに納得できない場合、客層パラメータを足す前に、条件や返事を減らして確かめるべき。希望の言葉が指示に見えないか、毎回の返事確認が増えていないか、棚の2行表示で出所が分かるかも実機評価が必要。

この段階では街への広がり・新しい口コミ・長期人物関係へ進まず、作者の試遊を待つ。本編・既存Lab・保存・Productionへの統合は行わない。
