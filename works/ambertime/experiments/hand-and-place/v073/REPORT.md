基点main：`f71a0cd7895b23e5d39e0fccfe0153da010e8f80`（PR633）。v072の数値配分と同じ結果を、量を選び、瓶の行き先をタップして仮置きする操作で比べる独立Staging Lab。本編・既存Lab・保存・Productionは変更しない。

## 1. 変えた操作

瓶棚・本編の瓶/樽/店舗ドット絵、美咲フォント、矩形と配色を引き継ぐ。小窓上部に瓶、短い名前と発売回、年齢、現在使える本数を表示。行先は自家販売・レストラン・酒屋の3つ。各行先の店舗iconと代表瓶1本・数量を使い、実本数分の瓶DOMを並べない。カード盤面にはしない。

本数を選んで行先をタップすると、仮手元からその量だけ加わり、瓶が短く収まる。同じ行先への連続タップは加算。取扱店→店→商品も同じ小窓と確定handler。主操作から3つの数値欄を外し、補助入力と希望全文は「個性と仕込み」の中へ折り畳んだ。最後のprimaryは「これで決める」。結果は同じ窓の一文1か所だけで、新しいpopupはない。

## 2. 量の仕様

| 選択 | 次のタップで置く量 |
| --- | --- |
| 1本 | 1本、残り0なら0 |
| 2本 | 2本、残り1なら1 |
| 半分 | その時点の仮手元の半分、端数切上げ |
| 残り全部 | その時点の仮手元全部 |

半分は選択時の固定値ではない。6本から半分を選んで3行先へ順に置けば3→2→1になる。上限を超える量は仮手元まで。残り0のタップは履歴もmotionも増やさない。

## 3. 仮置き・取消・分け直し

開いた時は自家販売が現在の未販売数、2店は今回の納品0。手元＋未販売だけが使える総数。仮置き、取消、元の配分、分け直しは純粋なUI helperで、modelを呼ばない。

「取消」は直前の配分操作1回を戻す。「元の配分」は開いた時の未販売数/店0へ戻す。「分け直す」は3行先を0にして全数を仮手元へ戻す。元の配分/分け直すも1回の仮操作として取消可能。量選択だけは取消履歴へ入れない。閉じる・戻る・Escapeは未確定の仮置きを捨て、state/commands/actionsを一切変えない。

手元3/未販売3から未販売1・レストラン2へは、分け直す→既定1本を自家販売→2本を選ぶ→レストラン。専用の「未販売分から渡す」source選択は復活させない。補助数値経路は開く/2つの折畳み/2入力/確定で6操作、仮置き経路も開く/分け直す/自家販売/2本/レストラン/確定で6操作。通常の手触りを保てる後者を主経路にした。数値方式より少手順とは扱わない。

## 4. 安全性

`app.mjs`は`../v072/model.mjs`を直接importし、新しいmodelもschemaも作らない。ゲーム変更は最後に既存`allocate-all`を一度だけdispatchする。途中のdraftは`draft.mjs`に隔離。原子性・整数/合計残高・店舗/希望ID・売却済み/納品済み保護・検証成功時だけ一括commitはv072そのまま。実納品した分は確定後戻せない。自家販売を減らす時と実納品時だけ必要な注意を表示する。次に開くと店は再び0。

任意数値欄は3つのraw値を一括検査する。不正欄が1つでも残れば確定不可、他行と最後の有効な仮置きを保持する。正しい一括変更だけ1取消履歴にする。入力中のDOM/focusは同一。数値詳細を残すために初期画面を長くしない。

店の短い希望は実際のopen order.reason/textから作る。初期は食後に出せる一本/店頭で紹介する一本、以降は前と同じ・軽い味・同製法で若いもの・別の一本など、モデルにある希望だけ。数量と全文は必要な時に確認できる。架空の会話や正解誘導を足さず、希望と違う味も既存ルールで実納品できる。

## 7. motionと負荷

仮置きで代表瓶だけを240ms、6px落として収める。入力をロックせず、同じ行先の先行motionを即cancelし、同targetの保留を積まない。初期表示・replay・noopに仮置きmotionはない。reduced-motionでは数と瓶濃度の静止変化だけ。hidden、閉じる、scroll、resizeで停止し、viewport外/小窓body clip外は開始しない。常時RAFや新しい時計は作らない。

rapid同targetの実測では同時motion最大1、終了後0。draft中のrender回数/棚objectCreatesは不変、数とariaと小要素だけ更新する。確定後のmodel event motionも同要素1回。時計は既存1個のsetTimeout、小窓を開く/hidden/pagehideで停止。

Hの30本はhelper/browserだけのUI fixture。15/2/13へまとめ、表示中の代表瓶DOMは前後3個、native sessionは完全不変。通常の初期数/瓶詰め6本を増量しない。30本の反応はまとまり単位で、30個のanimationを作らない。発熱・電力・物理端末の長時間性能は未確認。
