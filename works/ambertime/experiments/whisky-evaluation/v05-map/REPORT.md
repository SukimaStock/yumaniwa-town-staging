# AmberTime マップ Lab 0.5「町の地図に評判が現れる」

2026-10-30。着手時main `f8189d08691daf59af14b0c2858bec353829db0a`。v03の販売・在庫・購入評価・店の記憶を変更せず、蒸留所側から把握する管理情報を地図へ投影する独立Lab。本編・旧Lab・保存形式・経済・Productionは変更しない。

## 今回の体験

販売室で手元の瓶を選び、1本・5本・全部を店へ仮置きし、最後に確定する。時間を進めると実売と購入評価が返る。必要なときだけ「マップ」を開き、店の位置・数字・印を見て、店を選ぶと報告が開く。「販売室へ」で戻り、次の一本を試せる。

マップは時間送りのたびに強制表示しない。開閉・範囲変更・店選択・表示案の変更はUIだけで、時間・販売・在庫・支持・保存を進めない。店内を常時描画せず、数字は管理記録、客の反応は店から届いた報告として扱う。

次の試作はv02/v03と同じく熟成済みの比較用5本を用意する。製造費・熟成を待つ経営・地域伝播を追加したものではない。

## 店のID・仮配置・タップ

既存 `world-map-view.mjs` のmarker座標と、背景の建物中心には差がある。これを今回の正式位置変更として修正せず、Lab専用overlayを別の `PIN_POSITIONS` に持つ。表示中にも「3店はLab仮配置。範囲は比較用です。」と明示する。

| Lab店 | 近所のnative座標 | 町のnative座標 | 仮配置の根拠 |
| --- | --- | --- | --- |
| 専門酒店 | 102,46 | 94,52 | 既存liquor建物の中心を借りる |
| 食堂 | 114,106 | 106,100 | 既存super建物の中心を借りる。正式にスーパーを食堂に変えない |
| 町のバー | 48,52 | 30,56 | 近所は草地の試験pin、町は既存汎用家屋の中心。本編barではない |

特にバーの販売計算は、v02からのLab仮説で `retail` に対応する。本編のTown Simulationにあるbarノードや正式なバーの店舗位置と同一視しない。食堂＝supermarket、専門酒店＝town-liquorという販売式の対応も継承するだけで、本編のID・店名・位置・契約を変更しない。

Canvasはsource144pxのまま、通常288px、店選択時216pxで表示する。1 nativeセルはそれぞれ4px/3pxになる。Canvasと操作overlayは同じ正方形の親を共有し、markerの中心とDOMボタン中心を `x/144*100%` / `y/144*100%` で合わせる。文字のバッジは建物を覆いすぎないよう上下へずらす。markerの44px操作対象に加え、数字・店名のバッジからも同じ店を選べる。

背景の店らしい建物はnativeの情景の一部であり、全てが取扱店であるという意味ではない。**Labの確定納品履歴がある店だけにoverlayの印が付く。** 未納品・仮置きだけでは付かない。回収後も以前に納品した履歴の印は残るが、残数は0となり「取扱中の在庫がある」とは表現しない。

## 数字・報告・記憶の意味

`mapFor(session,stage)` はread-onlyの純粋関数。マップに表示する事実をv03から導き、計算へ戻す経路を持たない。

| 表示 | 根拠と期間 |
| --- | --- |
| 売N | その店の全商品の、Lab開始からの実売累計。納品本数や支持率ではない |
| 残N | その店の全商品の、現在の店頭在庫。未確定の仮置きは含めない |
| 好む客の報告 | 最近納品した商品の、その店で実際にlike/strong評価があったこと |
| 前の一本 | v03の反応が、過去に実売した別の商品を参照していること |
| 店頭あり・販売記録・納品済み | 現物在庫、実売、確定納品の事実を区別する補助表示 |
| 店の短い反応 | 最近納品した商品に対するv03 shopViewの実際の反応 |
| 好評からの期待 | v03の正の実購入評価から生じた見本の商品名・年数。未観測の個人嗜好から要求を作らない |

全商品累計と、最近納品した一本への購入者の評価は分ける。店の詳細には現在の全商品・残数を列挙し、「最近の納品：味・年数／この商品の累計評価N件」と出典を示す。同一商品の回収・再納品でも、それ以前の評価は消えないため、「今回納品した瓶だけの評価人数」とは説明しない。評価件数は同じ客が再び選ばれる場合もあるv03の事例数で、必ず異なる実人数とは限らない。

購入者の反応は、その店で売れた実瓶の評価文だけを選ぶ。新しい商品を置いただけでは、以前の商品の好評を新商品の好評へ転写しない。正の評価がない商品を好評にしない。否定的な印象も記憶には残り得るが、好意的な支持として加算しない。

マップ用投影にはprofile、target、weights、score、fit、maturity、ageInterest、支持・認知の内部値等を含めない。開いた店の報告と、実売から分かる記録を渡す。v03形式の完全JSONや計算詳細は、販売室の開閉式の検証領域として別に維持する。

## 3つの視覚案

同じ状態の同じ店を切り替える。初期表示Aは採用確定ではない。

| 案 | マップ上 | 選んだ店 |
| --- | --- | --- |
| A 数字中心 | 短い店名、売N・残N | 在庫、購入者の反応、過去の一本、期待の出典 |
| B 印中心 | 状態の印だけ。凡例を付ける | 数字を含む同じ報告 |
| C 数字＋短い反応 | 売Nと、一つだけ重要な状態 | 同じ報告 |

Cの優先順は、最近納品した商品を好む客の実報告→前の一本への参照→現在庫→販売記録→納品。すべての変化を同時表示しない。Bの印は突起・上線・縦線・横線で区別する。印が自然に読めるかは作者の確認事項であり、数式が正しいことでは判断できない。

文字量の多いCを自動採用しない。Aは数が分かる反面、地図を覆う面積が増える。Bは地図を残しやすい反面、意味の学習が要る。Cは変化を拾えるが、優先順で隠れる情報がある。これらを同じ履歴で比較する。

## 操作と4経過

v03のSCENARIOSと、v04の `timeline.mjs` を変更せず利用する。A同じ味、B少しずつ変更、C方向転換、D以前の味への復帰を、同じ初期状態・seedで再生する。

各発売について、納品直後／元のadvance6による販売後という10個の実状態を保持する。月次操作を独自に分割してv03の履歴を変えない。地図を開いたまま前へ・次へで比較でき、店の選択も維持する。過去のフレームには後の実売・評価・期待を持ち込まない。

再生の状態から手動操作・JSON読込・初期化へ進むと、古い再生を解除する。地図の選択店、表示範囲、表示案はUI状態であり、v03 JSONには追加しない。同じJSON・同じ範囲・同じ案なら同じマップになる。

## 修正と表示確認

- 独立レビューの指摘に合わせ、再納品した商品も以前の評価を持つ意味が分かるよう「この商品の累計評価N件」とした。
- 少し離して置く店名・数字のバッジからも店を選べるようにし、markerだけを正確に狙う必要を減らした。キーボードと読み上げには元の44px店ボタンを使う。
- 期待の見本に同じ味・年数が複数ある場合、表示文の重複だけをまとめる。別商品IDの記録やv03の重みは削除・合算しない。
- 選択時の地図は216px、報告は下側のスクロール領域とし、地図を情報窓で覆わない。比較中は報告の高さを128pxまでとし、前へ・次へを画面内へ残す。長い報告はその領域内で読む。

ローカルの360×568、375×620、390×680で近所／町・A/B/C・選択／未選択・Dの10時点を操作した。横幅とscrollWidthはそれぞれ360/360、375/375、390/390pxで一致。360pxのB・町・過去の反応・再生操作を同時に表示してもdocument高さ568pxに収まった。未納品では印0、3店へ確定納品後は印3、0か月のまま売0/残1の報告が開くことを確認した。

375pxの町のバーでは、地図左79.5／上118.1875、幅216px、店ボタン中心124.5／202.1875だった。native座標30／56を同じ矩形へ換算した値と一致し、ボタン44×44pxを確認。地図開閉の前後は31か月のまま、描画カウンターも15→15で、同じ状態ならCanvasを描き直さなかった。

最終公開版のログ保存・再読込と基本操作は、必須CI・Pages成功後にStagingで確認し、確認SHAと結果をPRへ追記する。実機Safari、OS設定によるreduced-motion、端末温度は未確認。formal verificationStateはUNVERIFIEDを維持する。

## 描画負荷

Canvasの背景と小さいmarkerは、地図を開いたとき、内容・範囲・案・選択店が変わったときだけ同期描画する。投影keyが同じなら再生成しない。地図を閉じた状態ではpaintMapを呼ばない。常時RAF、interval、map表示による月次処理を追加していない。地図自体のアニメーションはない。販売室の既存の有限240ms反応だけを維持し、reduced-motion・hidden・pagehideで停止する。

Nodeホストで投影2段階＋DOM文字列6案＋照合処理を含む12,000回は中央値4.43ms、P90 13.20ms、最大315.98ms。これはassertや保存照合を含み、iPhoneのpaint時間・FPS・温度ではない。ローカルブラウザーの一例でCanvas＋overlay生成0.4msを観測したが、端末性能の保証とは扱わない。

## 残る課題・作者の確認点

- バーは近所では空地の仮pinで、本編の建物を追加していない。正式位置を決める検証ではない。
- 固定3店・固定2範囲のため、全国へ広がる体験や本編の解放速度を検証したものではない。今回の「広がり」は納品先と実売・報告が町の管理情報に現れる範囲である。
- 累計売は長く遊ぶと増える。これを評判ポイントや現在の人気へ読み替えない。月別や最近の期間を主表示にするかは別の表示方針として検討できる。
- Bの小さい印、バッジの位置、報告内のスクロールが自然かは試遊事項。凡例を読まなくても分かると断言しない。
- v03の支持・期待の減衰、少数の評価の揺れ、v02のバーの販売量優位は継承した。今回の地図で販売バランスを解消したとは扱わない。

作者には、A「町の取扱状況の変化を見る楽しさ」、B「店を選んで過去の評価や期待を読む意味」、C「販売室との往復と数字・印の量の自然さ」を同じ経過の3案で比較してもらう。面白さが計算で証明されたとは判断しない。本編への採用、地域拡大、世代交代は試遊結果を確認してから検討する。
