## 店の記憶と現在の関係

店ごとに独立した記録を持つ。別の店の記録は、その店の支持・期待・反応の根拠にしない。

| 要素 | 保存する事実・現在値 |
| --- | --- |
| 受領記録 | 商品ID、製法、年数、風味、受領本数、初回・最終受領月。回収も移動として記録 |
| 購入記録 | 実売本数、実購入評価、支持・強い支持・不一致、正負印象、好評／不一致の風味、熟成への反応、最終実売月 |
| 認知 | 実際に受け取った商品による現在の認知。購入支持とは別 |
| 現在の支持 | 正の実売証拠と負の実売証拠を分けて集約した現在値 |
| 期待 | 好評だった複数の商品を、別々の風味・年数の見本として保持 |
| 過去の記憶 | 実売評価と、その時点の文脈評価・反応・参照商品を保持 |

置いた時点では認知と受領記録だけが生まれる。客が飲んだという反応、好意的支持、正の期待は発生しない。実売1本に1評価事例を対応させるv02の仮説を維持する。同じ潜在客が複数回選ばれる場合があるため、評価件数を実在する異なる人数とは表現しない。

同一商品の回収・再配置では、受領累計が増えることはあるが、認知の量的寄与は1商品につき元の5本までで打ち止めになる。実売・評価・支持は複製されない。実際の再取引で最終取引月が更新されることと、新たな好評を得ることは分ける。

## 新しい計算仮説

以下の係数と半減期はゲームの独立Lab仮説であり、実際のウイスキー市場や人の記憶を推定したものではない。

発売回 (r) の支持件数を (l_r)、強い支持件数を (t_r)、不一致件数を (b_r)、実売本数を (n_r)、最終実売からの経過月を (d_r) とする。強い支持件数は支持件数に含まれる。

\[
G=\sum_r\frac{l_r+0.5t_r}{7.5}2^{-d_r/72},\quad
B=\sum_r\frac{b_r}{5}2^{-d_r/72},\quad
支持=\frac{G}{4+G+0.5B}
\]

各商品は5本なので、1発売回の正・負それぞれの寄与は最大1である。納品操作や月次処理の回数を好評の点数にしない。正の証拠がなければ支持は0であり、強い否定的印象だけでは支持が増えない。

同じ時計の時刻で過去の正の証拠を固定すれば、新しい最悪の1発売回を加えても支持は元の8/9以上に留まる。これは数式の境界であり、長期間待つことによる減衰まで含めた下限ではない。実際の時間比較では、経過時間の減衰と新しい評価の寄与を分ける。

認知は、各発売回の受領量を5本までに制限し、120か月の半減期で減衰した合計 (A) から `1-exp(-A)` とする。支持と同じ値にしない。

期待の見本は、少なくとも1件の好意的評価が実際にあった商品だけから作る。

\[
w_r=\frac{l_r+0.5t_r}{n_r+2}2^{-d_r/36}
\]

煙の強い一本と軽い一本を平均して、未販売の第三の「バランスの味」を期待したことにはしない。各見本を残し、新商品とそれぞれの相性を計算する。好評だった新しい味は別の見本として加わり、少数の好評には小さい証拠量が対応する。

相性は8風味軸の平均絶対距離と、年数の対数差から算出する。

\[
相性(r,p)=\exp[-4(0.85\times風味距離+0.15\times年数距離)]
\]

年数距離は `abs(log1p(r.years)-log1p(p.years))/log(21)`。現在の商品自身と同月・未来の評価は期待の参照に入れない。

## 記憶が今回の受け止め方へ効く部分

今回実売した評価群の平均を `intrinsic`、その中の好意的評価率を (q) とする。過去の正の期待見本との相性の加重平均を (F)、見本の総重みから求めた `1-exp(-sum(w))` を (T)、今回想起した過去の好評商品との相性と想起の強さを (R) とする。

\[
補助値=q(0.04FT+0.01R),\quad
店の文脈評価=\min(1, intrinsic+補助値)
\]

補助値は最大0.05で、今回の実購入評価が全て中立・不一致なら0になる。想起した商品が悪い印象の記憶なら、その商品由来の (R) は0。別の好評見本が期待へ寄与する場合は、その商品ID・重み・相性を別に保存する。補正前の平均、補助値、補正後の値を保持するので、上限付近でも差を失わない。

期待との距離そのものに負の点を付けない。方向転換による固定減点はない。新商品の客評価が低ければ新しい負の証拠が加わる一方、高評価なら正の証拠と期待の見本が加わる。客のv011評価は、店の文脈評価が上がっても書き換わらない。

文脈評価は実売の時点で保存する。後の商品を売ってから以前の商品を選び直しても、その商品の過去の評価へ未来の記憶を混入させない。同月の複数商品の処理は月初の記憶を共通に使い、行の処理順で先に売れた商品が有利になることを防ぐ。

## 3つの記憶モデル

想起の強さは、実売量による信頼量 `n/(n+2)` と120か月半減期に、次の信号を組み合わせる。

| モデル | 想起の信号 | 副作用・区別 |
| --- | --- | --- |
| support／初期表示 | 強い支持件数／実売本数 | 強く好きだった一本を残しやすい。広い弱い好評は相対的に目立ちにくい |
| impression | 正負を含む印象の平均 | 悪い印象も残る。その記憶を好評や正の期待へ変換しない |
| repeat | 相性.85超の別の商品を扱い、実売があった回数 | 継続した似た味が残りやすい。同じ物の回収・分割納品では増やさない |

全モデルに基礎の想起信号.2を残し、信号部分.8を加える。想起候補は、過去の実売がある別商品だけとする。候補の相性と想起の強さから選び、同値なら最終実売月と商品IDで決定する。

3案は「どの過去商品を思い出すか」と文脈補助値の一部を比較する。実際の販売・売上・客評価・支持の証拠を変える案ではない。勝率を均等にするための係数調整は行わない。

## 検証と修正

本体12件、独立レビュー3件、全CSV・記録・空白・保存例の結果テスト4件、計19件が成功した。旧v02の15件も変更せず再実行し成功した。受領だけの状態、店別独立、v02の全状態一致、空白中の記録不変と現在値の減衰、正負証拠、復活の文脈効果、厳密なJSON再現、保存失敗時の原子的保護、反応の因果参照を検証している。

独立レビューでは、同月の複数商品を逆順に処理しても記憶が変わらないこと、一度の最悪の発売で既存の正の証拠が消えない境界、「若い」と述べる反応に実際の年数差と前後の好評証拠があることを追加確認した。

実装中に見つけて修正した問題：

1. 店情報APIの別名の不一致を統一し、画面・比較計算の参照値を揃えた。
2. 製法の同一判定をJSONのプロパティ順に依存させず、麦芽・発酵・採取区間・樽・年数の固定順へ変更した。保存時のキー順が違うだけで「違う味」と説明しない。
3. 期待の見本を表示用に保持するだけだった構造を改め、期待の複数見本を文脈補助値へ実際に入力した。全参照商品・重み・相性を保存し、否定的な想起商品と正の期待の出典を分けた。

これらは100seed計算を始める前に修正・再テストした。計算途中で記憶投影とチェックポイントを使う同条件の高速化へ切り替え、初期の遅い実行を停止して100seedを再開始した。数式や比較条件を変更する調整ではなく、全操作との固定部分対照を通す検証コードの変更である。旧Labの係数やテスト期待値は変更していない。

## 残る課題

- 過去の正の評価が少数なら、店全体の確定した好みとは言えない。通常文は実際に「好む客がいた」範囲で記述する。
- 証拠の減衰は**発売回の最終実売月**を基準にする。最後の古い1本が売れると、その発売回の集約された証拠全体の時刻が更新される。各購入者の評価を個別の時刻で減衰させるモデルとは異なる。1発売回の寄与は上限1で、未販売の瓶を再配置しても好評は増えないが、記憶が再び現在へ近づく扱いにはこの仮説が含まれる。
- 期待を複数残すため、長く試作すると候補が増える。今回は5回中心の比較で、無制限の長期関係の容量や世代交代は検証していない。
- 記憶の補助値は小さく、販売を有利にする報酬ではない。言葉と履歴に気付けるか、次を試す意味が変わるかは作者の試遊事項である。
- バーの販売量優位、専門酒店の低い販売機会、少数評価のばらつきはv02から引き継ぐ。今回の記憶でこれらを解決したとは扱わない。
- Dで以前の製法へ戻しても、通常の短文が必ず復活した商品を選ぶわけではない。想起は相性だけでなく強い支持・印象・時期から1件を選ぶため、最近の別の味に触れる場合がある。以前の同製法は期待の見本群に残り、数値の参照先にはなり得るが、プレイヤーに「戻した意味」が伝わるかは別の確認事項である。
- 3案の計算上の差が確認できても、どの残り方が自然か・自由に造れるかの採用判断には試遊が必要である。

## 再現方法とログ

```sh
node --test works/ambertime/experiments/whisky-evaluation/v03/model.test.mjs works/ambertime/experiments/whisky-evaluation/v03/review.test.mjs
node works/ambertime/experiments/whisky-evaluation/v03/run.mjs
```

`results.json` は固定seed、比較条件、分布、空白比較、反応例を保存する。`comparison.csv.gz` は全発売後観測、`gaps.csv` は空白比較、`example-log.json` は操作履歴を持つ実試遊の再現例である。これらは実行コードから生成する。画面ではJSONと購入CSV・記憶CSVを分けて保存する。

購入CSVは実売の行なので本数・売上を合算できる。記憶CSVや比較CSVはその時点の累積状態を含むため、異なる観測月の売上や件数を合計しない。JSON読込は初期状態から同じ操作を再実行し、店の記憶も含む全状態の一致を要求する。

## 作者が試遊する3点と次への引継ぎ

1. **店が覚えている実感**：前の一本への言及や店情報の記録で、同じ店との関係が続いていると感じられるか。
2. **次の一本への動機**：同じ製法を続ける、新しい味を試す、昔の味へ戻す、のいずれかを自分から試したくなるか。
3. **自由な方向転換**：期待へ応えることが義務にならず、好きな味を造り続けられるか。期待外れの減点がなくても、言葉だけで圧力を感じないか。

今回の数値だけで面白さ、意欲、自由さが成立したとは判断しない。作者の試遊結果を受けて、言葉・記憶の残り方・期待の見せ方を見直す。

将来の地域拡大へ渡せる候補は、実売に根拠のある正負の評価、支持の幅と強さ、想起商品、期待の見本と重みである。受領1件をそのまま遠方への抽選機会や全国的支持へ変換しない。世代交代へは、過去の固定記録と現在の減衰した関係を分けた構造を渡せる。ただし、新しい世代が何を引き継ぐか、地域へどう伝わるかは未実装・未採用である。
