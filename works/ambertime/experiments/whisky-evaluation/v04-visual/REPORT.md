## 体験と比較

手元の瓶を選び、1本・5本・全部から選んで店へ仮置きし、確定する。店頭の現物は1本ずつ描く。時間を進めると実売分だけ減り、実際に好意的な評価があった商品が、別区画の台紙付きの記録として残る。客の直接の反応とv03の店の記憶文も維持した。次の試作はv02/v03と同じく熟成済み5本を用意する比較操作であり、製造費や熟成待ちの経営は扱わない。

上部で見る店を選び、A/B/Cを切り替える。切替はUI状態だけを変更し、瓶・売上・評価・支持を変更しない。店への配分は下の店ボタンから行う。店頭の瓶を押すと同じ商品の残りをまとめて回収する。店情報内にも、本数付きの回収ボタンを用意した。記録の瓶は回収対象にしない。

| 案 | 同じデータの見せ方 | トレードオフ |
| --- | --- | --- |
| A 棚中心 | 店頭と記録を棚の上下、専門酒店では商品棚と展示区画に分ける | 少ない形で比較できる一方、棚だけだと店の役割は弱い |
| B 店内中心 | バーのカウンターとグラス、食堂の食卓・椅子・皿、専門酒店の前カウンターを加える | 店らしさを増やすが、瓶以外の情報も増える |
| C 瓶と記録中心 | 現在の商品と、台紙付きの過去の記録を左右に分ける | 区別を優先するため、店全体の景色としての一体感は弱い |

初期表示はAだが、採用確定ではない。Bの情報量が多いことを理由に自動採用しない。バーで納品5本→1か月後に実売4本・店頭1本・好意的記録1件を実操作し、A/B/Cの基本構造を確認してから食堂と専門酒店へ展開した。同じ棚の色替えにはせず、家具の構成を変えた。

## 状態と情景の対応

`sceneFor(session,shopId)` はv03の保存状態から描画用データを導く純粋関数。描画側からv03の状態を書き換える経路はない。

| 視覚要素 | 根拠 |
| --- | --- |
| 店頭の裸の瓶 | 全商品の `product.shops[shopId]` の実残数。選択中の商品だけに限定しない |
| 半透明の仮置き | v03の未確定allocation。確定前の実在庫・実売・記憶にはしない |
| 台紙と枠の中の瓶 | その店のarchiveで `sold>0 && supportCount>0` の商品記録。現物在庫は0本 |
| 記録の裏付け | 実売本数・好意的評価件数・年数・商品ID・製造月・最終販売月を保持 |
| 過去と今回の線 | 現在／仮置きの商品と、別商品IDの過去の好評記録に同じ製法・年数がある場合 |
| 記録の下の印・線の濃淡 | 現在の複数期待のweightから導出。支持ポイントの閾値による豪華化はしない |
| 店の短い反応 | v03のshopViewにある実売・評価・因果参照に基づく文章をそのまま利用 |

好意的評価と不一致が混在する商品もあるため、「全員に好評」「人気商品」とは表現しない。「好んだ客の記録」とし、実際に好む客がいた範囲の証拠を示す。悪い印象だけが強い商品を好評の展示にしない。負の記憶そのものはv03の店情報・反応・ログに残る。

記録は最近の好意的な商品から最大3件を表示する。これはv03の想起政策そのものの再選択ではなく、好意的な実売記録を景色に置く表示方針。同製法を繰り返せば似た記録が複数並び得る。候補件数を異なる風味の種類数とは扱わない。

無取引の時間が長くなると現在の期待の印・接続線は弱まるが、過去の実売・好意的評価という記録は消さない。瓶の展示を増やす・店を豪華にするアップグレード条件はない。

### 描画容量

現物と仮置きの描画は合計10本、好評記録は3件まで。超過分は「描画10本・ほかN本」「表示3件・ほかN件」と明示し、投影データとログには全数を保持する。10本を超えた状態を、全ての実瓶が1本ずつ画面に見えているとは説明しない。独立テストでは20本を同時配分し、10本描画＋描画外10本と、記録0件を3案で確認した。通常の1試作5本は全数描画する。

## 4つの経過と再現

v03のSCENARIOSを変更せず使う。A＝煙20年を継続、B＝煙20→15→10→8→6年、C＝煙20年2回からバランス3年へ転換、D＝転換後に煙20年へ戻す。初期のバランス8年5本は、v03と同じく手元へ残した共通条件である。

各発売の納品直後と、6か月販売後の実状態を保持し、10フレームを「前へ・次へ」で比較する。月次処理を別の操作へ分割して履歴を変えず、元のadvance6を使う。表示を戻しても過去の記録に未来の商品を混入させない。再生中は通常の月送りと同じ位置を比較操作に使う。次の一本や手動操作を始めると再生を解除する。

JSONはv03の厳密な保存形式をそのまま利用する。初期状態から操作を再実行し全状態の一致を要求する。視覚案と見る店は保存された計算状態を変更しないUI選択であり、JSONには追加しない。同じJSONと同じ店・視覚案なら同じ情景になる。モデルversionは `whisky-reputation/0.3`、視覚投影versionは `whisky-visual/0.4` と区別する。購入CSVと店の記録CSVもv03の処理を利用する。

## 発見した問題と修正

1. シナリオ再生後にJSON読込・初期化をしても古い再生状態が残り、次へで以前の状態へ戻れる問題を独立レビューで発見した。成功した読込・初期化時にも再生を解除した。保存モデルは変更していない。
2. v03の「右の瓶」の回収説明が、C案の配置と合わなかった。位置を指定せず、同商品の残りをまとめて回収する既存操作に合わせた。
3. 情景の追加で表示が縦に伸びるため、選択済みの店名・価格・結果見出しの重複を削り、比較の前へ・次へを月送りと同じ位置で使う。売切れた古い手元瓶は履歴で見返し、手元には現物または選択中の瓶を表示する。

## 描画負荷と確認範囲

sceneForとSVG生成は操作・店切替・案切替時だけ実行する。同じ投影keyなら情景DOMを作り直さない。独自の常時RAF、setInterval、時間の自動進行は追加していない。SVG数・表示瓶数に上限を設ける。

置く反応は既存v03の240ms有限animation。新しい好評記録が加わる時のopacity変化は200msの1回だけで、最終状態を即時に描画した後に補助する。アニメーションなしでも実在庫・台紙・区画から状態を読める。reduced-motionまたはdocument.hidden時は動かさず、pagehide・reducedへの切替時にも停止する。JSON書き出し時のURL解放用1秒timeoutは描画ループではない。

Nodeホストでの投影＋3SVG生成＋構造照合12,000回は中央値4.09ms、P90 10.94ms、最大171.42ms。モデルのstrict保存検査やassertも含む値で、iPhoneの描画時間・FPS・温度ではない。iPhoneの発熱は未測定。

ローカル360×568ではバーの初納品・販売減少・A/B/C・Dの10段階を操作した。横幅345pxとscrollWidth345pxの一致を確認。初期構成の通常販売後の次ボタンは画面内だったが、情景と再生controlsを併置すると縦長になる状態があったため上記3の表示整理を行った。その最終版の再読込はブラウザーURL保護で拒否され、CLIもpreview停止を示した。同じローカルURLへの迂回・再試行は行わず、最終版の360/375/390・ログ・公開後操作はStagingで確認してPRに記録する。

表示確認補助 `qa.html` は同じLabを360×568・375×620・390×680のiframeで表示する。通常の遊び画面には確認用パネルを追加していない。詳細を開いた時や長い履歴の閲覧はスクロールする。実機Safari、作者の見た目・手触り、端末温度は未確認。正式verificationStateはUNVERIFIEDを維持する。

## 残る課題と作者の確認点

- 記録の台紙と別区画が、文章なしでも在庫と区別できるかは試遊事項。形・ラベルは再利用したが、熟成年数や商品月はSVGの説明と店情報で確認するため、景色だけで同形の全商品を識別できるとは言えない。
- 現在の期待は細い印・接続線の濃淡で表す。長期空白の違いが弱く見える可能性があり、ゲージを増やさず伝わるかを確認する。
- 3件表示は見やすさと過去の存在感のトレードオフ。古い好評は全記録に残るが、常に飾られているわけではない。
- バーの販売量優位・v03の減衰仮説・同レシピ反復の見本重複は継承した。視覚化で数式の問題を解決したとは扱わない。
- 地域拡大、全国評判、世代交代は未実装。今回の画面を本編へ統合していない。

作者には、A「文章なしでも店との関係が育つ違いを感じるか」、B「過去の一本が景色に残る存在感があるか」、C「情景が操作を楽しくするか、邪魔するか」を3案の同じ経過で比較してもらう。計算の成功だけでこの3点が成立したとは判断しない。
