# AmberTime — お店のつながり M1-A 比較Lab

## 目的
既存の店舗の口コミが届いたことを、普段は静かな町のまま、選択した店から発見できるか比較する。A「文章だけ」とB「線を1本」を**同じ根拠・同じ地図**で比較する。作者がiPhoneで触って採用方向を判断するための独立Staging Lab。本編M0、通知PR #880、経済、正式保存、RNGには触れない。

## 画面と操作
1. 「届く前／届いた後／まだ取扱前」で検証用の固定イベントを切り替える。
2. 「町を眺める／関係を見る」で普段の地図と関係表示を切り替える。
3. 地図の店舗をタップ、またはキーボードで選ぶ。**関係を見る**では、口コミ到達の根拠がある場合だけ情報が出る。
4. Aは文章のみ、Bは選択店と口コミの直前の店舗を結ぶ1本の線。元の店舗に移動すると通常の店舗詳細に戻る。
5. 全画面地図でピンチズーム、パン、＋/−。描画は本編と共通の `renderMap(stage=3)`、店舗の当たり判定位置は `mapObservationBounds(3)`。

## 検証用データの境界
- `fixtures.mjs` は**実プレイ結果ではなく、既存のイベント形式に沿った固定シナリオ**。半年単位の本編経済・保存・イベント発生をシミュレートしない。
- `relationship-view.mjs` はDraft PR #881、blob `de4ead1516193fa57323a5d8cf8d39d2829afefb` と同一内容の、比較用に固定したコピー。Labで独立して読み取れるようにしたもの。M1-Bでは本編用の一つの正本を利用し重複しない。
- 発売→納品→紹介→到達の全`sourceId`連鎖を確認。元の記録がないと線は出ない。取扱前のバーは対象にしない。
- 既存M0のバー位置は**暫定**であり正式な建物アセットではない。町の店舗が現行では4種類、伝播用ノードの全てが取扱店ではないことを維持する。
- 紹介と契約の因果、個人名のある人間関係、閉店・再開、海外の具体都市は新規生成しない。

## 機械的確認
- `node --check`：`app.mjs`、`fixtures.mjs`、`relationship-view.mjs`。
- `node --test works/ambertime-map-relations-lab/relationship-lab.test.mjs`：8件 PASS（ローカルNode）。
- CSS+HTMLをブラウザーへ直接投入する**静的レイアウトだけの**検査では320×568、360×568、390×680、430×740で横はみ出しゼロ、関係表示領域を含む主画面がウィンドウ内に収まる。これは外部モジュールやJS実行を伴う統合テストではない。
- ローカルHTTPサーバーへのChromium接続は `ERR_BLOCKED_BY_ADMINISTRATOR` で不可。Safari実機および実際のM0描画・店舗選択・ピンチ操作は**UNVERIFIED**。
